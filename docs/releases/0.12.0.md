**Create and change elements with a dry run, compare baselines with their content, and see the same pages in the app and the HTML export.**

- **Next identifier and dry run.** Creating an element can take the next free identifier of its type, and creating or changing an element can run as a dry run that shows the result and its findings without writing anything.
- **Baseline comparison with content.** Comparing with a baseline now gives the old and the new version of each changed element, with title, text and properties, and names the Git command for the full difference.
- **Same pages in the app and the HTML export.** Element page, neighbourhood, lists, package pages, hint list and the start page are built the same way for both. The neighbourhood counts per relation kind, a package page no longer repeats its elements, and export lists show the verification status only in the core.
- **Clearer messages.** Messages name types and commands by their names, without spec numbers. Setting a status names the missing required properties, a missing ReqIF delivery or mapping file is named with its path and the command that makes one, and the core view also works in a workspace without variants.
- **Documentation and first steps.** The documentation shows app, command line, API and MCP side by side in tabs that keep your choice, and its sidebar is grouped by topic. An empty workspace shows the first steps as clickable lines, and a new workspace gets its evidence folder at once.
