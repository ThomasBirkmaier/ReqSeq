**Create and change elements with a dry run, compare an element with a baseline by its content, and get clearer HTML export pages.**

- **Next identifier and dry run.** Creating an element can take the identifier after the highest one of its type. On the command line, API and MCP, creating or changing an element can run as a dry run that shows the result and its problems without writing anything.
- **Baseline comparison with content.** Comparing an element with a baseline now gives its old and new version: the text, the acceptance criteria, the properties that count to the version and the relations added and removed. It also names the Git command for the full difference.
- **HTML export pages.** The neighbourhood counts per relation kind, a package page no longer repeats its elements, and lists show the verification status only in the core. Element page, lists, package pages, hint list and start page are built by one shared model, which the app uses for the element page and the neighbourhood.
- **Clearer messages.** Messages name types by their name and other commands by their title, without spec numbers. Setting a status names the missing required properties. A missing ReqIF delivery file is named with its path, and a missing mapping file also names the commands that make one. The core view also works in a workspace that defines no variants.
- **Documentation and first steps.** The documentation shows app, command line, API and MCP side by side in tabs that keep your choice, and its sidebar is grouped by topic. An empty workspace shows the first steps as clickable lines, and a new workspace gets its evidence folder at once.
