**Acceptance criteria keep their identity, and the verification status is right.**

- **Criterion keys.** Each acceptance criterion can carry a criterion key in the element file, while the app still numbers the criteria AK1, AK2, … without gaps. Tests, evidence records and references can name a criterion by its key, so they keep pointing at the right one when criteria are inserted or moved. A ReqIF round trip keeps the keys.
- **A more reliable verification status.** Elements with an invalid status no longer cause hints about outdated or superseded relations, the hint about outdated evidence follows the status of each acceptance criterion, and a matrix cell shows the worst of equally new test runs.
- **Clearer saving in the app.** After a save the app says how many elements are directly affected, and when a save fails the modeline says why. Elements show their identifier in brackets behind the short ID, and a click on the value of a choice opens its choices.
- **Safer files.** A local workspace file that Git tracks is ignored with a warning, filters and baselines are never written inside `.git`, and a ReqIF export replaces only its own file and images. The reference describes every file format, field by field, with an example.
- **Give your criteria their keys, and update together.** The workspace check now warns about every acceptance criterion without a criterion key: run "Assign criterion keys" once on all elements and commit the result. Elements saved with this version carry criterion keys, which older versions of ReqSeq read wrongly, so everyone working on one workspace, and its pipeline, should update at the same time.
