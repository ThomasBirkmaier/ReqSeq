**Acceptance criteria keep their identity, and the evidence status is right.**

- **Fixed keys for acceptance criteria.** Each acceptance criterion can carry a fixed key in the element file, while the app still numbers them AK1, AK2, … without gaps. Tests, evidence records and references can name a criterion by its key, so they keep pointing at the right one when criteria are inserted or moved. One command gives every criterion of a selection that lacks one its key, and a ReqIF round trip keeps the keys.
- **A more reliable verification status.** Elements with an invalid status no longer cause hints about outdated evidence or superseded targets, the outdated-evidence hint follows the status of each acceptance criterion, and a matrix cell shows the worst of equally new test runs.
- **Clearer saving in the app.** After a save the app says how many elements are directly affected, and when a save fails the status line says why. Elements show their identifier in brackets behind the short ID, and a click on the value of a choice opens its choices.
- **Safer files.** A local workspace file that Git tracks is ignored with a warning, filters and baselines are never written inside `.git`, and a ReqIF export replaces only its own file and images. The reference describes every file format, field by field, with an example.
- **Please update together.** Requirements saved with this version carry criterion keys, which older versions of ReqSeq read wrongly, so everyone working on one workspace, and its pipeline, should update at the same time.
