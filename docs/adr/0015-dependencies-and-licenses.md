# ADR-0015: Dependency policy

Status: Accepted · Based on: N-046, N-047, D-051 · Changed by [ADR-0021](0021-desktop-shell.md) (#2376): Rust crates: pins, licence check, audit

## Decision

- Allowed licenses for runtime dependencies: MIT, ISC, BSD-2-Clause, BSD-3-Clause, Apache-2.0, 0BSD, BlueOak-1.0.0, CC0-1.0, Unlicense, Python-2.0, MPL-2.0 (file-level copyleft, unmodified) and Unicode-3.0 (the Unicode data licence of the ICU4X crates that the desktop shell ships through Tauri and `url`, #2396; its notice goes into the notices of the release). One exception, for fonts only (ADR-0020): OFL-1.1 is allowed for a package that ships fonts and no code, which `scripts/licenses/check.mjs` checks file by file (`fontOnly` in `policy.mjs`: fonts, their style sheets, metadata, type declarations and texts, nothing else); the same licence on any other package fails. Anything else needs the product owner's answer first (label `needs-human` on the issue). Checked by `pnpm licenses:check` in CI, over the production packages of `pnpm-lock.yaml` including optional dependencies.
- No dependency that phones home, collects telemetry or downloads at runtime (N-047). Native modules only when there is no pure alternative, because each needs a build per Electron version.
- `pnpm audit --prod --audit-level high` in CI; findings block the PR. The nightly and the manual run also audit the dev packages (`pnpm audit --audit-level high`), because they run on the build machine.
- `minimumReleaseAge: 1440` is set in `pnpm-workspace.yaml`, the same as pnpm's default since pnpm 11, so that a change of the default cannot lower it for the workspace and for `toolchain/packaging`, which has its own `pnpm-workspace.yaml` (the docs site, installed with `--ignore-workspace`, keeps pnpm's default): a lockfile with a package published less than a day ago fails the install, a second line behind the two-week rule for pins. An entry in `minimumReleaseAgeExclude`, including one pnpm writes itself, needs a written reason in the PR.
- GitHub Actions in `.github/` are pinned by full commit SHA with the version as a comment (`@<sha> # v4.4.0`), never by a tag, because a tag can be moved. An update replaces the SHA and the comment together.
- Dependabot (`.github/dependabot.yml`) opens npm PRs only for security updates, and one grouped PR a month for the Actions, with a cooldown of 14 days, as for pinned packages.
- Every new runtime dependency is named in the PR body with license and reason.

It supplies the list at the caret, the listbox roles and the mouse picking; the entries, the ranking and the keys are our own.

SR-111 graph (ThomasBirkmaier/ReqSeq-archive#407): `@dagrejs/dagre` 3.1.1 (MIT) lays out the graph of the current element in the renderer (ADR-0010; D-063: an existing library, none of our own). Its ESM build bundles `@dagrejs/graphlib` 4.0.5 (MIT; a dependency of dagre), 49 KB minified. The build moves dagre's MIT notice to `dagre.esm.js.LEGAL.txt`, so the app bundle does not carry it: the packaging of the app (electron-builder) must ship a third-party notices file that names dagre and graphlib with their licences. Neither has further dependencies or install scripts, and the bundle has no network access, `eval`, `new Function`, `Worker` or `Math.random`, so it runs offline under the CSP `script-src 'self'` and gives the same layout for the same graph. The pin is exact: 3.1.2 and 3.1.3 were less than two weeks old when it was chosen. dagre's type declarations do not resolve under NodeNext (graphlib's import `./lib/graph` has no extension), so `graph-layout.ts` writes the part of the graph API it uses; an upgrade needs `graph-layout.test.ts` and the AK6 test green. Rejected: `elkjs` (EPL-2.0 or GPL-3.0, 1.6 MB, slower), `d3-dag` (several times slower), `@msagl/core` (a dependency without a licence).

SR-096 formulas (ThomasBirkmaier/ReqSeq-archive#108): `katex` 0.19.0 (MIT) sets the formulas of the editor in the renderer (ADR-0010), bundled and loaded with the editor. Its one dependency, `commander` (MIT), serves KaTeX's command line and is not bundled. It has no install script and no network access, `eval`, `new Function` or `Worker` (`test/renderer-bundle.spec.ts`); its fonts are 20 woff2 files (254 KB) served by `app:`, the woff and ttf copies (798 KB) are dropped by the build, and the renderer script grows by about 600 KB, KaTeX's module (the renderer build does not minify). The pin is exact: 0.18.11 is deprecated on npm (published with breaking changes, 0.19.0 replaces it), and 0.19.1 was less than two weeks old when it was chosen. `strict: "ignore"` keeps the 0.19 change of strict mode out of our calls. Mermaid 11 (ThomasBirkmaier/ReqSeq-archive#108, diagrams) asks for KaTeX `^0.16` for math in labels; it is held to this one copy by an `overrides` entry in `pnpm-workspace.yaml` when Mermaid is added.

SR-096 diagrams (ThomasBirkmaier/ReqSeq-archive#108): `mermaid` 11.17.2 (MIT) draws the diagrams of the editor in the renderer (ADR-0010), bundled as lazy chunks loaded on the first diagram (about 5.9 MB of scripts; the renderer build does not minify). Its production tree is 109 packages with KaTeX (107 new ones), all inside the allowlist: MIT 67 (among them `cytoscape`, `dagre-d3-es`, `khroma`, `marked`, `stylis`, `roughjs`, `dayjs`, `lodash-es`, `@mermaid-js/parser`, `@iconify/utils`), ISC 32 (`d3` and its modules), BSD-3-Clause 6, Apache-2.0 1 (`@chevrotain/types`), `(MPL-2.0 OR Apache-2.0)` 1 (`dompurify`) and Unlicense 1 (`robust-predicates`). None has an install script. `khroma` 2.1.0 has no `license` field in its `package.json`, so `pnpm licenses list` reports it as "Unknown"; its `license` file is the standard MIT text. `scripts/licenses/check.mjs` therefore keeps a list of verified licence files pinned by exact name, version and the sha256 of the file (`VERIFIED_LICENSE_FILES`): another version, a changed text, a missing file or an entry no package uses fails the check again. This reads the licence from the package itself; it is no ignore. The Node-only helpers in the tree (`@antfu/install-pkg`, `tinyexec`, `package-manager-detector`, `import-meta-resolve`, from `@iconify/utils`) are not bundled: Mermaid loads icon packs only through a loader the app would register, and it registers none. `test/renderer-bundle.spec.ts` scans every chunk; its two reviewed hits are lodash's `Function("return this")()` (reached only when no `self` exists, and refused by the CSP anyway) and an `EventSource` in a documentation comment that cytoscape carries. `overrides` in `pnpm-workspace.yaml` (until pnpm 12, #360: `pnpm.overrides` in the root `package.json`) holds `mermaid>katex` at 0.19.0, the one KaTeX copy of the app: Mermaid 11 asks for `^0.16.47`, which would ship a second KaTeX with GHSA-238p-pmpm-9mq7 (low, fixed in 0.18.2); with the override `pnpm audit --prod` finds nothing. The override is used at run time: sequence diagrams set `$$…$$` in messages, notes and actors with KaTeX as MathML, whatever `htmlLabels` says; in flowcharts, state and class diagrams the app's `htmlLabels: false` keeps such a label its text (`test/diagrams.spec.ts` checks both). The build drops the licence comments of the bundled packages, as for dagre: the notices file of the packaging must list Mermaid's tree too (`pnpm --recursive licenses list --prod`). Rejected for now: Mermaid 12, whose 12.0.0 to 12.2.0 depend on `elkjs` (EPL-2.0, outside the allowlist, and 1.5 MB more); moving to it needs the product owner's decision on elkjs. 11.x still gets maintenance releases; the pin is exact.

Packaging (ThomasBirkmaier/ReqSeq-archive#324, ADR-0014): `electron-builder` 26.17.0 (MIT), dev only, in its own package `toolchain/packaging/` with its own lockfile (exception to ADR-0001), installed with `--ignore-scripts` and audited (`pnpm audit --audit-level high`) only by the release workflow; a finding blocks the release build. None of its about 220 packages is shipped; one of them is WTFPL (`truncate-utf8-bytes`), which the allowlist above (for runtime dependencies) does not need to cover. It downloads the Electron zip at build time and verifies its checksum (`@electron/get`); nothing is downloaded at run time. The third-party notices file the SR-111 paragraph asks for is `resources/THIRD_PARTY_NOTICES.txt` in every artifact.

User documentation site (#344, ADR-0017): `astro` 7.3.8, `@astrojs/starlight` 0.42.6 and `starlight-links-validator` 0.27.0 (all MIT), dev only, in `packages/docs/site/` with its own lockfile outside the workspace, installed with `--ignore-scripts` and audited (`pnpm audit --audit-level high`) only by the docs steps of CI and `docs-pages.yml`. Astro builds the site, Starlight gives the docs layout, the validator fails the build on dead internal links. `satteri` 0.10.5 (MIT, a Markdown and HTML processor with a native binding per system) is a direct dev dependency too, for the build only (#2192): Starlight's `Tabs` component imports it, and the build bundles that component, so the bundle finds the native binding only when the site lists the package itself. Its pin must stay the version Starlight resolves in the site lockfile, so that an upgrade of Starlight upgrades it with it. Nothing of it ships: the tabs are processed when the pages are built. The tools themselves never ship; their about 290 packages are MIT, ISC, BSD, Apache-2.0, BlueOak, MPL-2.0, CC0 and Python-2.0, except libvips (LGPL-3.0-or-later, the image library of `sharp`), which the allowlist does not need to cover because it is never shipped. The direct pins are exact and were at least two weeks old when chosen.

Since SR-141 (#1205) the built site ships with every delivery (`resources/cli/docs/`, `package/docs/` of the CLI tarball; ADR-0014), so the allowlist above covers what it holds. `licenses:check` does not see it, because it reads only the workspace lockfile. `scripts/licenses/site.mjs` names the packages of the site lockfile whose code or styles land in the built site (`astro`, `@astrojs/starlight`, `astro-expressive-code` and `@expressive-code/*`, `minisearch`), reads their version from the site lockfile and their licence and licence files from the site's install, and checks them against the allowlist. That nothing else ships is checked too: the offline build writes hidden source maps, every source of every map must belong to a listed package or to the site's own `src/`, every script of `_astro/` needs a map (except the copy button of code blocks and chunks that only import others), and every file of the built site must match a short list of patterns (pages, `_astro/` chunks and images, `search-index.json`, the icons); the maps are left out of the staged site. SPDX expressions are evaluated by one rule for both checks (`scripts/licenses/policy.mjs`): `OR` needs one allowed side, `AND` both, and `WITH`, `+`, `LicenseRef-` or anything it cannot parse is refused. The release job `docs-site` runs the check (`stage.mjs --docs-site`), and its entries go into both notices files. Starlight's own search, Pagefind (MIT), stays installed with Starlight but is switched off and ships nothing: its WebAssembly holds `pagefind_microjson` 0.1.4 (GPL-3.0-only) and `unicode-ident` 1.0.24 (`(MIT OR Apache-2.0) AND Unicode-3.0`), the first outside the allowlist, so the site searches with `minisearch` 7.2.0 (MIT, no dependencies, the version core uses) instead (#1220). `minisearch` is a dependency of the site (bundled into its search script) and of `@reqseq/docs`, which builds the index, and a dev dependency of `@reqseq/cli` for the delivery test.

ReqIF XSD check (#265, ADR-0013): `xmllint-wasm` 5.3.0 (MIT; libxml2 compiled to WebAssembly, MIT), dev only, in `devDependencies` of `@reqseq/testkit`, which is never shipped, so `licenses:check` and `pnpm audit --prod` do not read it. It has no dependencies and no install script, runs libxml2 in a worker thread with its files in memory, gets `--nonet` and has no network code; the tests' network block covers its worker too (`worker-preload.mjs`). `validateReqif` points the `schemaLocation`s of the downloaded XSDs to their base names in memory, so the files stay as downloaded. The pin is exact and was at least two weeks old when chosen (5.3.0, 2026-08-05).

Mutation runs (#1335): `@stryker-mutator/core` and `@stryker-mutator/vitest-runner` 10.1.1 (Apache-2.0), dev only, in the root `devDependencies`, run only by the local command `pnpm mutate` (`scripts/mutate/mutate.mjs`), never in CI. Their 134 new packages are MIT, Apache-2.0, ISC, BSD-3-Clause and 0BSD; none ships. A run opens no outbound connection. Its parent process listens for the log lines of its workers on a random TCP port without a host (`LoggingServer`), so on all interfaces, and the workers connect over localhost: that port is reachable from the LAN while a run lasts. Wrapping `net.Server.prototype.listen` in `mutate.mjs` before Stryker loads would keep it on 127.0.0.1; it is not done, because it patches Stryker's behaviour from outside. `typed-rest-client`, used only by Stryker's dashboard reporter and `stryker init`, which the command does not use, pins `qs` 6.15.1 with four moderate advisories; an override in `pnpm-workspace.yaml` lifts it to `^6.17.1` (#1506). The Stryker pin is exact and was at least two weeks old when chosen (10.1.1, 2026-10-23).

Status model (#1394, epic #1389): `fast-check` 4.10.2 (MIT) and its only dependency `pure-rand` 8.4.2 (MIT), dev only, in `devDependencies` of `@reqseq/testkit`, which is never shipped, so `licenses:check` and `pnpm audit --prod` do not read them. They generate the inputs of the property tests that compare the core with the reference model (`packages/testkit/src/status-model/`), and shrink a failing input to a small one. Neither has an install script, network code or file access; fast-check reads `Math.random` only for a seed when none is given, and the tests always give one, so a run replays. Only `@reqseq/testkit/status-model` imports it, so other tests do not load it. `fast-check` is pinned exactly; `pure-rand` is not pinned itself but held by the lockfile within fast-check's range `^8.0.0`. Both versions were at least two weeks old when chosen (4.10.2, 2026-09-19; 8.4.2, 2026-07-10).

HTML export (#1963, SR-231 AK5): `katex` 0.19.0 (MIT, the app's version) is a runtime dependency of `@reqseq/core`: the export sets formulas when it writes the pages and copies KaTeX's stylesheet with its woff2 fonts inlined (`assets/katex.css`). The pages draw diagrams with a Mermaid bundle of our own, not Mermaid's prebuilt `dist/mermaid.min.js`, which carries an older KaTeX (GHSA-238p-pmpm-9mq7), DOMPurify and marked out of reach of the lockfile and `pnpm audit`. `mermaid` 11.17.2 and `rolldown` 1.2.15 (both MIT, already in the lockfile) are dev dependencies of core; core's build bundles Mermaid's ESM against the lockfile into one minified script (`scripts/build/html-export-vendor.mjs`, which fails on `eval`, `new Function` or a dynamic `import`), shipped in core's `vendor/html-export/` and so in the CLI tarball and the delivery. Because `licenses:check` and `pnpm deploy` do not see a dev dependency as shipped, `scripts/licenses/html-export.mjs` reads the bundle's hidden source map: every source must belong to an installed package, or, inside the prebuilt chunks of `@mermaid-js/parser`, to a package that chunk's map names but that is not installed (langium, chevrotain and their parts, vscode-uri, path-browserify; Apache-2.0 and MIT), whose licence texts are kept in `scripts/licenses/texts/` with their SHA-256. A source it cannot attribute, a licence outside the allowlist or a changed text fails `licenses:check`. It writes `notices.generated.ts`, which the export writes as `licenses/THIRD-PARTY-NOTICES.txt` (with Starlight, whose styles `assets/docs.css` holds) and `stage.mjs` adds to both notices files. Dev only: `happy-dom` 21.0.4 (MIT, the app's version) runs the page scripts in core's unit tests, `micromark-util-types` 2.0.3 (MIT) types the formula syntax of the export, and `parse5` 8.1.1 (MIT) reads the docs page in `@reqseq/docs` (ADR-0017).
