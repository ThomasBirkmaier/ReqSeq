# ADR-0015: Dependency policy

Status: Proposed · Based on: N-046, N-047, D-051

## Decision

- Allowed licenses for runtime dependencies: MIT, ISC, BSD-2-Clause, BSD-3-Clause, Apache-2.0, 0BSD, BlueOak-1.0.0, CC0-1.0, Unlicense, Python-2.0 and MPL-2.0 (file-level copyleft, unmodified). Anything else needs the product owner's answer first (label `needs-human` on the issue). Checked by `pnpm licenses:check` in CI.
- No dependency that phones home, collects telemetry or downloads at runtime (N-047). Native modules only when there is no pure alternative, because each needs a build per Electron version.
- `pnpm audit --prod --audit-level high` in CI; findings block the PR.
- Every new runtime dependency is named in the PR body with license and reason.

Pinned now (stage 0, dev only): TypeScript, typescript-eslint, ESLint, Prettier, Vitest, Ajv, ajv-formats, yaml, @types/node. Runtime dependencies of `core` pinned since: `yaml`, `ajv`, `ajv-formats`, `minisearch` 7.2.0 (#323: MIT, no dependencies, no network access, no install scripts; ReqSeq never calls its vacuum, so it starts no timers, ADR-0008). `search-scoring.ts` reads protected members; an upgrade needs `search-scoring.test.ts` green and a review of `search`/`executeQuerySpec`/`termResults`. Planned with their stage: `micromark` family (stage 1–3), `commander`, `@modelcontextprotocol/server` (stage 1; the v2 package of the official MCP SDK, instead of the v1 `@modelcontextprotocol/sdk`, ADR-0009), `electron`, `electron-vite`, `react`, `@codemirror/*`, `katex`, `mermaid`, `@playwright/test`, `electron-builder` (stage 3, see below), `fast-xml-parser`, `hast-util-*` (stage 6).

Stage 3 app shell (#322): `react` and `react-dom` (MIT, runtime, bundled into the renderer); dev only: `electron` (MIT), `electron-vite` and `vite` (MIT), `@playwright/test` (Apache-2.0), `@types/react` and `@types/react-dom` (MIT), and `happy-dom` (MIT, a DOM for the unit tests of the renderer). pnpm does not run Electron's install script. `pnpm --filter @reqseq/app electron:install` downloads the binary where it is needed (Electron tests, later packaging).

SR-100 main view (#112): `@leeoniya/ufuzzy` 1.0.19 (MIT, no dependencies, no network access, bundled into the renderer) ranks the names of app actions and open buffers in the minibuffer.

SR-065 editor (#77): `@codemirror/state`, `@codemirror/view`, `@codemirror/language`, `@codemirror/commands`, `@codemirror/lang-markdown` (with `@codemirror/lang-html`), `@lezer/markdown`, `@lezer/common`, `@lezer/highlight` (all MIT, no network access, bundled into the renderer). Dev only: `micromark` and `micromark-extension-gfm` (MIT), the reference parser of the round-trip test for CommonMark with GitHub extensions.

SR-129 slash menu (#446): `@codemirror/autocomplete` 6.20.4 (MIT, no network access, bundled into the renderer) is a direct dependency of `@reqseq/app`; it was a transitive one of `@codemirror/lang-markdown` before. It supplies the list at the caret, the listbox roles and the mouse picking; the entries, the ranking and the keys are our own.

SR-111 graph (#407): `@dagrejs/dagre` 3.1.1 (MIT) lays out the graph of the current element in the renderer (ADR-0010; D-063: an existing library, none of our own). Its ESM build bundles `@dagrejs/graphlib` 4.0.5 (MIT; a dependency of dagre), 49 KB minified. The build moves dagre's MIT notice to `dagre.esm.js.LEGAL.txt`, so the app bundle does not carry it: the packaging of the app (electron-builder) must ship a third-party notices file that names dagre and graphlib with their licences. Neither has further dependencies or install scripts, and the bundle has no network access, `eval`, `new Function`, `Worker` or `Math.random`, so it runs offline under the CSP `script-src 'self'` and gives the same layout for the same graph. The pin is exact: 3.1.2 and 3.1.3 were less than two weeks old when it was chosen. dagre's type declarations do not resolve under NodeNext (graphlib's import `./lib/graph` has no extension), so `graph-layout.ts` writes the part of the graph API it uses; an upgrade needs `graph-layout.test.ts` and the AK6 test green. Rejected: `elkjs` (EPL-2.0 or GPL-3.0, 1.6 MB, slower), `d3-dag` (several times slower), `@msagl/core` (a dependency without a licence).

SR-096 formulas (#108): `katex` 0.19.0 (MIT) sets the formulas of the editor in the renderer (ADR-0010), bundled and loaded with the editor. Its one dependency, `commander` (MIT), serves KaTeX's command line and is not bundled. It has no install script and no network access, `eval`, `new Function` or `Worker` (`test/renderer-bundle.spec.ts`); its fonts are 20 woff2 files (254 KB) served by `app:`, the woff and ttf copies (798 KB) are dropped by the build, and the renderer script grows by about 600 KB, KaTeX's module (the renderer build does not minify). The pin is exact: 0.18.11 is deprecated on npm (published with breaking changes, 0.19.0 replaces it), and 0.19.1 was less than two weeks old when it was chosen. `strict: "ignore"` keeps the 0.19 change of strict mode out of our calls. Mermaid 11 (#108, diagrams) asks for KaTeX `^0.16` for math in labels; it is held to this one copy by a `pnpm.overrides` entry when Mermaid is added.

SR-096 diagrams (#108): `mermaid` 11.17.2 (MIT) draws the diagrams of the editor in the renderer (ADR-0010), bundled as lazy chunks loaded on the first diagram (about 5.9 MB of scripts; the renderer build does not minify). Its production tree is 109 packages with KaTeX (107 new ones), all inside the allowlist: MIT 67 (among them `cytoscape`, `dagre-d3-es`, `khroma`, `marked`, `stylis`, `roughjs`, `dayjs`, `lodash-es`, `@mermaid-js/parser`, `@iconify/utils`), ISC 32 (`d3` and its modules), BSD-3-Clause 6, Apache-2.0 1 (`@chevrotain/types`), `(MPL-2.0 OR Apache-2.0)` 1 (`dompurify`) and Unlicense 1 (`robust-predicates`). None has an install script. `khroma` 2.1.0 has no `license` field in its `package.json`, so `pnpm licenses list` reports it as "Unknown"; its `license` file is the standard MIT text. `scripts/licenses/check.mjs` therefore keeps a list of verified licence files pinned by exact name, version and the sha256 of the file (`VERIFIED_LICENSE_FILES`): another version, a changed text, a missing file or an entry no package uses fails the check again. This reads the licence from the package itself; it is no ignore. The Node-only helpers in the tree (`@antfu/install-pkg`, `tinyexec`, `package-manager-detector`, `import-meta-resolve`, from `@iconify/utils`) are not bundled: Mermaid loads icon packs only through a loader the app would register, and it registers none. `test/renderer-bundle.spec.ts` scans every chunk; its two reviewed hits are lodash's `Function("return this")()` (reached only when no `self` exists, and refused by the CSP anyway) and an `EventSource` in a documentation comment that cytoscape carries. `pnpm.overrides` in the root `package.json` holds `mermaid>katex` at 0.19.0, the one KaTeX copy of the app: Mermaid 11 asks for `^0.16.47`, which would ship a second KaTeX with GHSA-238p-pmpm-9mq7 (low, fixed in 0.18.2); with the override `pnpm audit --prod` finds nothing. The override is used at run time: sequence diagrams set `$$…$$` in messages, notes and actors with KaTeX as MathML, whatever `htmlLabels` says; in flowcharts, state and class diagrams the app's `htmlLabels: false` keeps such a label its text (`test/diagrams.spec.ts` checks both). The build drops the licence comments of the bundled packages, as for dagre: the notices file of the packaging must list Mermaid's tree too (`pnpm licenses list --prod`). Rejected for now: Mermaid 12, whose 12.0.0 to 12.2.0 depend on `elkjs` (EPL-2.0, outside the allowlist, and 1.5 MB more); moving to it needs the product owner's decision on elkjs. 11.x still gets maintenance releases; the pin is exact.

Packaging (#324, ADR-0014): `electron-builder` 26.17.0 (MIT), dev only, in its own package `toolchain/packaging/` with its own lockfile (exception to ADR-0001), installed with `--ignore-scripts` and audited (`pnpm audit --audit-level high`) only by the release workflow; a finding blocks the release build. None of its about 220 packages is shipped; one of them is WTFPL (`truncate-utf8-bytes`), which the allowlist above (for runtime dependencies) does not need to cover. It downloads the Electron zip at build time and verifies its checksum (`@electron/get`); nothing is downloaded at run time. The third-party notices file the SR-111 paragraph asks for is `resources/THIRD_PARTY_NOTICES.txt` in every artifact.

User documentation site (#344, ADR-0017): `astro` 7.3.8, `@astrojs/starlight` 0.42.6 and `starlight-links-validator` 0.27.0 (all MIT), dev only, in `packages/docs/site/` with its own lockfile outside the workspace, installed with `--ignore-scripts` and audited (`pnpm audit --audit-level high`) only by the docs steps of CI and `docs-pages.yml`. Astro builds the site, Starlight gives the docs layout and the local search (Pagefind, MIT), the validator fails the build on dead internal links. Nothing of it ships in the product; the built site is static HTML, CSS and scripts without network access. Their about 290 packages are MIT, ISC, BSD, Apache-2.0, BlueOak, MPL-2.0, CC0 and Python-2.0, except libvips (LGPL-3.0-or-later, the image library of `sharp`), which the allowlist for runtime dependencies does not need to cover because it is never shipped. The pins are exact and were at least two weeks old when chosen.
