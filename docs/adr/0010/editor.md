# ADR-0010, part: Editor, property boxes, title and copy

Part of [ADR-0010](../0010-electron-app.md). Read this part when you work on `src/renderer/editor/`, `TextBox.tsx`, `TitleBox.tsx`, `property-edit.ts`, the copy symbols; the decision itself is in the ADR.

- Editor (SR-065, #77): CodeMirror 6 in live-preview mode (D-061) in the element buffer. Decorations only, the document is never rewritten: headings, emphasis, lists, task lists, tables, code blocks, quotes and links appear set; the Markdown source shows only on the lines the cursor touches while the editor has the focus, and a table shows its source while the cursor is in it (spec question #420). Nothing from a file is interpreted as HTML (widgets use text nodes). The input is saved without a save command (SR-105, `autosave.ts`): one `element.update` one second after the last change of a document, at most one save per buffer at a time, waiting while input is still going on (an input method composing, an open slash menu, "Insert reference" open) but not when the buffer is left (a `/query` is then written as typed), at once when the buffer is left (also when the window closes or the app quits) or a prompt opens, never over a change on disk, a deleted file or a read-only element; Ctrl/Cmd+S ("Save element", a key, not a button) saves at once. Undo and redo reach back to the opening of the buffer: the app keeps each editor's state with its history (`EditorState.toJSON`/`fromJSON` with `historyField`, not live states, whose extensions close over the old component) and each choice or relation box's value history per open buffer (`buffer-memory.ts`, `value-history.ts`), with the saves of the buffer in order, so a buffer shown again while its leaving save runs reads after it; Enter on the element edits, Escape leaves the text. An inline reference (`reqseq:` link) opens its element on a click on its label and with Ctrl/Cmd+Enter (the editor only finds what is under the pointer or the cursor; whether a reference is outdated comes from the `relation.outdated` hints of `element.get`, shown in the accent colour with the word "outdated"). A reference to another repository has the short ID as its label in the file (ADR-0004); off the lines that show their source the editor shows the title of its target in place of it when the target is here, asked of core once per target with `element.get` and kept by the app for the workspace that is open (`reference-titles.ts`: also "not here", but no other failure, which is asked again; a pick brings the title of its target along; cleared when another workspace opens or core restarts; core giving the titles with the element is #669) (D-058; the label of a reference within the repository is shown as written, spec question #622). The modeline names the type by its name in the metamodel (`metamodel.get`). Extension points (`editor/plugins.ts`): parser extensions and preview rules for formulas and diagrams (KaTeX and Mermaid bundled locally, #108; the live preview does not draw images yet, an inserted image, SR-097, shows its Markdown), further CodeMirror extensions (the slash menu and the `[[` search below). Formulas (SR-096, `editor/math-syntax.ts`, `formula.ts`, `formula-preview.ts`, plugged in by `formulas-diagrams.ts`) use GitHub's notation, which follows from CommonMark with GitHub extensions (SR-065 AK2, SR-129): `$…$` within a line (no white space inside the dollars, no digit after the closing one, `\$` escapes), `$$…$$` within a line, a block between two lines that are only `$$` (a formula only once its closing line is there and without a blank line inside, so a lone `$$` stays a paragraph) and fenced `math` blocks; a `/` or `[[` in a formula opens nothing. KaTeX, bundled and loaded with the editor, sets them as DOM nodes, never as HTML, with `trust: false` (`\href`, `\url`, `\includegraphics` and `\html…` are drawn as text), `maxSize` 20, `maxExpand` 1000, `strict: "ignore"` and a grey `errorColor` (D-062). Off the lines that show their source a formula replaces its source; while the cursor is in a block formula its whole source shows with the set formula directly below it, and while the caret is inside a `$…$` a tooltip that takes no input shows the set formula under the line (assumption A1, spec question #420); a formula with a syntax error keeps its source and KaTeX's message follows it in grey (SR-096 AK3). A block in a list item or a quote keeps its source with the formula below. A preview rule can own a node (`PreviewRule.owns`, decided on the focus and the selection), so the built-in rules leave a fenced block alone that a formula replaces. Set formulas are kept by source (2,000 of them); a text with more sets the others again on each change. KaTeX's fonts are woff2 files served by `app:`: the renderer build drops the woff and ttf alternatives of its style sheet and inlines no font, because the CSP has no `font-src` and `default-src 'self'` blocks a `data:` font; the CSP is unchanged. `test/renderer-bundle.spec.ts` checks the built renderer: only file types `app:` serves, no `url(data:` in a style sheet, and no network, worker or `eval` API in a script (a hit is reviewed and fixed, never allowed silently). Diagrams (SR-096, `editor/diagram.ts`, `mermaid-renderer.ts`) are fenced `mermaid` blocks, drawn by Mermaid 11, bundled and loaded on the first diagram (its chunks are `app:` files). Mermaid's SVG is never put into the page as markup: it becomes the `data:` URL of an `<img>` (the CSP has `img-src data:`), in which nothing runs, loads, gets events or styles the page; error messages are text nodes. Mermaid runs with `securityLevel: "strict"`, `htmlLabels: false` (labels of flowcharts, state and class diagrams as SVG text, so math there stays its source; sequence diagrams ignore it and set `$$…$$` in messages, notes and actors with the bundled KaTeX as MathML in a `foreignObject`, inert inside the image, while KaTeX's measuring `div` goes into `body` for that moment), `deterministicIds`, `suppressErrorRendering`, and a `secure` list that keeps the security level, the limits, the theme, the CSS and the font from `%%{init}%%` directives; it draws in the greys of the app's tokens (`theme: "base"`, the tokens resolved to colours), again when the colour scheme changes, and colours the author writes in the diagram are drawn as written (assumption A3, D-062). While it draws, Mermaid builds a temporary SVG in the page to measure the text: in a container of its own (`mermaid-renderer.ts`), out of view but laid out, emptied after each drawing. That temporary DOM is built before Mermaid's DOMPurify pass, which sanitizes only the serialized output, so the barrier there is the CSP (`script-src 'self'`, no inline handlers) and the sandboxed renderer; `strict` (label texts sanitized, no click handlers) is defence in depth. A sandboxed iframe is not possible (`frame-src 'none'`), and a worker has no layout. Mermaid draws on the main thread, so the drawing is kept off the keystroke path: a view plugin draws the diagrams of the visible ranges after a pause of three times the last drawing's duration (at least 300 ms, at most 5 s) after the last change, and at once when the cursor leaves the diagram, one at a time, and keeps the drawings by source (64 of them); `decorate` only reads them, and the last drawing stays below the source until the new one arrives. One drawing still holds the main thread for its whole layout (measured in `test/diagrams.spec.ts`, about 1.3 s for 300 edges and 2 s for the largest flowchart on the Linux CI container), so a pause of that length when a large diagram is drawn again, and when an element with such a diagram opens and it is not drawn yet, is the accepted residue. Bounds of the size, each ending in an error message below the source (AK3): 50,000 characters and 500 statements (non-empty lines or parts of a line between `;`, which several diagram types accept) for every diagram type, checked before Mermaid sees the text (Mermaid itself would draw a box with a message instead of an error), and Mermaid's 500 edges of a flowchart. They limit the size, not every shape: a diagram inside them can still hold the main thread for seconds, depending on its shape (a fan-out of 500 edges written as `a --> b & c` held it for about 8 s); a bound for that (edges per node or a lower edge cap, measured across shapes) is a follow-up in #726. Off the lines that show their source the drawing replaces the fence; while the cursor is in it, its source shows with the drawing below it (A1, #420); with an error the source stays and Mermaid's message follows it in grey. Properties are boxes below the text, edited in place (below); Markdown properties reuse the editor. Slash menu (SR-129, `editor/slash-menu.ts`, `slash-entries.ts`): a `/` that is typed (not pasted, not brought back by undo) at the start of a line or after white space, outside code, links, addresses and HTML, opens the list of `@codemirror/autocomplete` at the caret with the Markdown elements (headings, normal text, lists, task list, quote, code block, table, link, reference to an element, image, math block, diagram, bold, italic; no underline, D-015). It is ranked like the minibuffer (`fuzzy.ts`: initials first, then letters in order, then one slip), Down/Up, Tab and Ctrl+N/Ctrl+P (SR-122) choose and Enter takes the entry, Escape closes the menu only and leaves the `/` and the query as typed (only the menu of a typed `/`: every letter asks the menu's source, and an Escape before that answer, with no `/` typed, is the editor's own and leaves the text, #574); while the menu is open it handles these keys (a handled key is prevented, so Ctrl+P does not open "Go to"), closed it handles none. Taking an entry is one transaction and one undo step, which brings back the `/` with its query. The menu edits the text only and adds no catalog command (ADR-0002): the file is saved by `element.update`, "Image" asks for an image file in the prompt "Insert image" of the action of the same name (SR-097: `element.addAttachment` copies it into the folder named like the element file and returns the Markdown that embeds it relatively, which the editor writes in place of the `/` and its query; Escape or a refused file leave them as typed), and "Reference to element" asks the same `element.search` as "Go to" in a minibuffer prompt "Insert reference" and writes `[title](reqseq:<uuid>)` (the short ID and `?version=&repository=<name>` for a target in another repository, D-058; the empty `version=` keeps its place, so core fills it on save and the order is `version`, `repository` as in ADR-0004). `[[` search (SR-066, `editor/reference-search.ts`; the waiting text and the write of the reference are `reference-pick.ts`, shared with the slash menu): a second `[` typed right after a `[` (not pasted, not brought back by undo, not composed by an input method, not after `\` or `!`, not a third `[`, not in code, links, addresses or HTML, the rule of the slash menu, #453, and not in the query of a `/` while its menu shows entries) opens the same prompt "Insert reference" with the same `element.search` over title and IDs of all elements, not a list at the caret (the smallest step, one search for both triggers); the pick replaces the `[[` with the reference as "Reference to element" writes it, in one undo step that brings back the `[[`; text typed after the `[[` before the prompt has the focus stays after the reference; Escape leaves the `[[` as typed; autosave waits while the prompt is open. `[[` is only the typing trigger: the file holds the Markdown link (ADR-0004 rejects wiki links in files). The library's base theme is overridden with the colour tokens only, as the colour test requires.
- Property boxes (SR-104, SR-127, `TextBox.tsx`, `property-edit.ts`): every property that is set and not empty is a box below the text with its key and its values and nothing else (no form, no dialog, D-062); the targets of a property of kind `relation` (the outgoing relations with `property: true` of `element.get`) are a box with one link per target, and the relation groups keep only the relations of relation kinds and the incoming ones. The box is built from the type of the element in `metamodel.get` (kind, list or single value, `markdown`; the app only reads it). A property of a text kind (text, number, date) is one editor per box with the values, one per line, editable. The value of a choice or relation property is set in the minibuffer, the one control (D-062, no second menu): Enter on its box opens a prompt named after the property (`property-prompts.ts`) whose entries are only the choices of the metamodel (no free text, SR-104 AK3), or the targets that are set (taking one removes it, taking one of a list toggles it) and the elements `element.search` finds among the target types of the property (taking one replaces the target of a single relation and is appended to a list); with the same fuzzy search as the command line. A property the type does not know (D-012; core refuses `set` and `unset` of it, spec question #469) and a list with a value that holds a line break stay read-only. "Add property" (Ctrl/Cmd+Alt+A, macOS ⌥⌘A, in the command prompt too; not Cmd+Shift+A, which macOS gives to the service "Search man Page Index in Terminal" when text is selected. Cmd+Option counts the physical key, since Option changes the character; Ctrl+Alt does not, since on Windows it is AltGr, which types letters such as Polish ą) asks which of the properties of the type the element lacks (by name, the key as hint; a key stored empty is offered, the title is not) and puts an empty box at its place in the order of the type with the caret in it (text kinds), or with the focus on it and the value prompt open at once (choice and relation: there is no text cursor, so the focus is the cursor and the prompt is the completion, SR-104 AK2 and AK3 read with D-062). When that prompt ends, taken or escaped, the focus goes back to the box, an exception to "after a prompt the focus goes to the element". An added box with nothing in it is no draft and is dropped at the next save or when the buffer is left. "Clear property" (command prompt, no key) empties the box with the cursor or the one the cursor was in; no key on a box clears it; a choice or relation box has a value history of its own, so Ctrl/Cmd+Z and Ctrl/Cmd+Shift+Z on it undo and redo its changes (SR-105 AK2). The Markdown properties (`markdown: true`) use the live preview of the text with the inline rules only and the Markdown source on the line with the caret; every line is a paragraph of its own (`editor/value-lines.ts`), so a mark never pairs across two values, and the block syntax of a text (headings, lists, quotes, code, tables, HTML) is plain text in a value. No image preview (an image in a property is no embedded image, ADR-0004, D-057), no slash menu. `[[` asks for an element in an editable box of a property marked `markdown` as in the text and writes the reference into that value (SR-127 AK2, the same `reference-search.ts`; autosave waits while any editor of the buffer waits for its element); a property that is not marked, and a read-only box, have no `[[` search (SR-127 AK5). A reference to another repository in a value shows the title of its target like one in the text. A reference in a value is marked "outdated" like one in the text, from the `relation.outdated` hints of `element.get` whose place is `@text:<key>`; a click on its label follows it, Ctrl/Cmd+Enter follows the reference at the caret, or the first one of a box that has the focus itself. Keys: one Tab stop per box, and one more per target link in a relation box; Enter on the box edits it, Enter in a single value leaves it, Enter in a list starts a value, no key inserts a line break in a value; Escape leaves the box, then the element; Down at the last line and Up at the first line of an editor go to the next and previous box (`editor/box-navigation.ts`, visual lines of a wrapped value count; on macOS Ctrl+N / Ctrl+P too). The one write is `element.update { ref, text?, set?, unset? }`, by autosave or "Save element": the text and every box whose document differs from the stored value go together, an emptied box (only blank lines left) is `unset` so its property leaves the file and the box disappears (SR-104 AK4); blank lines are dropped and every other line is kept byte for byte; a number property stores a decimal literal as a number. The unsaved boxes are part of the draft of the buffer (with the stored values they were typed on, for the rule of SR-106). "Copy field" copies what the editor of the box holds, the unsaved input included, one value per line. A choice or relation box is part of the draft as its keys, or as one line per target with its id, repository and label separated by tabs (`<id>\t<repository>\t<label>`); an added box has the empty document as its base.
- Title (#621, SR-104, SR-073 AK1; spec question #676, `TitleBox.tsx`, `title-box.ts`, `editor/single-line.ts`): the title is edited where it is shown, in the heading of the element, as one line of plain text (SR-127 AK5: no preview rule and no `[[` search), no box, label or input (D-062). While it is not edited the heading is plain text; entering it (Enter on the field of the title, a click on the heading with the caret where the browser puts it, "Edit title" in the command prompt, Up at the first line of the text) puts a CodeMirror editor into the same heading for the life of the buffer, styled so that neither the heading nor the text below moves. Enter, Shift+Enter and Escape leave it for its field; Down at the line goes to the text; a line break typed or pasted becomes one space and empty lines are dropped (a transaction filter on input; `Editor.set`, which replaces the document from outside as `input.set`, is left alone). The title is one more field of the buffer, keyed `Title` (`TITLE_FIELD`): it goes into the same `element.update` as `title` (never into `set` or `unset`, which core refuses for it), is part of the draft with the stored title it was typed on, is saved by autosave and Ctrl/Cmd+S (SR-105), has its own undo memory, and a change of the file under the input is resolved like a box (block "On disk", SR-106). An emptied title is saved as `title: ""` with core's hint `element.missing-required` appended to "Saved ...", and the heading shows the short ID of the element muted (assumption of #676). A title that holds a line break (written outside) and the title of a locked or deleted element are read-only; a type without a property of meaning title has none to edit. The names of open buffers keep the old title until they are opened again (#678).
- Copy field (SR-128): every field of the element buffer (the title, the text, each property box, each group of relations) is a `div.field` with a copy symbol at its right edge, a button of 1.5rem that has no tab stop and keeps the focus where it is on a press (so the editor keeps its cursor). It is `visibility: hidden` unless the pointer is over the field or the focus is in it (`:hover`, `:focus-within`); the title and the boxes have a `tabindex` so that the focus can be in them. The ID that the modeline names the element by (the identifier, else the short ID) is a field of the modeline: its symbol is the only control there. The value is the one the file stores as text, one value per line (the Markdown source of the text, the lines of a box and the labels of the relations as shown, #457). A click on the symbol, or the action "Copy field" (Ctrl/Cmd+Shift+C; in the command prompt too, which copies the field the focus was in before the prompt opened it), calls `copyText` and the modeline says "Copied <field>" for 3 s, or "Copy failed". With the focus in no field the action copies the ID. A plain click on a field only sets the cursor and copies nothing (AK4). The symbol uses the colour tokens only.
