# ADR-0010: Electron app: process model and security

Status: Proposed · Based on: D-003, D-004, D-019, D-029, D-061, D-062, D-063 · SRs: SR-065, SR-066, SR-073, SR-074, SR-076, SR-077, SR-078, SR-082, SR-100, SR-104, SR-113, SR-125, SR-127, SR-128, SR-129

## Decision

**Processes**
- *Main process:* windows, menus, file dialogs, the API server when enabled. No program logic.
- *Core process:* `core` runs in an Electron `utilityProcess` (plain Node), so long commands never block the window. Main passes a `MessagePort` between renderer and core process, a new one on every page load. There is one core process per open workspace, opened as `logreq serve api` opens it: the root is found upwards from the chosen folder (else the folder itself), the model cache lies in the cache folder of the copy, and the watcher starts before the load. Opening another workspace stops the core process: running reads are aborted, running writes finish, then the workspace closes; the process is killed after 5 s. The app stops it the same way before it quits. A write also finishes when its window goes away. A core process that cannot open its workspace ends with exit code 1.
- *Renderer:* UI only. It calls `window.logreq.invoke(name, input)` and subscribes to `window.logreq.on("workspace-changed", …)` via a minimal preload bridge (`contextBridge`; the preload is one CommonJS bundle, as the sandbox requires). It cannot reach Node, the file system or the network.
- *Bridge (#322):* it is generic over the catalog and offers only four functions:
  - `invoke` resolves to `{ ok: true, output }` or `{ ok: false, error }` with the error object of every access. It never rejects, because the context bridge keeps only an error's message.
  - `commands()` gives the catalog entries with `implemented`, as `GET /v1/commands` of the API does.
  - `copyText(text)` (SR-128) puts a text on the system clipboard and resolves `true`, or `false` when it could not. It never rejects. It is a facility of the window like the theme, so it is no catalog command (ADR-0002): it computes nothing, and CLI, API and MCP already give every value of a field with `element get` (SR-080). It is the one message from the renderer to the main process, `ipcRenderer.invoke("logreq:copy", text)` answered by `ipcMain.handle`; the renderer's own clipboard API is not used, because the session refuses every permission. The renderer is not trusted, so main writes the clipboard with `clipboard.writeText` only for a string of at most 16 Mi characters, from `event.senderFrame` that is the main frame of the web contents of the LogReq window, whose URL has the protocol `app:` and the host `logreq`; anything else, and a clipboard that cannot be written, resolves `false` and writes nothing. Nothing is ever read from the clipboard.
  - `on("workspace-changed")` gets `{ reason }`: `opened`, `restarted`, `stopped` or `written` (a write command of the app). Changes from outside the app follow with a change event of core's watcher (#331).

**Security settings (all windows)**
- `contextIsolation: true`, `sandbox: true`, `nodeIntegration: false`, `webSecurity: true`, no `webview`, no `remote`.
- Content Security Policy, sent as a response header with every page: `default-src 'self'; img-src 'self' data: logreq-file:; style-src 'self' 'unsafe-inline'; script-src 'self'; connect-src 'none'; object-src 'none'; base-uri 'none'; form-action 'none'; frame-ancestors 'none'; frame-src 'none'`.
- The renderer is loaded from a custom `app://` protocol serving the bundled files (`app://logreq/index.html`; no development server). Images of elements are served by a `logreq-file:` protocol, `logreq-file://workspace/<repository>/<path>`, that only serves image files inside an available repository of the workspace. The repository is in the path because Chromium canonicalises hosts like `1.2` into IPv4 addresses. The path is checked lexically first (no `\`, `:` or NUL, inside the repository folder), so no UNC share or automount is touched; then links are resolved and checked again. The core process reads the files, and main relays them.
- All navigation, `window.open` and webviews are denied. External links open in the system browser only after the user clicks them; that arrives with the first screen that shows links. Redirects and the navigation of every frame are denied too. Every permission request (camera, notifications, ...) and every device chooser (HID, serial, USB, Bluetooth) is refused. The spell checker is off, because it downloads dictionaries, and its download URL points at a local URL that serves nothing. The CSP adds `frame-src 'none'`.
- Menu: minimal, so the keys stay free for the minibuffer and buffers (D-061..D-063): File > Open Workspace (Ctrl/Cmd+O), Quit (Close on macOS), Edit. Reload (F5) and the developer tools (F12) only in unpackaged builds.
- `session.webRequest.onBeforeRequest` cancels every request that is not `app:`, `logreq-file:` or `devtools:` (SR-078).
- No auto-updater, no crash reporter upload, no telemetry (SR-078). Electron fuses: `runAsNode` only for the bundled CLI entry (ADR-0014), `EnableNodeCliInspectArguments` off.

**UI** (D-061..D-063)
- React with TypeScript, bundled with `electron-vite`. A white sheet (D-062): the window shows one buffer (a list, a search result, an element or a neighbourhood; later a graph, D-063), a quiet modeline (a display, not a control, with one exception: the ID of an element carries the copy symbol of a field, below) and the minibuffer. There is no tab bar, no permanent sidebar or tree, no form and no modal dialog (SR-100 AK1). Colour only for meaning: greys, and one accent colour for "outdated" and for a gap in the traceability chain ("—" in a cell of the matrix, D-062: „Farbe trägt nur Bedeutung, zum Beispiel veraltet oder Lücke in der Kette“; the token `--accent-gap` has the value of `--accent-outdated`).
- The first buffer of a workspace is the overview: one line per element type with its count (`element.facets`) and the five elements opened last; the full list opens only with "List all elements" (SR-118). Closing the last buffer shows the overview. The elements opened last are display state of the app (UUID and repository, per workspace) in the app's local storage, not in the workspace.
- Command prompt ranking (SR-108 AK3, SR-121 AK2, `usage.ts`): what was chosen is display state of the app, like the elements opened last: kept in the app's local storage under `logreq.usage.v1`, not per workspace (the commands are the same in every workspace) and never in the workspace or through a catalog command (SR-080 AK1: "außer reiner Darstellung der App"). Only the command ID and the text typed in the command prompt are recorded, with the count and the time of the last use (at most 500 commands and 500 texts); nothing for "Go to", argument steps or elements. Order: the match comes first (initials, letters in order, one slip per word); equally good matches go by use (uses divided by one plus the days since the last one); the command chosen the last time for exactly this text (lower case, spaces collapsed) comes first, when it is offered and matches now. A storage that is missing or throws gives the plain order.
- Minibuffer: the only control, apart from two exceptions: the copy symbols of the fields (SR-128, below; seen only on hover or focus) and the editor's transient `/` menu at the caret (SR-129, below; whether D-062 allows it is the spec question #453, until it is answered the menu only inserts formatting). Ctrl/Cmd+Shift+P opens the command prompt, Ctrl/Cmd+P jumps to an open buffer or to an element, Ctrl/Cmd+Shift+F searches; each entry shows its shortcut. In a prompt, Down/Up, Tab and Ctrl+N/Ctrl+P (the physical Ctrl key on every platform, also macOS) move the selection (SR-122); the prompt stops these keys, so they never reach the global shortcuts (Ctrl+P is "Go to" otherwise), and a key that a control handled is no shortcut (the window handler ignores a prevented key). In the text editor on macOS, CodeMirror binds the Emacs keys Ctrl+N/Ctrl+P to the caret, so there they move the caret and do not open "Go to"; Cmd+P does. The same holds for Ctrl+T (the traceability matrix, below): the physical Ctrl+T in the text editor on macOS stays the Emacs "transpose" of CodeMirror and shows no matrix; Cmd+T does. Every action has a keyboard path (SR-073 AK1). The prompt finds every function by its name (SR-073 AK2). So far it lists the actions of the app that apply to the shown buffer; the catalog commands follow with #85, because they need argument entry. Names of actions and open buffers are ranked with uFuzzy in the renderer (UI only), and a query of one word that gives the beginnings of the words of a name finds it first (`flp` for "Filter list by property", SR-121 AK1); elements are found by `element.search` in core (ADR-0002). Lists come from `element.list` (filter, sort, derivation tree) in pages of 200, search results in pages of 50. A list starts sorted by type, then ID (#418): the app sends `sort: [{"by":"type","order":"asc"},{"by":"identifier","order":"asc"}]` (`DEFAULT_SORT`; digit runs by number, SR-9 before SR-10), which a CLI user reproduces with that input; `element.list` without `sort` stays the workspace order for every other access, and the modeline says nothing about the default (D-062). "Sort list" offers "Type and ID" (the default, sent explicitly), "Workspace order" (`sort: []`, named in the modeline) and the other keys; a list with a saved filter and no chosen sort keeps the filter's own sort (SR-070 AK3). Assumption: no SR sets a default order, so it is the app's choice of the input (ADR-0002). List filters cascade (SR-124): a list keeps its filter steps, each adds a condition (or the one saved filter) to the selection it sends to `element.list`, and the values "Filter list by property" offers come from `element.facets`, so the app counts and filters nothing itself.
- Editor (SR-065, #77): CodeMirror 6 in live-preview mode (D-061) in the element buffer. Decorations only, the document is never rewritten: headings, emphasis, lists, task lists, tables, code blocks, quotes and links appear set; the Markdown source shows only on the lines the cursor touches while the editor has the focus, and a table shows its source while the cursor is in it (spec question #420). Nothing from a file is interpreted as HTML (widgets use text nodes). Ctrl/Cmd+S saves with `element.update` (autosave follows with #401); Enter on the element edits, Escape leaves the text. An inline reference (`logreq:` link) opens its element on a click on its label and with Ctrl/Cmd+Enter (the editor only finds what is under the pointer or the cursor; whether a reference is outdated comes from the `relation.outdated` hints of `element.get`, shown in the accent colour with the word "outdated"). The modeline names the type by its name in the metamodel (`metamodel.get`). Extension points (`editor/plugins.ts`): parser extensions and preview rules for formulas and diagrams (KaTeX and Mermaid bundled locally, #108) and images (#109), further CodeMirror extensions for `[[` element search with an inline reference (#78, ADR-0004). Properties are boxes below the text, edited in place (below); Markdown properties reuse the editor. Slash menu (SR-129, `editor/slash-menu.ts`, `slash-entries.ts`): a `/` that is typed (not pasted, not brought back by undo) at the start of a line or after white space, outside code, links, addresses and HTML, opens the list of `@codemirror/autocomplete` at the caret with the Markdown elements (headings, normal text, lists, task list, quote, code block, table, link, reference to an element, image, math block, diagram, bold, italic; no underline, D-015). It is ranked like the minibuffer (`fuzzy.ts`: initials first, then letters in order, then one slip), Down/Up, Tab and Ctrl+N/Ctrl+P (SR-122) choose and Enter takes the entry, Escape closes the menu only and leaves the `/` and the query as typed; while the menu is open it handles these keys (a handled key is prevented, so Ctrl+P does not open "Go to"), closed it handles none. Taking an entry is one transaction and one undo step, which brings back the `/` with its query. The menu edits the text only and adds no catalog command (ADR-0002): the file is saved by `element.update`, and "Reference to element" asks the same `element.search` as "Go to" in a minibuffer prompt "Insert reference" and writes `[title](logreq:<uuid>)` (the short ID and `?version=&repository=<name>` for a target in another repository, D-058; the empty `version=` keeps its place, so core fills it on save and the order is `version`, `repository` as in ADR-0004). The library's base theme is overridden with the colour tokens only, as the colour test requires.
- Property boxes (SR-104, SR-127, `TextBox.tsx`, `property-edit.ts`): every property that is set and not empty is a box below the text with its key and its values and nothing else (no form, no dialog, D-062); the targets of a property of kind `relation` (the outgoing relations with `property: true` of `element.get`) are a box with one link per target, and the relation groups keep only the relations of relation kinds and the incoming ones. The box is built from the type of the element in `metamodel.get` (kind, list or single value, `markdown`; the app only reads it). A property of a text kind (text, number, date) is one editor per box with the values, one per line, editable. The value of a choice or relation property is set in the minibuffer, the one control (D-062, no second menu): Enter on its box opens a prompt named after the property (`property-prompts.ts`) whose entries are only the choices of the metamodel (no free text, SR-104 AK3), or the targets that are set (taking one removes it, taking one of a list toggles it) and the elements `element.search` finds among the target types of the property (taking one replaces the target of a single relation and is appended to a list); with the same fuzzy search as the command line. A property the type does not know (D-012; core refuses `set` and `unset` of it, spec question #469) and a list with a value that holds a line break stay read-only. "Add property" (Ctrl/Cmd+Alt+A, macOS ⌥⌘A, in the command prompt too; not Cmd+Shift+A, which macOS gives to the service "Search man Page Index in Terminal" when text is selected. Cmd+Option counts the physical key, since Option changes the character; Ctrl+Alt does not, since on Windows it is AltGr, which types letters such as Polish ą) asks which of the properties of the type the element lacks (by name, the key as hint; a key stored empty is offered, the title is not) and puts an empty box at its place in the order of the type with the caret in it (text kinds), or with the focus on it and the value prompt open at once (choice and relation: there is no text cursor, so the focus is the cursor and the prompt is the completion, SR-104 AK2 and AK3 read with D-062). When that prompt ends, taken or escaped, the focus goes back to the box, an exception to "after a prompt the focus goes to the element". An added box with nothing in it is no draft and is dropped at the next save or when the buffer is left. "Clear property" (command prompt, no key) empties the box with the cursor or the one the cursor was in; no key on a box clears it (no undo for a choice or relation). The Markdown properties (`markdown: true`) use the live preview of the text with the inline rules only and the Markdown source on the line with the caret; every line is a paragraph of its own (`editor/value-lines.ts`), so a mark never pairs across two values, and the block syntax of a text (headings, lists, quotes, code, tables, HTML) is plain text in a value. No image preview (an image in a property is no embedded image, ADR-0004, D-057), no slash menu, no `[[` search yet (#78). A reference in a value is marked "outdated" like one in the text, from the `relation.outdated` hints of `element.get` whose place is `@text:<key>`; a click on its label follows it, Ctrl/Cmd+Enter follows the reference at the caret, or the first one of a box that has the focus itself. Keys: one Tab stop per box, and one more per target link in a relation box; Enter on the box edits it, Enter in a single value leaves it, Enter in a list starts a value, no key inserts a line break in a value; Escape leaves the box, then the element; Down at the last line and Up at the first line of an editor go to the next and previous box (`editor/box-navigation.ts`, visual lines of a wrapped value count; on macOS Ctrl+N / Ctrl+P too). The one write is `element.update { ref, text?, set?, unset? }` on "Save element": the text and every box whose document differs from the stored value go together, an emptied box (only blank lines left) is `unset` so its property leaves the file and the box disappears (SR-104 AK4); blank lines are dropped and every other line is kept byte for byte; a number property stores a decimal literal as a number. The unsaved boxes are part of the draft of the buffer (with the stored values they were typed on, for the interim "changed on disk" echo of #401/#402). "Copy field" copies what the editor of the box holds, the unsaved input included, one value per line. A choice or relation box is part of the draft as its keys, or as one line per target with its id, repository and label separated by tabs (`<id>\t<repository>\t<label>`); an added box has the empty document as its base.
- Neighbourhood (SR-107): a buffer of its own, opened from an element with Ctrl/Cmd+J and left the same way. It shows the children as a tree and the incoming relations and references by kind. Both are `trace.neighbourhood`: the tree with `meanings: ["derivation"]` from the element and a growing `maxDepth` (the deepest open row plus two, so every shown row knows whether it has children; Right and Left open and close a row), the groups from one unfiltered call of depth 1. The element is named by UUID and repository (`repository` input, as `element.get`). The parents line above the title of every element page is `trace.neighbourhood` with `direction: "up"`. The app builds the inputs and shows the output in the order of the walk (ADR-0002).
- Traceability matrix (SR-125): a mode of the list buffer (`ListBuffer.matrix`, D-062), not a buffer of its own: Ctrl/Cmd+T ("Show traceability matrix") shows the list as a table and Ctrl/Cmd+T ("Show as list") brings the rows back, the selected row kept. The matrix has the key of the list, so it replaces the list in place and "Filter list by ...", "Clear list filter" and "Sort list" keep the mode (they rebuild the list from its steps and carry the flag). A package page offers the same shortcut and opens the list of its members (`where.package`, its sort) in matrix mode. The table is `trace.matrix` for the selection and sort of the list (the same input as `element.list`, so rows, columns, cells, counts and shares are what CLI, API and MCP give, ADR-0002, SR-080): one row per element, one column per relation kind and direction that occurs, each cell the elements at the other end as "<identifier or short ID> <title>", a "—" in the accent colour for a gap, "outdated" and the state of an end that is not there ("missing") marked as in the element view, and above each column "<count> · <share> %" over the whole selection. The app computes nothing: it formats the share as a whole percent and lays the answer out. Up/Down select a row, Right/Left step through the row element and the relations of its cells, Enter or a click opens the element (an end that is not there opens nothing and the modeline says why). Rows come in pages of 200 as in the list. Search results and the neighbourhood have no entry yet.
- Copy field (SR-128): every field of the element buffer (the title, the text, each property box, each group of relations) is a `div.field` with a copy symbol at its right edge, a button of 1.5rem that has no tab stop and keeps the focus where it is on a press (so the editor keeps its cursor). It is `visibility: hidden` unless the pointer is over the field or the focus is in it (`:hover`, `:focus-within`); the title and the boxes have a `tabindex` so that the focus can be in them. The ID that the modeline names the element by (the identifier, else the short ID) is a field of the modeline: its symbol is the only control there. The value is the one the file stores as text, one value per line (the Markdown source of the text, the lines of a box and the labels of the relations as shown, #457). A click on the symbol, or the action "Copy field" (Ctrl/Cmd+Shift+C; in the command prompt too, which copies the field the focus was in before the prompt opened it), calls `copyText` and the modeline says "Copied <field>" for 3 s, or "Copy failed". With the focus in no field the action copies the ID. A plain click on a field only sets the cursor and copies nothing (AK4). The symbol uses the colour tokens only.
- Package page (SR-112): an element whose type has the meaning `package` shows below its title, text, properties and relations the elements that name it (`element.list` with `where.package`, read-only like any list). They sort and show as a tree with "Sort list" like any list; Down on the page goes into them, Escape and Up on the first row come back. The page stays the element buffer, so the editor, saving and the draft are unchanged; the list is a part of it, not a buffer of its own.
- Graph (D-063): the current element and what hangs on it, in layers, with an existing library (licence check per ADR-0015 when it comes).
- All UI text is English, no i18n framework (D-019, SR-074).
- Light and dark (SR-113): colours are custom properties with `light-dark()`; `color-scheme` follows the OS (`prefers-color-scheme`, from `nativeTheme`) at start and while running. "Toggle dark mode" sets `data-theme` on the root for the running app only (nothing is stored, AK1); "Follow system light or dark mode" removes it. The window background at start follows `nativeTheme`. The native title bar keeps the OS look (no bridge function for `themeSource`).

## Consequences

- Renderer bugs cannot touch files or the network directly.
- The core process restarts independently if it crashes; the window shows a message and reloads the workspace. After more than 3 stops within 60 s it is not started again, and the window says so.

## Rejected

- Core in the main process: blocks the UI on long checks.
- Monaco: larger, more than a Markdown editor needs.
