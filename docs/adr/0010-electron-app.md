# ADR-0010: Electron app: process model and security

Status: Proposed · Based on: D-003, D-004, D-019, D-029, D-061, D-062, D-063 · SRs: SR-065, SR-066, SR-073, SR-074, SR-076, SR-077, SR-078, SR-082, SR-100, SR-104, SR-106, SR-111, SR-113, SR-115, SR-116, SR-117, SR-125, SR-127, SR-128, SR-129, SR-130, SR-131, SR-132

## Decision

The ADR states the decisions; the details of the bridge and of the UI are in the parts under [`0010/`](0010/), one file per topic. Read only the part you work on.

**Processes**
- *Main process:* windows, menus, file dialogs, the API server when enabled, and the switch to a recent workspace or to the workspace of a typed folder that the window asks for (SR-131). No program logic: the list of recent workspaces, its existence checks and the check of a typed path are core's (`@reqseq/core/recent-workspaces`, a module of its own that loads no schema validator and no command, imported on the first request, so the start of main loads no part of core).
- *Core process:* `core` runs in an Electron `utilityProcess` (plain Node), so long commands never block the window. Main passes a `MessagePort` between renderer and core process, a new one on every page load. There is one core process per open workspace, opened as `logreq serve api` opens it: the root is found upwards from the chosen folder (else the folder itself), the model cache lies in the cache folder of the copy, and the watcher starts before the load. Opening another workspace (File > Open Workspace, or "Open workspace" in the window, SR-131) first has the window save its unsaved input (SR-131 AK3, `onSave` below) and goes on only when the window answers that it is saved; then it stops the core process: running reads are aborted, running writes finish, then the workspace closes; the process is killed after 5 s. A root of the list of recent workspaces is opened exactly (`exact`): the folder itself is the root, and a folder without its workspace file fails, never opening a workspace above it. Once a workspace with a workspace file is open, the core process records its root in core's list of recent workspaces (`<OS cache>/logreq/recent-workspaces.json`, ADR-0008, `recordOpenedWorkspace`; not when that folder lies inside a repository of the workspace) and sends main its key with `ready`, so main can mark the open one; stopping waits for that write, and a failed write is a log line. The app stops it the same way before it quits. A write also finishes when its window goes away. A core process that cannot open its workspace ends with exit code 1.
- *Renderer:* UI only. It calls `window.logreq.invoke(name, input)` and subscribes to `window.logreq.on("workspace-changed", …)`, `on("agent-activity", …)` and `on("save-expired", …)` via a minimal preload bridge (`contextBridge`; the preload is one CommonJS bundle, as the sandbox requires). It cannot reach Node, the file system or the network.
- *Bridge (#322):* it is generic over the catalog and offers only seven functions. Details: [bridge and channels](0010/bridge.md).

**Security settings (all windows)**
- `contextIsolation: true`, `sandbox: true`, `nodeIntegration: false`, `webSecurity: true`, no `webview`, no `remote`.
- Content Security Policy, sent as a response header with every page: `default-src 'self'; img-src 'self' data: logreq-file:; style-src 'self' 'unsafe-inline'; script-src 'self'; connect-src 'none'; object-src 'none'; base-uri 'none'; form-action 'none'; frame-ancestors 'none'; frame-src 'none'`.
- The renderer is loaded from a custom `app://` protocol serving the bundled files (`app://logreq/index.html`; no development server). Images of elements are served by a `logreq-file:` protocol, `logreq-file://workspace/<repository>/<path>`, that only serves image files inside an available repository of the workspace. The repository is in the path because Chromium canonicalises hosts like `1.2` into IPv4 addresses. The path is checked lexically first (no `\`, `:` or NUL, inside the repository folder), so no UNC share or automount is touched; then links are resolved and checked again. The core process reads the files, and main relays them.
- All navigation, `window.open` and webviews are denied. External links open in the system browser only after the user clicks them; that arrives with the first screen that shows links. Redirects and the navigation of every frame are denied too. Every permission request (camera, notifications, ...) and every device chooser (HID, serial, USB, Bluetooth) is refused. The spell checker is off, because it downloads dictionaries, and its download URL points at a local URL that serves nothing. The CSP adds `frame-src 'none'`.
- Menu: minimal, so the keys stay free for the minibuffer and buffers (D-061..D-063): File > Open Workspace (Ctrl/Cmd+O), Quit (Close on macOS), Edit. Reload (F5) and the developer tools (F12) only in unpackaged builds.
- Channels from the renderer to main (`copyText`, `recentWorkspaces`, `openWorkspace`, and the answer of `onSave`): each takes only messages of the main frame of the LogReq window (`main/sender.ts`). Details: [bridge and channels](0010/bridge.md).
- `session.webRequest.onBeforeRequest` cancels every request that is not `app:`, `logreq-file:` or `devtools:` (SR-078).
- No auto-updater, no crash reporter upload, no telemetry (SR-078). Electron fuses (ADR-0014): `RunAsNode` on for the CLI launcher (a fuse applies to the whole binary), `EnableNodeCliInspectArguments` and `EnableNodeOptionsEnvironmentVariable` off, `OnlyLoadAppFromAsar` on.

**UI** (D-061..D-063)
- React with TypeScript, bundled with `electron-vite`. A white sheet (D-062): the window shows one buffer, or two side by side after "Split window" (SR-115 AK3, below) (a list, a search result, an element, a neighbourhood, a graph (D-063), the metamodel (SR-130) or the result of a catalog command laid out by its shape), a quiet modeline (a display, not a control, with one exception: the ID of an element carries the copy symbol of a field, below) and the minibuffer. There is no tab bar, no permanent sidebar or tree, no form and no modal dialog (SR-100 AK1). Colour only for meaning: greys, and one accent colour for "outdated" and for a gap in the traceability chain ("—" in a cell of the matrix, D-062: „Farbe trägt nur Bedeutung, zum Beispiel veraltet oder Lücke in der Kette“; the token `--accent-gap` has the value of `--accent-outdated`).
- The first buffer of a workspace is the overview: one line per element type with its count (`element.facets`) and the five elements opened last; the full list opens only with "List all elements" (SR-118). Closing the last buffer shows the overview. The elements opened last are display state of the app (UUID and repository, per workspace) in the app's local storage, not in the workspace.
- Open buffers after a restart (SR-115 AK4, `buffer-session.ts`): the buffers open when the window closed, or when the workspace was left for another, are display state like the elements opened last: kept per workspace in the app's local storage (`logreq.buffers.v1` with the name and repositories of the workspace, a literal like `logreq.recent.v1` and `logreq.usage.v1`, so a rename renames the three together), never in the workspace (SR-118 AK5) and through no catalog command (SR-080 AK1). Details: [lists, buffers and the views of an element](0010/views.md).
- "Open workspace" (SR-131, `workspaces.ts`): an action of the command prompt, no shortcut (File > Open Workspace and Ctrl/Cmd+O keep the native folder dialog). Details: [command prompt and minibuffer](0010/command-prompt.md).
- "Create element" (SR-064, `catalog-commands.ts`, `create-element.ts`): the catalog command `element.create` in the command prompt by its title, no action of its own; its key is Ctrl/Cmd+K E (below). Details: [command prompt and minibuffer](0010/command-prompt.md).
- Command prompt ranking (SR-108 AK3, SR-121 AK2, SR-133, `usage.ts`): what was chosen is display state of the app, like the elements opened last: kept in the app's local storage under `logreq.usage.v1`, not per workspace (the commands are the same in every workspace) and never in the workspace or through a catalog command (SR-080 AK1: "außer reiner Darstellung der App"). Details: [command prompt and minibuffer](0010/command-prompt.md).
- Minibuffer: the only control, apart from two exceptions: the copy symbols of the fields (SR-128, below; seen only on hover or focus) and the editor's transient `/` menu at the caret (SR-129, below; whether D-062 allows it is the spec question #453, until it is answered the menu only inserts formatting). Details: [command prompt and minibuffer](0010/command-prompt.md).
- Editor (SR-065, #77): CodeMirror 6 in live-preview mode (D-061) in the element buffer. Details: [editor, property boxes, title and copy](0010/editor.md).
- Property boxes (SR-104, SR-127, `TextBox.tsx`, `property-edit.ts`): every property that is set and not empty is a box below the text with its key and its values and nothing else (no form, no dialog, D-062); the targets of a property of kind `relation` (the outgoing relations with `property: true` of `element.get`) are a box with one link per target, and the relation groups keep only the relations of relation kinds and the incoming ones. Details: [editor, property boxes, title and copy](0010/editor.md).
- Title (#621, SR-104, SR-073 AK1; spec question #676, `TitleBox.tsx`, `title-box.ts`, `editor/single-line.ts`): the title is edited where it is shown, in the heading of the element, as one line of plain text (SR-127 AK5: no preview rule and no `[[` search), no box, label or input (D-062). Details: [editor, property boxes, title and copy](0010/editor.md).
- Elements with a value (SR-132, `value-list.ts`): from a value of the shown element, the list of every element of the workspace with that value, a list buffer with one filter step, the step "Filter list by property", "Filter list by status" or the overview's type line adds (SR-124, SR-118), so it narrows further like any list. Details: [lists, buffers and the views of an element](0010/views.md).
- Neighbourhood (SR-107): a buffer of its own, opened from an element with Ctrl/Cmd+J and left the same way. Details: [lists, buffers and the views of an element](0010/views.md).
- Traceability matrix (SR-125): a mode of the list buffer (`ListBuffer.matrix`, D-062), not a buffer of its own: Ctrl/Cmd+T ("Show traceability matrix") shows the list as a table and Ctrl/Cmd+T ("Show as list") brings the rows back, the selected row kept. Details: [lists, buffers and the views of an element](0010/views.md).
- Copy field (SR-128): every field of the element buffer (the title, the text, each property box, each group of relations) is a `div.field` with a copy symbol at its right edge, a button of 1.5rem that has no tab stop and keeps the focus where it is on a press (so the editor keeps its cursor). Details: [editor, property boxes, title and copy](0010/editor.md).
- Lists of the main window (SR-122 AK4, AK5, `keys.ts` `rowTarget`): the overview, a list (also filtered and as a tree), a search result, the matrix, the elements of a package page, the neighbourhood (tree and incoming groups), the result buffer of a catalog command (SR-073) and the metamodel as text (SR-130, which always has a row selected: the type selected in the graph). Details: [lists, buffers and the views of an element](0010/views.md).
- Split window (SR-115 AK3, `window-layout.ts`, `BufferArea.tsx`, actions "Split window", "Other window" and "Unsplit window"): commands of the prompt, no keys (#472), no catalog entry (pure display, ADR-0002 rule 3, like Follow agent). Details: [lists, buffers and the views of an element](0010/views.md).
- Next and previous buffer (SR-115 AK5, `opening-order.ts`, actions "Next buffer" and "Previous buffer"): Alt+N and Alt+P, Option+N and Option+P on macOS, show the buffer opened after or before the shown one, after the last the first. Details: [lists, buffers and the views of an element](0010/views.md).
- Package page (SR-112): an element whose type has the meaning `package` shows below its title, text, properties and relations the elements that name it (`element.list` with `where.package`, read-only like any list). Details: [lists, buffers and the views of an element](0010/views.md).
- Graph (SR-111, D-063): a buffer of its own. Details: [graph](0010/graph.md).
- Metamodel (SR-130, D-063): a buffer of its own, one per workspace (`MetamodelBuffer`). Details: [metamodel](0010/metamodel.md).
- Follow agent (SR-117, `follow.ts`, `use-follow.ts`): the mode „Agent folgen“ is display state of the renderer (ADR-0002 rule 3, SR-080 AK1): off at the start, never stored, switched only by the actions "Follow agent" and "Stop following agent" (one key, Ctrl/Cmd+Shift+O, with availability that excludes each other; in the command prompt too), never by a catalog command, an app argument or the bridge (AK4). Details: [lists, buffers and the views of an element](0010/views.md).
- All UI text is English, no i18n framework (D-019, SR-074).
- Light and dark (SR-113): colours are custom properties with `light-dark()`; `color-scheme` follows the OS (`prefers-color-scheme`, from `nativeTheme`) at start and while running. "Toggle dark mode" sets `data-theme` on the root for the running app only (nothing is stored, AK1); "Follow system light or dark mode" removes it. The window background at start follows `nativeTheme`. Nothing sets `themeSource` (no bridge function for it).
- Title bar (#490): on macOS the window has `titleBarStyle: "hiddenInset"`: the traffic lights lie on the sheet, and a strip of the sheet at its top (`.titlebar`, 38 px, the `--sheet` colour, so it follows the system and "Toggle dark mode" with the page) is the drag region (`-webkit-app-region: drag`) and shows the window title quietly centred; nothing in it is a control. The renderer shows the strip when `navigator.platform` is macOS, the same test as for the shortcut labels. Windows and Linux keep the native frame: a hidden title bar there needs `titleBarOverlay` colours that follow "Toggle dark mode", which only the renderer knows, so another bridge message from the renderer to main would be needed; the hidden frame also drops the menu bar (File > Open Workspace, shown with Alt) and would change every Electron test, which runs on Linux. Rejected for now; a native frame follows the OS's light or dark setting there.
- The modeline is one quiet rounded bar (#490): every part is a segment, the shown buffer and the workspace on the `--select` tone, the rest on `--raised`, the joints thin rounded edges in `--rule` (the layout of a powerline status line, without its colours, D-062). The candidates of a prompt are a card: `--raised`, a 1 px `--rule` edge, rounded corners and a soft shadow upwards, above the modeline.

## Consequences

- Renderer bugs cannot touch files or the network directly.
- The core process restarts independently if it crashes; the window shows a message and reloads the workspace. After more than 3 stops within 60 s it is not started again, and the window says so.

## Rejected

- Core in the main process: blocks the UI on long checks.
- Monaco: larger, more than a Markdown editor needs.
