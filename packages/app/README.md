# @logreq/app

The LogReq desktop app (ADR-0010). It is an Electron shell over the command catalog of `@logreq/core` (ADR-0002) and has no logic of its own. Every call of the renderer is one `invoke` in the core process, so the app gives the same results as CLI, API and MCP (SR-080).

```sh
pnpm build                                   # core and the other packages (tsc)
pnpm --filter @logreq/app electron:install   # downloads the Electron binary (pnpm runs no install scripts)
pnpm --filter @logreq/app build:electron     # electron-vite: out/main, out/preload, out/renderer
pnpm --filter @logreq/app start -- --workspace ../../fixtures/SR-004/one-repository
pnpm --filter @logreq/app start -- --workspace ../../spec   # the specification of LogReq itself
pnpm --filter @logreq/app test:electron      # install, build and the Playwright tests (Linux: under xvfb-run)
```

## Main view (SR-100)

A white sheet (D-062). The window shows one buffer at a time, the most recent one, above the modeline and the minibuffer; nothing else is permanently visible.

- **Start (SR-118):** the first buffer of a workspace is the overview, not the list of all elements. It has one line per element type with the number of its elements (`element.facets`, `types`: "System Requirement 117"), the types of the metamodel first, and below them the elements opened last, at most five, newest first, under a muted "Recent" (nothing of it before an element was opened). Enter or a click on a type line opens the list of the elements of exactly that type (`subtypes: false`, so the list is as long as the count says; it filters further like any list). The full list opens only on request: "List all elements" in the command prompt. Ctrl/Cmd+P works at once, with the overview as the only buffer. "Show overview" in the command prompt (offered when the overview is not shown) and closing the last buffer, also "Close all buffers", show it again; the lone overview cannot be closed. The counts are asked once per change of the workspace, not at every return to the overview. The recent elements are display state of the app, like the open buffers: only the UUID and the repository are kept, per workspace (its name and repositories), in the local storage of the app (Chromium, in the user data folder of the operating system), never in the files of the workspace (SR-118 AK5) and not through a catalog command (SR-080 AK1: "außer reiner Darstellung der App"). Each is read with `element.get` when the overview is shown; one that cannot be read is left out. The main process writes the storage to disk when the app quits.
- **Buffers:** the overview, the list of elements (`element.list`: filter, sort, derivation tree, pages of 200), a search result (`element.search`, pages of 50) and one element (`element.get`: title, the text in the Markdown editor, the properties that are set as boxes below the text and the relations by kind, with a mark for outdated ones; the text and the text properties are edited in place, see below). Opening a buffer again shows the one that is open. A **result** buffer shows the output of a catalog command that no other buffer shows (SR-073 AK2, run from the command prompt with #85), laid out by its shape alone (`result.ts`): an element is a row that Enter or a click opens, a problem or hint is one line with its element (Enter opens it), everything else is a quiet indented outline in greys, at most 2,000 lines; the modeline gives the `total` of the output. When the workspace changed, it asks the command again with the same input. It knows no command (ADR-0002).
- **Property boxes (SR-104, SR-127):** every property that is set and not empty is a box below the text: its key and its values, no label, input or button (D-062). The targets of a property of kind relation (such as the packages of a requirement) are a box too, one link per target (click or Enter opens it); the relation groups below the boxes keep the relations of relation kinds and the incoming ones. A property of a text kind (text, number, date; `metamodel.get`) is edited in its box: one editor with the values, one per line (a single value is the whole document). A click puts the caret in; Tab stops once per box (the box itself), and in a relation box once more on each target link, and Enter on it puts the caret at the end of the last value; Enter in a single value leaves the box, Enter in a list starts a new value at the caret (no key puts a line break inside a value); Escape leaves the box for the box itself, and Escape on the box for the element. Down on the last line of the text or of a box goes to the next box, Up on the first line to the one before (a wrapped line counts as lines; Ctrl+N / Ctrl+P on macOS do the same); on a box that has the focus itself, Down and Up move to the next and previous field. A property the metamodel marks `markdown` (in the standard model the acceptance criteria and the rationale) shows its values formatted like the text: bold, italic, code and references without their marks, and the Markdown source only on the line with the caret. Only inline syntax is Markdown in a value, and every line is a paragraph of its own, so a mark never pairs across two values; no image is drawn and there is no slash menu or `[[` search in a box yet (#78). A reference in a value opens its element on a click on its label and, with the caret on it or the focus on the box, with Ctrl/Cmd+Enter (the reference at the caret, else the first one of the box); an outdated one is marked like in the text. The value of a choice or relation property is set in the minibuffer (below), not typed. The title, a property the type does not know and a list with a value that holds a line break (hand-written file) are not edited in the box (the box says so on entering when it is the line break; a property the type does not know: spec question #469). "Copy field" copies what the editor of the box holds, the unsaved input included.
- **Choice and relation values, adding and clearing (SR-104):** Enter on the box of a choice property opens a prompt named after the property with only its choices (name, the key as hint; one that is set first, with the hint `set`): Enter takes it, it replaces the value of a single choice and toggles the values of a list, and typed text only narrows the choices, there is no free text. Enter on a relation box opens a prompt with the targets that are set (taking one removes it) and, for the typed text, the elements `element.search` finds among the target types of the property: taking one replaces the target of a single relation and is appended to a list. When the prompt ends, taken or escaped, the focus is on the box (not the element: an exception to the rule below). "Add property" (Ctrl/Cmd+Alt+A, macOS ⌥⌘A) asks which property the element lacks (by name; a property stored with an empty value is offered, the title is not) and puts an empty box at its place in the order of the type: a text kind has the caret in it, a choice or relation has the focus on the box and its prompt open at once. The empty box is no draft and goes away with the next save (or when the buffer is left) when nothing was put in it. "Clear property" (command prompt, no key) empties the box with the cursor or the one the cursor was in; text can be undone, and the property is removed from the file with the next "Save element" (SR-104 AK4). No key on a box that has the focus clears it.
- **Saving boxes:** "Save element" (Ctrl/Cmd+S) sends one `element.update` with the text when it changed and the boxes that changed (`set` and `unset`, built by `property-edit.ts`). A box goes in only when its document differs from the stored value, so every other property keeps its bytes (core writes a changed key in its fixed style, SR-102). Blank lines are dropped, every other line is kept as typed (no trimming); a box with nothing left is removed with `unset` (SR-104 AK4) and its box is gone after the save; a number property stores a decimal literal as a number and anything else as typed text. A refused update (`input.invalid`, `file.changed-on-disk`, ...) shows core's message in the minibuffer and keeps everything typed; a hint in the answer about a saved key is appended to "Saved ...". Unsaved boxes are part of the draft below.
- **Package page (SR-112):** an element whose type has the meaning `package` shows below its title, text, properties and relations the elements that name it (`element.list` with `where.package`). They sort and show as a tree with "Sort list" like any list. Down on the page goes into them, Escape and Up on the first row come back.
- **Neighbourhood (SR-107):** on an element, the parents stand in one line above the title (`trace.neighbourhood`, `up`, derivations, all levels): the titles from the top need down to the direct parents, each a link to the parent; the line is there only when the element has parents, a parent whose link from the element is outdated says so, and it wraps. Ctrl/Cmd+J (action "Show neighbourhood") opens the buffer "Neighbourhood: <ID> <title>": the parents line, the title, the children as an indented tree and below it the incoming relations and inline references grouped by kind ("← derives-from" is the tree itself; "← excludes", "← packages" for the members of a package, "← inline reference"), outdated ones marked. The tree is `trace.neighbourhood` with `meanings: ["derivation"]` from the element; Right opens the row (the app asks again from the same element with one more level), Left closes it or goes to the parent row. A child that appears under more than one parent is shown under each and marked "repeated" from the second time (it is a leaf there). The order of siblings is the command's walk order; the app sorts nothing. Ctrl/Cmd+J on the neighbourhood goes back to the element (action "Show element"). Need to requirements: Ctrl+P, the need's ID or title, Enter, Ctrl+J (SR-119 AK2).
- **Traceability matrix (SR-125):** Ctrl/Cmd+T on a list (action "Show traceability matrix") shows it as a matrix, Ctrl/Cmd+T again ("Show as list") as rows. The matrix is a mode of the list buffer, not a buffer of its own: there is one list buffer, so the matrix replaces the list in place, and "Filter list by ...", "Clear list filter" and "Sort list" keep the mode; the modeline says "matrix". On a package page the same shortcut opens its members as a matrix (all system requirements of a package: Ctrl+P, the package's ID or title, Enter, Ctrl+T; from the overview with a type line and "Filter list by property": about 15 keys). One row per element of the list, in the order of the list (`trace.matrix` with the list's selection and sort), one column per relation kind and direction that occurs ("Derives from", "Derived by", ...), each cell the elements at the other end ("<ID> <title>", one per line). A row without a relation of a column shows "—" in the accent colour (a gap); above each column stands "<count> · <share> %": how many rows of the whole selection have such a relation. An outdated relation says "outdated" and one to a target that is not there says "missing" (or its other state), as in the element. Up/Down select a row, Right/Left step through the row element and the relations of the row (the cursor is underlined), Enter or a click on a row element or a relation opens that element; an end that is not there opens nothing and the modeline says why. The columns, counts, gaps and marks are what `logreq trace matrix` gives for the same input (SR-080, SR-125 AK6). Not yet: an entry from a search result or the neighbourhood.
- **Modeline:** a display, not a control (the ID of an element has the copy symbol of a field, and a copy is confirmed here for 3 s, SR-128). Left the parts of the shown buffer (a list: its filter, sort and count; an element: one part with the ID, the type by its name in the metamodel and the status, then `read-only`, outdated relations, hints), right the workspace and its marks. Values are the commands' output as it is.
- **Minibuffer:** the only control. Idle it is one line with the last message. Asked, it has an input and the candidates rise above the modeline, only while asked.
- **Fuzzy matching:** names of actions and buffers are ranked with uFuzzy in the renderer (`intraMode: 0`, and one slip per word when that finds nothing). Elements are found by `element.search` in core.
- **Not shown unless asked:** UUID and version (action "Show element ID and version": the UUID and the date of the version, D-013, not the check value), empty properties, the shortcut of an action (only in the prompt).

**Catalog commands (SR-073 AK2, SR-108, #85, `catalog-commands.ts`):** the command prompt also lists the catalog's implemented read commands by their `title` ("Show relation options", "List hints", "Check workspace", ...); a command an action does is listed once, by the action ("List all elements", "Search elements", "Show neighbourhood", "Show traceability matrix", and "Go to element or buffer" for `element.get`). Write commands follow with PR 5b. Choosing one asks its arguments in the minibuffer one by one, in the order of the catalog's `arguments` ("Show relation options SR-1 · kind:"); each source's values come from one read command (`metamodel.get` for types and, without an element, relation kinds; `relation.options` for the kinds from an element; `workspace.status` for repositories; `element.search` for elements, the shown element, else the selected row of the shown list or search, first; the inline `enum` of the field; yes or no), and text, numbers and JSON are typed. The prompt of an argument opens at once with its label and fills its candidates when they arrive; Enter or Ctrl/Cmd+Enter pressed before acts on them then, and a source that fails says why in the label. A `selection` is the shown list's and never asked. Enter takes the candidate or the text and runs the command after the last required argument; Backspace in an empty input goes back one argument (before the first, to the command prompt); Escape ends it; Ctrl/Cmd+Enter takes the answer and then offers the optional arguments ("Run" first), and is remembered and waits for the hits of the typed text like Enter; a list field takes one value per Enter and Enter on an empty input ends it. The app checks nothing: an input core refuses with `input.invalid` asks the last argument again with core's message. The output opens a result buffer.

The command prompt orders its hits by the match first (SR-108 AK1: the beginnings of words, "crel" or "lae"; letters in order; one slip per word, "lsit") and marks the matched letters (AK2). Equally good hits go by use (AK3): the command chosen more often and more recently first, and an empty text lists the commands in use first. The command chosen last for exactly a typed text comes first when that text is typed again (SR-121 AK2). This is display state in the local storage of the app (`logreq.usage.v1`, `usage.ts`): command IDs, typed texts, counts and times, at most 500 of each, never in the workspace; a storage that fails gives the plain order. Only the command prompt records, not "Go to" nor argument steps.

## Editor (SR-065)

The text of an element is Markdown source with a live preview (D-061, `src/renderer/editor/`, CodeMirror 6): headings, emphasis (`*em*`, `**strong**`, `~~strike~~`, `` `code` ``), bullet, ordered and task lists, tables, fenced and indented code blocks, quotes and links appear set, and the source shows only on the lines the cursor touches while the editor has the focus. A table shows its source while the cursor is in any of its rows (spec question #420). There is no preview pane, no toolbar and no Markdown rewriting: the preview only decorates, and the file holds exactly what is in the editor (core adds the final line break, ADR-0004). Nothing in the text is interpreted as HTML. An inline reference (a `logreq:` link) opens its element on a click on its label (Ctrl/Cmd+click on a line that shows its source) and with Ctrl/Cmd+Enter when the cursor is on it (action "Follow reference"); an outdated one (a `relation.outdated` hint of `element.get`) is shown in the accent colour with the word "outdated". Other links are not followed, and a link in a table cell is not clickable yet.

- **Keys:** Enter on the element puts the cursor at the end of the text; Escape comes back to the element; Ctrl/Cmd+S saves with `element.update`; Ctrl/Cmd+Z and Ctrl/Cmd+Shift+Z undo and redo; Enter in a list continues it. After a prompt closes, the focus goes to the element (the article), not to the text, unless the action was "Edit text", or the prompt set the value of a property box or added a property: then it goes to that box.
- **Unsaved text and boxes** are a draft the app keeps per buffer while another buffer is shown (the modeline says `modified`). "Close buffer" asks once and discards when repeated. Opening another workspace drops all drafts. "Close all buffers" closes every buffer; with unsaved text it asks in the minibuffer (Enter keeps the buffers with unsaved text, the second choice discards it). A draft keeps the text, the boxes with changes (the keys of a choice, one line per target of a relation with its id, repository and label separated by tabs, and the boxes that were added, whose base is the empty document) and the file text and stored values they were typed on; autosave and the rule for a file that changed outside come with #401 and #402. Until then, when a buffer with a draft is shown and the file text differs from the one it was typed on, the minibuffer says that saving overwrites the file. A file changed outside the app is seen only then, after a write or after a restart of the core process.
- **Slash menu (SR-129)** (`slash-menu.ts`, `slash-entries.ts`): `/` typed at the start of a line or after white space, outside code, links and addresses, opens a menu at the caret with headings, normal text, lists, task list, quote, code block, table, link, reference to an element, image, math block, diagram, bold and italic (no underline: Markdown has none, D-015). More typing narrows it as the command line does (initials, letters in order, one slip); Down/Up, Tab and Ctrl+N/Ctrl+P choose, Enter takes the entry in one undo step, Escape closes the menu and the `/` stays as typed. "Reference to element" opens the prompt "Insert reference" (the search of "Go to") and writes `[title](logreq:<uuid>)`. The menu only edits the text; whether D-062 allows it is the spec question #453.
- **Extension points** (`editor/plugins.ts`) for the following issues: parser extensions and preview rules (formulas and diagrams #108, images #109) and further CodeMirror extensions (`[[` link search #78). Property boxes use the same plugins (`TextBox.tsx`, #400).

## Light and dark (SR-113)

The app follows the system's light or dark setting at start and while it runs (`prefers-color-scheme`, which Chromium takes from Electron's `nativeTheme`). Every colour is a token in `src/renderer/styles.css` with a light and a dark value (`light-dark()`), and `styles.test.ts` checks that the text reaches WCAG 2.2 AA in both and that no rule uses a colour of its own. The action "Toggle dark mode" (command prompt, no shortcut) switches to the other scheme at once, without a restart, by setting `data-theme` on the root element; "Follow system light or dark mode" (offered only after a choice) removes it. The choice lasts until the app quits and is stored nowhere, because every start follows the system (SR-113 AK1). The window background at start follows `nativeTheme`; the native title bar keeps the system's look. A new colour in a style rule or in the editor theme must be a token.

## Processes

- **Main** (`src/main/`, `out/main/index.js`) opens one window, the menu and the folder dialog. The menu is minimal: File > Open Workspace (Ctrl/Cmd+O), Quit (Close on macOS) and Edit. An unpackaged build adds Developer > Reload (F5) and Developer Tools (F12). Other keys stay free for the minibuffer and buffers. The menu bar hides until Alt on Windows and Linux. It also handles the protocols and the security settings. `--workspace <folder>` opens that folder at start.
- **Core process** (`src/core/`, `out/main/core.js`) is an Electron utility process (plain Node) with one workspace. That workspace is the root found upwards from the chosen folder, or else the folder itself. Its model cache lies in the cache folder of the copy, and the watcher and the load run as in `logreq serve api`. Opening another workspace stops the core process and starts a new one. Before it stops, it aborts running reads, lets running writes finish and closes its workspace; after 5 s it is killed. The app stops it the same way before it quits. A write command also runs to its end when its window goes away. If the workspace cannot be opened, the core process logs it and ends with exit code 1. A core process that stops by itself is started again; after more than 3 stops within 60 s it is not started again.
- **Renderer** (`src/renderer/`, React) is sandboxed and loaded from `app://logreq/index.html`. It reaches only `window.logreq`.

Main gives each page load a `MessagePort` to the core process (`logreq:workspace`, `src/shared/protocol.ts`). The renderer talks to the core process over that port directly.

## `window.logreq` (preload, `src/preload/bridge.ts`)

- `invoke(name, input = {})` resolves to `{ ok: true, output }` or `{ ok: false, error }`, where `error` is the error object of every access. It never rejects, because the context bridge would keep only an error's message. Without a workspace it gives `workspace.not-found`.
- `commands()` returns the catalog entries, each with `implemented`, as `GET /v1/commands` of the API does (for the command palette, SR-073 AK2).
- `copyText(text)` (SR-128) puts a text on the system clipboard and resolves `true`, or `false` when it could not; it never rejects. It sends the one message from the renderer to main (`logreq:copy`), which writes the clipboard only for a string of at most 16 Mi characters from the main frame of the LogReq window (`app://logreq`). It is a facility of the window like the theme, not a catalog command, and it reads nothing.
- `on("workspace-changed", listener)` returns the function that unsubscribes. The listener gets `{ reason }`:
  - `opened`: another workspace was opened.
  - `restarted`: the core process was started again.
  - `stopped`: the core process stopped and is not started again.
  - `written`: a write command of a window changed files.

  Files changed outside the app do not send the event yet; that needs a change event of core's watcher (#331).

The bridge offers nothing else, and in particular no delete (SR-099): `invoke` and `commands` are generic over the catalog, `on` is the one event, `copyText` the one facility of the window.

## Security (SR-077, SR-078)

- The renderer sends main exactly one message, `logreq:copy` (SR-128): main checks the sender (the main frame of the LogReq window on `app://logreq`) and the text (a string, at most 16 Mi characters) before it writes the clipboard, and never reads it.
- Windows use `contextIsolation`, `sandbox` and `app.enableSandbox()`. They have no `nodeIntegration` and no webview. The spell checker is off and its dictionary URL points at `app://logreq/no-dictionaries/`, which serves nothing.
- The content security policy is sent as a header with every page: `connect-src 'none'`, and only the app's own scripts.
- Navigation of any frame (`will-navigate`, `will-frame-navigate`), redirects, `window.open` and webviews are denied. Every permission request and device (HID, serial, USB, Bluetooth) is refused. The CSP has `frame-src 'none'`.
- `session.webRequest` cancels every request that is not `app:`, `logreq-file:` or `devtools:`, and logs only its origin to standard error.
- `logreq-file://workspace/<repository>/<path>` serves images (by extension) inside an available repository of the workspace. The repository is in the path, because Chromium turns hosts like `1.2` into IPv4 addresses. The path is checked first by its names alone (no `\`, `:` or NUL, and inside the repository folder), before any file system call: a UNC path or `/net/...` would otherwise open a network share. Only then are links resolved and checked again.
- There is no updater, no crash upload and no telemetry. Fuses and packaging belong to #324.

## Tests

- Unit tests (`src/**/*.test.ts`, Vitest) use fake Electron objects, a Node `MessageChannel` and happy-dom for React. They cover 100 % (ADR-0016).
- `test/app.spec.ts` (Playwright, `_electron.launch`) runs the built app on fixture workspaces:
  - it starts and shows the status;
  - `invoke` gives what the CLI gives (`[SR-080/AK2]`);
  - the bridge offers the catalog commands, the one event and `copyText`, and no delete (`[SR-099/AK1]`);
  - the renderer has no Node;
  - the session cancels a non-local request, and the app makes none itself (SR-078);
  - `logreq-file:` does not leave the repository;
  - navigation and new windows are denied;
  - a stopped core process is started again;
  - without a workspace, the app says how to open one.

  The JUnit file is `test-results/junit-electron.xml` (CI job `electron`, under `xvfb-run` on Linux).
- `test/main-view.spec.ts` runs the main view on `fixtures/SR-069/filter` and compares it with the CLI: the list, the tree, a filter, the search and an element (`[SR-100/AK1]` checks that nothing but the buffer, the modeline and the minibuffer is permanently visible; the SR is verified by inspection, `verification/SR-100.md`).
