# Minibuffer and command prompt

Part of the [`@reqseq/app` README](../README.md).

- **Minibuffer:** the only control. Idle it is one line with the last message. Asked, it has an input and the candidates rise above the modeline, only while asked; a long candidate wraps, the card never scrolls sideways (#293). When the card appears (hits or the next keys) it rises from the command line while the backdrop dims (`--dim`) and blurs in a seam as wide as its shadow, by one progress; new hits or a prompt that takes its place move nothing, and on close a copy (`.card-leaving`, no role, no `.candidates`) runs back, shorter. The knobs are the `--card-*` tokens in `styles.css`; without motion it stands at once (SR-182, `Card` in `Minibuffer.tsx`). By mouse (SR-202): a click anywhere on the idle line whose press began there, also where it shows no message, opens the command prompt as Ctrl/Cmd+Shift+P does (not a click on the card of the next keys); the wheel scrolls the card through every row, which no cap shortens; a press on a row takes it as Enter does.
- **Search (SR-183):** Ctrl/Cmd+Shift+F asks for a text and, while it is typed, shows the first hits of the search buffer for it: `element.search` with the same query, in its order, as many as fit the card at its size for commands (`CARD_LINES`; a hit with a snippet takes two lines, one without it one, `fittingRows` in `actions.ts`), each with its ID and title marked as core marks them, its status and the SR-174 snippet under it. No hit is chosen (`Prompt.preview`): Ctrl+N, Ctrl+P or the arrows choose one, Up from the first chooses none again, and Enter opens the chosen hit; Enter without one opens the search buffer at once, without waiting for the hits.
- **About ReqSeq (SR-161, `AboutWindow.tsx`, `about.ts`):** the catalog command `tool.info` ("About ReqSeq") shows its output not in a result buffer but in a window in the middle of the app, which D-062 allows as an exception: a card like the command line's (raised tone, thin edge, 8px corners, the same shadow) over a backdrop dimmed by `--about-dim` and blurred by `--about-blur` all over, both far more than behind the command line's card (AK6). The values stand as rows in groups (Version, Build, Runtime, Workspace, Licence, Documentation; a value core leaves out has no row; the licence notice is reflowed into paragraphs). Each row carries the copy symbol of a field (SR-128), seen on hover or focus, and copies only its value; with the focus on a row, Enter or Ctrl/Cmd+C (without a selected text) copies it too, Up, Down and Tab move the focus. "Copy all" or Ctrl/Cmd+Shift+C puts the whole content on the clipboard as one block, `label: value` under each group (AK3). The modeline confirms each copy. Escape or a click beside the card closes it; while it is open no shortcut of the app acts behind it.
- **Context menu (SR-194):** a right-click offers a fixed few entries of the command prompt for the place, with their names and keys, and "All commands…" to open it ([Context menu](context-menu.md)). A command run from the menu goes through the same step as one run from the prompt (`beforeCommand` in `App.tsx`).
- **Documentation (SR-141 AK2, AK3, `docs-help.ts`):** the action "Open documentation" (also without a workspace) and Help > ReqSeq Documentation open the start page of the bundled documentation in the default browser; F1 on an entry of the command prompt opens its page (`docsTopic`: a catalog command, or the command an action covers, by `covers` or the same title, opens its reference page; any other action its row on the page of keys, where every action has an anchor `action-<id>`, the keyless ones in the section "Actions without a key"), and the prompt stays open. The minibuffer says "Opened the documentation in the browser", or core's message when the delivery has no site. Main serves and opens it (README, Security).
- **Explanation line (SR-210 AK1, AK2, AK5, `withExplanations` and `argumentExplanation` in `catalog-commands.ts`, `CommandLine` and `ArgumentLine` in `Minibuffer.tsx`):** under the hits the card explains the marked entry when it runs a catalog command, its own entry or an action that covers it (`coveredCommand`: by `covers`, else by the same title): the catalog `summary` on one line, cut with "…", then the required arguments the prompt asks (`askedOf`), and the number and names of the optional ones with Ctrl/Cmd+Enter; names that do not fit end with "…" and the number stays; a command without arguments says so. It changes with the mark. Any other entry (an action alone, an element, a buffer) has none. While an argument is asked, the same place shows its name and its `description` in the catalog's input schema, and the keys of the step: Enter adds a value of a list, Enter on an empty input ends the values once one is given or skips an optional argument a write command asks, Ctrl/Cmd+Enter while optional arguments are left, Escape back. The texts come from the catalog as the core process lists it (`listing.ts`); the app only shows them.
- **Fuzzy matching:** names of actions and buffers are ranked with uFuzzy in the renderer (`intraMode: 0`, and one slip per word when that finds nothing). Elements are found by `element.search` in core.
- **Create element (SR-064):** "Create element" in the command prompt (the catalog command `element.create`; Ctrl/Cmd+K E) asks in the minibuffer the type (only the types that are not abstract), the title, and then each required property of the type in turn: a choice among its choices, a relation target found among its target types, a text typed; a list takes one value per Enter. An empty input skips a property, or ends a list; Backspace goes back one answer; Ctrl/Cmd+Enter offers `text`, `repository` and `folder` after the required properties. The element is created with the last answer and opens with its title, its text and a box for each property given, none for an empty one (D-062); the minibuffer says "Created <ID> <title> · <n> hints", the modeline counts the hints, and "Add property" offers the rest of the type's properties.
- **Open workspace (SR-131):** the action "Open workspace" (command prompt, no shortcut; File > Open Workspace and Ctrl/Cmd+O keep the folder dialog) asks in the minibuffer for one of the workspaces opened last, by their full path, the most recent first (at most 20), narrowed as typed like the command prompt; the open one is marked "open", one whose `reqseq-workspace.yaml` is gone "not found" (it stays in the list until newer ones push it out). Choosing another opens it in the same window in place of the open one (no new window, no restart): the buffers start again with its overview. Choosing one that is gone opens nothing and says the open workspace stays. A typed folder path (starting with `/`, `~`, `\` or a drive letter with `:` and a separator) is the first choice, "Open <path>": Enter opens the workspace found from that folder upwards (AK5), which is then first in the list; relative paths and, on Windows, UNC paths are refused, and a folder without a workspace opens nothing. Before every switch, also from File > Open Workspace, the unsaved input of every buffer is saved (AK3); input that cannot be saved keeps the open workspace, and the minibuffer names the element. The list is written by the core process into `<OS cache>/reqseq/recent-workspaces.json` (ADR-0008) whenever a workspace opens, also with `--workspace` and the dialog, and so outlives a restart. Without an open workspace the command prompt opens too and offers only this action and "Open documentation".
- **Path completion (SR-143, `path-completion.ts`):** while a path is typed, the entries of the folder up to its last separator (`/`, and `\` on Windows) are the candidates, narrowed by the name after it with the ranking of the command prompt on the NFC form of the names, folders and links (with a separator at the end, a link marked "link") before files, the matched letters marked; at most 200, then a row "… n more". Core lists them (`workspace.listFolder`: names that start with "." only when the typed name does, files only for a file argument); the window asks once per folder and dot rule while the prompt is open, so a letter only narrows. Choosing an entry puts the path up to it in the input, in the spelling on disk, and the prompt stays open (`Choice.complete`); the first row is the typed path itself, so Enter takes it. A folder that is missing, not readable (also no answer within 1 s) or no local path gives no entries and says so before the label ("<folder> is missing · …"). In "Open workspace" a text that starts with `/`, `~` or, on Windows, a drive letter lists the folders of its folder through main (`listFolder`) in place of the recent workspaces, after "Open <path>"; a `\` starts none (on Windows it names the current drive); `~` alone offers `~/`, a drive `C:` offers `C:\`. Every other path argument (`complete: folder|file`) is listed with `workspace.listFolder` relative from the workspace root, after "Use <path>", and `~` is the home folder there, as when the command runs (core's rule of the app).
**Catalog commands (SR-073 AK2, SR-108, ThomasBirkmaier/ReqSeq-archive#85, `catalog-commands.ts`):** the command prompt also lists the catalog's implemented read commands by their `title` ("Show relation options", "List hints", "Check workspace", ...); a command an action does is listed once, by the action ("List all elements", "Search elements", "Show neighbourhood", "Show traceability matrix", and "Go to element or buffer" for `element.get`). The write commands are listed too ("Create relation", "Remove relation", "Confirm hints", "Set status", "Supersede element", "Bulk update elements", "Save filter", "Initialise workspace", ...), except "Update element", which the element buffer does ("Save element"); while the workspace is read-only, none that core refuses then, and while a folder without a workspace is open only "Initialise workspace". A write command without a required argument asks its first one (Confirm hints: the element), and an optional argument whose `of` names a given field is asked after the required ones (the hints of the element, the value of a bulk update's property); Enter on an empty input skips it. A value of an argument takes the place of the fields it `replaces` in the input: hints chosen in Confirm hints confirm only those, not every hint of the element, target or kind given before (#291). Before a write command runs, the input of every open buffer is saved, the shown one last; one that cannot be saved stops it. Its output opens a result buffer that is never asked again (that would write again); "Bulk update elements" writes only with `confirm` yes (Ctrl/Cmd+Enter), else it shows what it would change. A confirmation writes only what an open preview of the same input said (#836, ADR-0002 rule 3): it passes the `plan` of that preview; without one it opens the preview and writes nothing, and when the change is no longer the previewed one (`plan-changed`) it says so and opens the new preview. Choosing one asks its arguments in the minibuffer one by one, in the order of the catalog's `arguments` ("Show relation options SR-1 · kind:"); each source's values come from one read command (`metamodel.get` for types and, without an element, relation kinds; `relation.options` for the kinds from an element; `workspace.status` for repositories; `element.search` for elements, the shown element, else the selected row of the shown list or search, first; `baseline.list` for baselines, by name, by file name where two share a name; the `enum` of the field, which the core process puts inline where the catalog names it by a `$ref` (`listing.ts`: the problem codes of List hints and Confirm hints, #1575); yes or no; SR-108 AK4: the statuses of the element's type, the properties of its type or of the metamodel without the title, a property's choices or the elements of its target types, the targets of a kind among its target types, an element's outgoing relations and its confirmable hints (each by its target, then its message, #293), as ADR-0010 lists them), a `view` the core and the variants of the workspace as "Choose view" offers them (#285; a read with a `view` or a selection whose `view` is skipped runs in the view the window shows, so all elements need "Choose view" → "All elements" first), paths are typed with completion (above), and text, numbers and JSON are typed. The prompt of an argument opens at once with its label and fills its candidates when they arrive; Enter or Ctrl/Cmd+Enter pressed before acts on them then, and a source that fails says why in the label. A `selection` is the shown list's (on the list of all elements outside a view, every element: the empty selection for a command that requires one, "Bulk update elements" and "Create baseline", #856), or on a package page its package (`selection.package`, for every command with a selection, reads and writes alike: "Create baseline" there asks only the name, SR-050 AK1), and never asked; a command that requires one is offered only there. Enter takes the candidate or the text and runs the command after the last required argument; Backspace in an empty input and Escape go back one argument (before the first, to the command prompt, SR-134 AK1); Ctrl/Cmd+Enter takes the answer and then offers the optional arguments ("Run" first), and is remembered and waits for the hits of the typed text like Enter; a list field takes one value per Enter and Enter on an empty input ends it. The app checks nothing: an input core refuses with `input.invalid` asks again, with core's message, the value core names (the field of the first schema violation, else the property in `key`), in its place; the values read from it are dropped and asked or offered again, the others stay; a refusal that names nothing asked asks the value given last. The output opens a result buffer. An item of a list whose `id` is an element of `names` is that element's row with its other fields indented under it, as the CLI gives it: an entry of "Show baseline" (`baseline.get`) is its element with its state (changed, superseded, removed, added, missing, inaccessible), its version in the baseline with that version's date, and with `withEvidence` (Ctrl/Cmd+Enter, then withEvidence yes) a verification row per view with the records dated after the baseline and the validation status (SR-051, SR-094); "Compare baseline" gives both commits and the Git command (SR-051 AK4). There the share of a verification degree (`evidence.degree`, SR-037) is a percentage by core's rule of every access (`@reqseq/core/verification-degree`: one decimal, rounded down).

The command prompt orders its hits by the match first (SR-108 AK1: the beginnings of words, "crel" or "lae"; letters in order; one slip per word, "lsit") and marks the matched letters (AK2). Equally good hits go first by fit to the shown view (SR-133 AK2), then by use (SR-108 AK3): the command chosen more often and more recently first. An empty text lists the commands that fit the view first (SR-133 AK1): every action shown (an action is shown only where it applies) and each catalog command whose argument the view gives (a list its selection, an element or a neighbourhood its element to a required element argument); the others follow below, each group in the order of use, and stay reachable by search. The command chosen last for exactly a typed text comes first when that text is typed again (SR-121 AK2). This is display state in the local storage of the app (`reqseq.usage.v1`, `usage.ts`): command IDs, typed texts, counts and times, at most 500 of each, never in the workspace; a storage that fails gives the plain order. Only the command prompt records, not "Go to" nor argument steps.

**Waiting Enter (#467):** while an Enter or Ctrl/Cmd+Enter waits for the hits of the typed text (SR-119) or for the parts of the prompt, the minibuffer shows "searching…" after the input; typing cancels the Enter, and the mark goes.
