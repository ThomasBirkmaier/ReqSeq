# Minibuffer and command prompt

Part of the [`@reqseq/app` README](../README.md).

- **Minibuffer:** the only control. Idle it is one line with the last message. Asked, it has an input and the candidates rise above the modeline, only while asked.
- **Fuzzy matching:** names of actions and buffers are ranked with uFuzzy in the renderer (`intraMode: 0`, and one slip per word when that finds nothing). Elements are found by `element.search` in core.
- **Create element (SR-064):** "Create element" in the command prompt (the catalog command `element.create`; Ctrl/Cmd+K E) asks in the minibuffer the type (only the types that are not abstract), the title, and then each required property of the type in turn: a choice among its choices, a relation target found among its target types, a text typed; a list takes one value per Enter. An empty input skips a property, or ends a list; Backspace goes back one answer; Ctrl/Cmd+Enter offers `text`, `repository` and `folder` after the required properties. The element is created with the last answer and opens with its title, its text and a box for each property given, none for an empty one (D-062); the minibuffer says "Created <ID> <title> · <n> hints", the modeline counts the hints, and "Add property" offers the rest of the type's properties.
- **Open workspace (SR-131):** the action "Open workspace" (command prompt, no shortcut; File > Open Workspace and Ctrl/Cmd+O keep the folder dialog) asks in the minibuffer for one of the workspaces opened last, by their full path, the most recent first (at most 20), narrowed as typed like the command prompt; the open one is marked "open", one whose `reqseq-workspace.yaml` is gone "not found" (it stays in the list until newer ones push it out). Choosing another opens it in the same window in place of the open one (no new window, no restart): the buffers start again with its overview. Choosing one that is gone opens nothing and says the open workspace stays. A typed folder path (starting with `/`, `~`, `\` or a drive letter with `:` and a separator) is the first choice, "Open <path>": Enter opens the workspace found from that folder upwards (AK5), which is then first in the list; relative paths and, on Windows, UNC paths are refused, and a folder without a workspace opens nothing. Before every switch, also from File > Open Workspace, the unsaved input of every buffer is saved (AK3); input that cannot be saved keeps the open workspace, and the minibuffer names the element. The list is written by the core process into `<OS cache>/reqseq/recent-workspaces.json` (ADR-0008) whenever a workspace opens, also with `--workspace` and the dialog, and so outlives a restart. Without an open workspace the command prompt opens too and offers only this action.
**Catalog commands (SR-073 AK2, SR-108, #85, `catalog-commands.ts`):** the command prompt also lists the catalog's implemented read commands by their `title` ("Show relation options", "List hints", "Check workspace", ...); a command an action does is listed once, by the action ("List all elements", "Search elements", "Show neighbourhood", "Show traceability matrix", and "Go to element or buffer" for `element.get`). The write commands are listed too ("Create relation", "Remove relation", "Confirm hints", "Set status", "Supersede element", "Bulk update elements", "Save filter", "Initialise workspace", ...), except "Update element", which the element buffer does ("Save element"); while the workspace is read-only, none that core refuses then, and while a folder without a workspace is open only "Initialise workspace". A write command without a required argument asks its first one (Confirm hints: the element), and an optional argument whose `of` names a given field is asked after the required ones (the hints of the element, the value of a bulk update's property); Enter on an empty input skips it. Before a write command runs, the input of every open buffer is saved, the shown one last; one that cannot be saved stops it. Its output opens a result buffer that is never asked again (that would write again); "Bulk update elements" writes only with `confirm` yes (Ctrl/Cmd+Enter), else it shows what it would change. Choosing one asks its arguments in the minibuffer one by one, in the order of the catalog's `arguments` ("Show relation options SR-1 · kind:"); each source's values come from one read command (`metamodel.get` for types and, without an element, relation kinds; `relation.options` for the kinds from an element; `workspace.status` for repositories; `element.search` for elements, the shown element, else the selected row of the shown list or search, first; the inline `enum` of the field; yes or no; SR-108 AK4: the statuses of the element's type, the properties of its type or of the metamodel without the title, a property's choices or the elements of its target types, the targets of a kind among its target types, an element's outgoing relations and its confirmable hints, as ADR-0010 lists them), a `view` the core and the variants of the workspace as "Choose view" offers them (#285), and text, numbers and JSON are typed. The prompt of an argument opens at once with its label and fills its candidates when they arrive; Enter or Ctrl/Cmd+Enter pressed before acts on them then, and a source that fails says why in the label. A `selection` is the shown list's and never asked. Enter takes the candidate or the text and runs the command after the last required argument; Backspace in an empty input goes back one argument (before the first, to the command prompt); Escape ends it; Ctrl/Cmd+Enter takes the answer and then offers the optional arguments ("Run" first), and is remembered and waits for the hits of the typed text like Enter; a list field takes one value per Enter and Enter on an empty input ends it. The app checks nothing: an input core refuses with `input.invalid` asks again, with core's message, the value core names (the field of the first schema violation, else the property in `key`), in its place; the values read from it are dropped and asked or offered again, the others stay; a refusal that names nothing asked asks the value given last. The output opens a result buffer. There the share of a verification degree (`evidence.degree`, SR-037) is a percentage by core's rule of every access (`@reqseq/core/verification-degree`: one decimal, rounded down).

The command prompt orders its hits by the match first (SR-108 AK1: the beginnings of words, "crel" or "lae"; letters in order; one slip per word, "lsit") and marks the matched letters (AK2). Equally good hits go first by fit to the shown view (SR-133 AK2), then by use (SR-108 AK3): the command chosen more often and more recently first. An empty text lists the commands that fit the view first (SR-133 AK1): every action shown (an action is shown only where it applies) and each catalog command whose argument the view gives (a list its selection, an element or a neighbourhood its element to a required element argument); the others follow below, each group in the order of use, and stay reachable by search. The command chosen last for exactly a typed text comes first when that text is typed again (SR-121 AK2). This is display state in the local storage of the app (`reqseq.usage.v1`, `usage.ts`): command IDs, typed texts, counts and times, at most 500 of each, never in the workspace; a storage that fails gives the plain order. Only the command prompt records, not "Go to" nor argument steps.
