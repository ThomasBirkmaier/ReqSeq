# Property boxes and title

Part of the [`@reqseq/app` README](../README.md).

- **Property boxes (SR-104, SR-127):** every property that is set and not empty is a box below the text: its key and its values, no label, input or button (D-062). The targets of a property of kind relation (such as the packages of a requirement) are a box too, one link per target (a click or Enter without Ctrl, Cmd or Alt opens it; Ctrl/Cmd+Enter opens it through "Follow reference", Ctrl/Cmd+Shift+Enter lists its elements, SR-132; Alt+Enter and, on macOS, the physical Ctrl+Enter do nothing on it); the relation groups below the boxes keep the relations of relation kinds and the incoming ones. A property of a text kind (text, number, date; `metamodel.get`) is edited in its box: one editor with the values, one per line (a single value is the whole document). A click puts the caret in; Tab stops once per box (the box itself), and in a relation box once more on each target link, and Enter on it puts the caret at the end of the last value; Enter in a single value leaves the box, Enter in a list starts a new value at the caret (no key puts a line break inside a value); Escape leaves the box for the box itself, and Escape on the box for the element. Down on the last line of the text or of a box goes to the next box, Up on the first line to the one before (a wrapped line counts as lines; Ctrl+N / Ctrl+P on macOS do the same); on a box that has the focus itself, Down and Up move to the next and previous field. A property the metamodel marks `markdown` (in the standard model the acceptance criteria and the rationale) shows its values formatted like the text: bold, italic, code and references without their marks, and the Markdown source only on the line with the caret. Only inline syntax is Markdown in a value, and every line is a paragraph of its own, so a mark never pairs across two values; no image is drawn and there is no slash menu; `[[` asks for an element as in the text and writes the reference into that value (SR-127 AK2), in an editable box only. A reference in a value opens its element on a click on its label and, with the caret on it or the focus on the box, with Ctrl/Cmd+Enter (the reference at the caret, else the first one of the box); an outdated one is marked like in the text. The value of a choice or relation property is set in the minibuffer (below), not typed. The title, a property the type does not know and a list with a value that holds a line break (hand-written file) are not edited in the box (the box says so on entering when it is the line break; a property the type does not know: spec question #469). "Copy field" copies what the editor of the box holds, the unsaved input included.
- **Choice and relation values, adding and clearing (SR-104):** Enter on the box of a choice property opens a prompt named after the property with only its choices (name, the key as hint; one that is set first, with the hint `set`): Enter takes it, it replaces the value of a single choice and toggles the values of a list, and typed text only narrows the choices, there is no free text. Enter on a relation box opens a prompt with the targets that are set (taking one removes it) and, for the typed text, the elements `element.search` finds among the target types of the property: taking one replaces the target of a single relation and is appended to a list. When the prompt ends, taken or escaped, the focus is on the box (not the element: an exception to the rule below). "Add property" (Ctrl/Cmd+Alt+A, macOS ⌥⌘A) asks which property the element lacks (by name; a property stored with an empty value is offered, the title is not) and puts an empty box at its place in the order of the type: a text kind has the caret in it, a choice or relation has the focus on the box and its prompt open at once. The empty box is no draft and goes away with the next save (or when the buffer is left) when nothing was put in it. "Clear property" (command prompt, no key) empties the box with the cursor or the one the cursor was in; text can be undone, and the property is removed from the file with the next save (SR-104 AK4). No key on a box that has the focus clears it.
- **Saving boxes:** a save (autosave, below, or "Save element", Ctrl/Cmd+S) sends one `element.update` with the text when it changed and the boxes that changed (`set` and `unset`, built by `property-edit.ts`). A box goes in only when its document differs from the stored value, so every other property keeps its bytes (core writes a changed key in its fixed style, SR-102). Blank lines are dropped, every other line is kept as typed (no trimming); a box with nothing left is removed with `unset` (SR-104 AK4) and its box is gone after the save; a number property stores a decimal literal as a number and anything else as typed text. Every save sends the `fileSha256` of the file the buffer shows as `expectedFileSha256`, so core writes nothing over a file that changed since (SR-106, below). A refused update (`input.invalid`, ...) shows core's message in the minibuffer and keeps everything typed; a hint in the answer about a saved key is appended to "Saved ...". Unsaved boxes are part of the draft below.
- **Title (#621, SR-104, SR-073 AK1):** the title is edited in the heading, as one line of plain text (spec question #676; no `[[` search, SR-127 AK5). Enter on the field of the title, a click on the heading (the caret where it was clicked), "Edit title" in the command prompt or Up at the first line of the text puts the editor into the same heading without moving the page (`TitleBox.tsx`); Enter, Shift+Enter and Escape go back to the field, Down goes to the text, a pasted line break becomes one space (`editor/single-line.ts`). It is saved with the text and the boxes as `title` of `element.update`, part of the draft, undone with Ctrl/Cmd+Z and resolved like a box when the file changed under the input. An emptied title is saved as `title: ""` with the hint of core in "Saved ..."; the heading then shows the short ID, muted. A title with a line break, a locked or deleted element and a type without a title property cannot be edited.
