# Keys

Part of the [`@reqseq/app` README](../README.md).

The user documentation lists these keys on its generated page "Keyboard shortcuts" (SR-139 AK5), from `shortcutReference` (`shortcut-reference.ts`): the actions' shortcuts (`actions.ts`), the letters after the prefix (`bindings.ts`), and the tables next to the handlers that have no action, `PROMPT_KEYS` (`prompt-keys.ts`), `LIST_KEYS` and `HISTORY_KEYS` (`keys.ts`), `GRAPH_KEYS` (`graph-nav.ts`), `FIELD_KEYS`, `PACKAGE_KEYS` (with `leavesPart` of `keys.ts`), `LEAVE_KEYS` and `ELEMENT_MORE_KEYS` (`element-keys.ts`; the block "On disk" through `onDiskKey`), `BOX_KEYS`, `EDITOR_KEYS`, `MARKDOWN_KEYS` and `TABLE_KEYS` (`editor/editor-keys.ts`; the slash menu and `boxNavigation` build their keymaps from `SLASH_NEXT`, `SLASH_PREVIOUS`, `BOX_NEXT` and `BOX_PREVIOUS`), `GRAPH_MORE_KEYS` (`graph-nav.ts`, the depth keys `DEPTH_MORE` and `DEPTH_LESS`), `MENU_KEYS` (`shared/menu-keys.ts`, whose Open Workspace item and File role the menu reads) and `PREFIX_KEYS` (`bindings.ts`). CodeMirror's own text editing keys are not listed one by one. A new key of a handler goes into its table, whose test ties it to the handler.

| Keys (Ctrl, or Cmd on macOS; on macOS the physical Ctrl key with a letter is never one of these shortcuts: it stays the editor's and the lists' key, so Ctrl+P there moves the caret or the selection and never jumps) | |
| --- | --- |
| Ctrl/Cmd+Shift+P | Command prompt: the app's actions that apply to the shown buffer (filter, sort, close, ...); without a workspace only "Open workspace" and "Open documentation" |
| F1 | In the command prompt: the documentation of the chosen entry in the default browser (SR-141 AK3, `HELP_KEY` of `prompt-keys.ts`): a catalog command's reference page, an action's covered command's page, or the action's row on the page of keys (anchor `action-<id>`; every action has one, a keyless one in its last section "Actions without a key"); with no entry chosen the start page. The prompt stays open. Help > ReqSeq Documentation has no key |
| Ctrl/Cmd+P | Go to an open buffer (the most recent first, so Enter goes back) or to an element (SR-115 AK1): after the open buffers the elements shown last that are no longer open, newest first (the recent elements of the overview, with the names the overview read or they were shown with; the prompt asks core nothing when it opens, so the search of the typed text is not queued behind reads; one that a read finds gone, in the overview or in its buffer, is left out until the overview reads it again, ThomasBirkmaier/ReqSeq-archive#681), then the hits of `element.search` for the typed text; a hit whose whole title is the typed text (ignoring case and spaces) comes first, before an open or recent buffer that only contains it (#195). Enter typed before the hits of the text have arrived waits for them and opens the first one (SR-119 AK1: Ctrl+P, text, Enter). The physical Ctrl+P in a list with a selected row moves the selection instead, on every platform (SR-122 AK5); with no row selected it jumps on Linux and Windows. On macOS only Cmd+P jumps, always; the physical Ctrl+P never does (product owner decision, 2026-10-27, ThomasBirkmaier/ReqSeq-archive#543). "Go to element or buffer" in the command prompt always jumps |
| Ctrl/Cmd+Shift+F | Search elements |
| Ctrl/Cmd+K, then a letter (macOS ⌘K) | The prefix key (SR-109 AK3, SR-121 AK3; the assumption of ThomasBirkmaier/ReqSeq-archive#472, `bindings.ts`): E "Create element", R "Create relation", T "Set status", H "Confirm hints", L "List all elements", O "Show overview", F "Filter list by type", S "Sort list", B "Close buffer", where the command applies (the four write commands not in a read-only workspace); the letter bare or with Ctrl/Cmd held. After half a second without a key the minibuffer shows the possible next keys with their commands; Ctrl+N/Ctrl+P (the physical Ctrl, also on macOS) and Down/Up show them at once and move a selection through them, Enter runs the selected one (SR-122 AK6, SR-145 AK3); Escape ends it. The command prompt shows the key next to the command („Ctrl+K L“). The letter never reaches the text or a box. Not while a prompt is open |
| Ctrl/Cmd+Shift+G | On an element or its neighbourhood: its graph (SR-111); on the graph: back to the element |
| Up, Down, Left, Right, Page Up, Page Down, Home, Enter, `+`, `-` (graph) | Follow a link up or down, go through a layer, from layer to layer, to the element; open the selected box as the current element; one level more or less |
| Up, Down, Left, Right, Page Up, Page Down, Home (metamodel) | Follow a curve up or down, go through a layer, from layer to layer, to the first type |
| Ctrl/Cmd+Shift+O | Follow agent: show the element an agent read or changed last through the API or MCP (SR-117); again: stop following |
| Ctrl/Cmd+J | On an element: its neighbourhood (SR-107); on the neighbourhood: back to the element |
| Ctrl/Cmd+T | On a list: show it as a traceability matrix (SR-125); on the matrix: back to the list; on a package page: its members as a matrix; on the metamodel: graph and text (SR-130), the selected type kept. On macOS only Cmd+T; the physical Ctrl+T stays CodeMirror's "transpose" in the text editor |
| Right, Left (matrix) | Step through the row element and the relations of the selected row; Enter or a click opens the element there |
| Enter, Tab, Right, Left (folded section row) | Open or close the folded statuses at the end of a list (SR-201): Enter and Tab toggle, Right opens, Left closes |
| Right, Left | In the neighbourhood: open the tree row (shows its children), close it or go to the parent row |
| Up, Down, Page Up, Page Down, Home, End | Select a row (on a package page, Down on the page enters its elements). A fresh list has no row selected: the first Down selects the first row, and Enter opens the first row |
| Enter | Open the selected row (in a prompt: run the candidate; on an entry of a path, put the path up to it in the input and keep the prompt open, SR-143 AK1; on the first row "Use <path>" or "Open <path>", take the typed path) |
| Escape | In a later step of a command (an argument, the value after the property of a filter, the question an action asks after it was chosen in the command prompt): back one step, the prompt stays open and nothing runs (SR-134 AK1, `steppedContext` in `actions.ts`); in the first step, end the prompt (AK2), and also in "Find in element" and "Replace … with" (SR-189). A press of the left, middle or right mouse button outside the minibuffer and its card ends it too, and acts on what it presses (the prompt is no dialog, D-062) |
| Tab | In a prompt, the next candidate |
| Ctrl+N / Ctrl+P (the Ctrl key, also on macOS) | In an open prompt: the next / previous hit, like Down / Up (SR-122). The prompt takes these keys: Ctrl+P is not "Go to" while a prompt is open. In a list of the main window (overview, list, search result, matrix, package page, neighbourhood, result of a command): the next / previous row, like Down / Up; with no row selected Ctrl+N selects the first row and Ctrl+P is still "Go to" on Linux and Windows (on macOS it does nothing there). On any other element Ctrl+N goes to its first field, like Down (SR-155). On a field, in the title, the text or a box they act as Down / Up on every platform: to the next / previous field, from the last field of a package page into its elements, and in an editor through its lines first (SR-155 AK4); Ctrl+P there only moves and is never "Go to". On a package page Ctrl+N enters its elements at the first one (Down enters at the row used last), and Ctrl+P on the first one goes back to the page. Cmd+N / Cmd+P do not move a selection |
| Alt+N / Alt+P (macOS ⌥N / ⌥P) | Forward / back through the buffers in the order they were shown last, like back and forward: Alt+P shows the buffer shown before, each further Alt+P the one before it, Alt+N goes forward again; switching with these keys keeps the order, and at the ends it wraps (actions "Next buffer" and "Previous buffer", SR-115 AK5). Also while typing in the text editor or a property box: the key types nothing there, so on a German Mac "~" (⌥N) is typed with the slash menu or pasted. In an open prompt the keys are the prompt's and type what the layout gives. With one buffer open the app does not take them: they switch nothing, and in the text editor on macOS they type what the layout gives (⌥N "~" on a German Mac) |
| Right mouse button (macOS also Ctrl+click), Menu key, Shift+F10 | The context menu of the place (D-075, SR-194, [Context menu](context-menu.md)): Up/Down or Ctrl+P/N, Home/End select an entry, Enter or Space runs it, Escape closes it; any other key closes it and acts as without it |
| Mouse buttons Back / Forward | The same as Alt+P / Alt+N, on the release of the button, also in the text editor; not while a prompt is open, and the window never goes back in its history (SR-163) |
| macOS ⌘[ / ⌘] | The same as the mouse buttons Back / Forward, by the character (German layout ⌘⌥5 / ⌘⌥6) or the physical key (German layout ⌘ü / ⌘+; on other layouts the key in that place), because mouse software such as Logi Options+ sends the side buttons as these keys; not while a prompt is open (SR-163 AK3) |
| Alt+O (macOS ⌥O) | The other area of a split window (action "Other window", SR-150 AK7), also while typing in the text editor; in an open prompt it types what the layout gives. Without a split the app does not take it, so the layout types what it gives (⌥O "ø" on a German Mac). Not Ctrl/Cmd+O, which opens a workspace, and not the physical Ctrl+O on macOS, which belongs to the editor |
| Ctrl/Cmd+S | Save the text and the property boxes of the shown element now (action "Save element"; they are also saved one second after the last input and when the buffer is left, SR-105) |
| Ctrl/Cmd+Alt+A (macOS ⌥⌘A) | On an element, add a property it lacks (action "Add property", SR-104). Not Cmd+Shift+A: with text selected, macOS gives it to the service "Search man Page Index in Terminal". On Windows, Ctrl+Alt is AltGr: where AltGr+A types a letter (Polish ą), the letter wins and "Add property" is in the command prompt |
| Enter | On an element, put the cursor into the text (action "Edit text"; pressed while the element loads, once its text is shown); on a property box that has the focus, put it into the box, and on the box of a choice or relation property open the prompt for its value; on the field of the title, put the caret at the end of the title (action "Edit title"; a title that cannot be edited goes to the text); in the title, back to its field |
| Up, Down (also Ctrl+P, Ctrl+N) | In the text and in a property box at the first and last line: to the box before and after, from the last line of the last one into the elements of a package page (SR-155 AK4) (from the first line of the text up into the title, or onto its field when it cannot be edited; from the title down into the text); on a field that has the focus: to the field before and after; Down on the element itself: to its first field (SR-155), on a package page into its elements |
| Ctrl/Cmd+Enter | On an element, open the element of the inline reference at the cursor, or the first reference of the Markdown property box that has the focus; in a box, the reference at the caret; on a focused target link of a relation box or group, that target (action "Follow reference") |
| Ctrl/Cmd+Shift+Enter | On an element, the list of the elements with the value at the cursor, or the prompt "Elements with" among its values (action "List elements with this value", SR-132). On macOS only Cmd+Shift+Enter |
| Ctrl/Cmd+click on a value | On an element, the list of the elements with the value clicked in a property box (SR-132, #235). On macOS only Cmd+click |
| Ctrl/Cmd+Shift+C | On an element, copy the field with the cursor, else the ID, as text, one value per line (action "Copy field", SR-128). Every field also has a copy symbol at its right edge, seen on hover or focus; the field with the focus has the grey of a selected list row, and Up and Down move it with its symbol (SR-155) |
| Escape | In the text, back to the element; in a property box, back to the box, and from the box to the element; in the title, back to its field |
| Ctrl/Cmd+B, Ctrl/Cmd+I | In the text and in a Markdown property box: bold or italic for the selection or the word at the caret, again to take it off (actions "Bold", "Italic", SR-186); on an element outside an editor, the same in the text. On macOS only Cmd: the physical Ctrl+B stays the editor's Emacs key |
| Ctrl/Cmd+F | On an element: "Find in element" (SR-189); in its prompt Enter and Shift+Enter go to the next and the previous hit, Escape ends it at the hit. On macOS only Cmd: the physical Ctrl+F stays the editor's Emacs key |
| `/` | In the text, at the start of a line or after a space: the slash menu (SR-129) with the Markdown elements at the caret |
| (slash menu open) Down, Up, Tab, Ctrl+N / Ctrl+P, Enter, Escape | Choose, take the entry (one undo step), close the menu and leave the `/` as typed |
| `[[` | In the text and in a Markdown property box, outside code, links and addresses: the prompt "Insert reference" (SR-066); the pick replaces the `[[` with the reference, Escape leaves the `[[` as typed |
