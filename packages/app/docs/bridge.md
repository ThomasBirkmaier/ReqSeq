# `window.logreq` (preload, `src/preload/bridge.ts`)

Part of the [`@logreq/app` README](../README.md).

- `invoke(name, input = {})` resolves to `{ ok: true, output }` or `{ ok: false, error }`, where `error` is the error object of every access. It never rejects, because the context bridge would keep only an error's message. Without a workspace it gives `workspace.not-found`.
- `commands()` returns the catalog entries, each with `implemented`, as `GET /v1/commands` of the API does (for the command palette, SR-073 AK2).
- `copyText(text)` (SR-128) puts a text on the system clipboard and resolves `true`, or `false` when it could not; it never rejects. It asks main over `logreq:copy`, which writes the clipboard only for a string of at most 16 Mi characters from the main frame of the LogReq window (`app://logreq`, `src/main/sender.ts`). It is a facility of the window like the theme, not a catalog command, and it reads nothing.
- `recentWorkspaces()` (SR-131) resolves the workspaces opened last, the most recent first, each `{ root, state }` with `state` `open`, `found` or `missing`; `openWorkspace(root)` opens a root of that list in the window in place of the open workspace, `openWorkspace(path, { typed: true })` the workspace found from a typed folder upwards, and resolves `{ ok: true }` or `{ ok: false, reason: "missing" | "refused" | "unsaved" | "timeout" | "busy" | "no-workspace" }` (`timeout`: the window did not answer main's request to save within 30 s; `busy`: another switch is running, main runs one at a time). Neither rejects, and an answer of another shape is an empty list or a refusal. `onSave(save)` sets the function that saves the window's unsaved input when main asks before a switch (SR-131 AK3) or before the window closes (`save({ closing: true })`, SR-105 AK1); it answers `true` when all is saved. A draft is dropped only when it is still the one that was saved. Until the other workspace has loaded and the old buffers are gone the window takes no input and says "Opening another workspace…". Both ask main (`logreq:recent-workspaces`, `logreq:open-workspace`), because no core process, and so no port, exists while no workspace is open.
- `on(event, listener)` returns the function that unsubscribes; a name that is not an event subscribes nothing. The events share one channel (`BridgeEvents` in `src/shared/protocol.ts`); the bridge checks the data of each as its schema does and passes on only those fields.
  - `workspace-changed`: the listener gets `{ reason }`:
    - `opened`: another workspace was opened.
    - `restarted`: the core process was started again.
    - `stopped`: the core process stopped and is not started again.
    - `written`: a write command of a window changed files.
    - `external`: files changed outside the app (CLI, API, MCP, another editor, Git; SR-116, SR-106). It is a batch of core's watcher (#331), which never reports the app's own writes, with `scope` (`elements`, `metamodel` or `workspace`) and `elements: { added, changed, removed }` (UUIDs). More than 1,000 UUIDs in all come as `scope: "workspace"` with empty lists.
  - `save-expired` (SR-131 AK3): the listener gets `{}`: main gave up waiting for the window's save, and the open workspace stays. Before a close it gets `{ closing: true }` (SR-105 AK1): the window stays open, and a close within 10 s closes it without waiting.
  - `agent-activity` (SR-117): the listener gets an access an agent made through the API or the MCP server of this copy, as `workspace.activity` gives it: `{ access, command, effect, at, element: { id, repository } }`, no content. The core process watches `activity.json` in the cache folder of the copy (core's `watchActivity`) and sends each new access to every window, once its store holds the state of the element the access saw (at most 1 s later). Nothing is sent when a window connects; `workspace.activity` gives the last access. The app's own calls are never recorded (they pass the access `app`).

The bridge offers nothing else, and in particular no delete (SR-099): `invoke` and `commands` are generic over the catalog, `on` is the one subscription (three events), and `copyText`, `recentWorkspaces`, `openWorkspace` and `onSave` are the facilities of the window.
