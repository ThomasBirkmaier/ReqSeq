# Tests

Part of the [`@reqseq/app` README](../README.md).

- Unit tests (`src/**/*.test.ts`, Vitest) use fake Electron objects, a Node `MessageChannel` and happy-dom for React. The `.ts` modules have an 80 % threshold for the package (ADR-0016, ThomasBirkmaier/ReqSeq-archive#752); React components (`.tsx`) have no coverage threshold, Playwright covers them (ADR-0016, ThomasBirkmaier/ReqSeq-archive#537).
- `test/app.spec.ts` (Playwright, `_electron.launch`) runs the built app on fixture workspaces:
  - it starts and shows the status;
  - `invoke` gives what the CLI gives (`[SR-080/AK2]`);
  - the bridge offers the catalog commands, the events, `copyText`, `pasteText` and the recent workspaces, and no delete (`[SR-099/AK1]`);
  - the renderer has no Node;
  - the session cancels a non-local request, and the app makes none itself (`[SR-078/AK1]`);
  - `reqseq-file:` does not leave the repository;
  - navigation and new windows are denied;
  - a stopped core process is started again;
  - without a workspace, the app says how to open one.

  The JUnit file is `test-results/junit-electron.xml` (CI jobs `electron-shard` on Ubuntu in two shards, each of every second file (`ELECTRON_SHARD=1/2` runs shard 1 locally), and `electron-platform`, under `xvfb-run` on Linux).
