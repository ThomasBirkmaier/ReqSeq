# Metamodel (SR-130)

Part of the [`@reqseq/app` README](../README.md).

- **Metamodel (SR-130, D-063):** "Show metamodel" in the command prompt (the title of `metamodel.get`, which it `covers`; initials `sm`; no key of its own, and not offered on the metamodel itself) shows the metamodel of the workspace as a graph, a buffer of its own ("Metamodel", one per workspace; the modeline says how many types it defines). Every type is a box with its name, its prefix, "abstract" when it is, every property, the inherited ones muted (a property is inherited when the type named by `extends` has it), and its statuses (own and inherited) as small tags in as many rows as the box's width needs (`statusRows`), the initial status in bold, an invalid one struck through, both said in the tag's tooltip (AK2); every curve has one label line per link: "extends" to the parent, the name of each relation kind from each of its source types to each of its target types, and the name of each property of kind `relation` from the type that has it as its own to each of its target types (spec question ThomasBirkmaier/ReqSeq-archive#619). A side a relation kind or property leaves out allows every type: the box "Any type", with the open side in the label ("Based on · any source", "Traces to · any target", "Refines · any source and target"). Everything shown is one `metamodel.get` call (core's `metamodel/graph.ts`, `@reqseq/core/metamodel-graph`), asked again when the workspace changed; an equal answer is not laid out again. `metamodel-layout.ts` places the boxes with dagre, top-down, a target above its source; a curve that would close a cycle (a relation kind from a parent to its subtype, the opposite of another curve) is drawn afterwards down from its source, with its label in the first free place beside it, so every parent stands above its subtypes. Every curve ends in an arrowhead at its target. Keys as in the graph of an element (Up/Down along a curve, Left/Right through a layer, Page Up/Down from layer to layer, Home the first type), keys with Ctrl, Cmd or Alt are the window's. Ctrl/Cmd+T ("Show metamodel as text", "Show metamodel as graph") shows the same answer as text ("Metamodel · text"): a section per type with its name, prefix, key, "abstract", "extends" and the parent, every property with its key, value kind ("list of" for several values, "→" the target types of a relation), "required" and "counts to version" (its `content`, D-057), the inherited ones muted, and its statuses ("none" when it has none); then a line per relation kind with its source and target types ("any type" for a side left out, "none" for an empty list); then the problems of the output. Its rows move like a list (Down/Up, Ctrl+N/Ctrl+P, Page Up/Down, Home/End). The selected type is shared: the text opens on it and the graph opens on the type selected in the text; a relation kind has no box, so the graph keeps the type selected before it. "Show metamodel" from another buffer always shows the graph. A right-click on a type's head, a property row, a status, a label line, "Any type" or the sheet opens the metamodel commands of that place with the definition given (SR-199, [context menu](context-menu.md)). After a metamodel command succeeds in the app (`metamodelChanged` of the context, from `metamodel-prompt.ts`), the window keeps what it added or changed (`metamodel-changes.ts`, from the command's output) and the graph and the text mark every place that shows that definition itself (`.changed`, the mark colour): a type's head, its own "extends" row in the text and the "extends" label of its curve to its parent; a property added to a type in that type and its subtypes, with the curves from them, a changed property everywhere, with its curves; a relation kind's label lines, its row and its limit rows; a status added to a type in that type, its subtypes and the other types that got it (`alsoTypes`), a changed status everywhere, with the status that lost the initial mark (AK7). A place where another definition names the changed one is not marked: the "extends" of a subtype, a source, target or limit type of a relation kind, a target type of a property. The next metamodel command that writes a file (its output's `files`) replaces the marks, a removal that writes a file leaves none; a command that writes nothing, a refused command and every other command keep them. They last until the app ends or a workspace is opened, also the same one again (a failed open keeps them), and changes through other accesses or by hand mark nothing.
