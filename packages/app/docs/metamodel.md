# Metamodel (SR-130)

Part of the [`@logreq/app` README](../README.md).

- **Metamodel (SR-130, D-063):** "Show metamodel" in the command prompt (the title of `metamodel.get`, which it `covers`; initials `sm`; no key of its own, and not offered on the metamodel itself) shows the metamodel of the workspace as a graph, a buffer of its own ("Metamodel", one per workspace; the modeline says how many types it defines). Every type is a box with its name, its prefix, "abstract" when it is, and every property, the inherited ones muted (a property is inherited when the type named by `extends` has it); every curve has one label line per link: "extends" to the parent, the name of each relation kind from each of its source types to each of its target types, and the name of each property of kind `relation` from the type that has it as its own to each of its target types (spec question #619). A side a relation kind or property leaves out allows every type: the box "Any type", with the open side in the label ("Based on · any source", "Traces to · any target", "Refines · any source and target"). Everything shown is one `metamodel.get` call (`metamodel-graph.ts`), asked again when the workspace changed; an equal answer is not laid out again. `metamodel-layout.ts` places the boxes with dagre, top-down, a target above its source; a curve that would close a cycle (a relation kind from a parent to its subtype, the opposite of another curve) is drawn afterwards down from its source, with its label in the first free place beside it, so every parent stands above its subtypes. Every curve ends in an arrowhead at its target. Keys as in the graph of an element (Up/Down along a curve, Left/Right through a layer, Page Up/Down from layer to layer, Home the first type), keys with Ctrl, Cmd or Alt are the window's. Ctrl/Cmd+T ("Show metamodel as text", "Show metamodel as graph") shows the same answer as text ("Metamodel · text"): a section per type with its name, prefix, key, "abstract", "extends" and the parent, every property with its key, value kind ("list of" for several values, "→" the target types of a relation) and "required", the inherited ones muted, and its statuses ("none" when it has none); then a line per relation kind with its source and target types ("any type" for a side left out, "none" for an empty list); then the problems of the output. Its rows move like a list (Down/Up, Ctrl+N/Ctrl+P, Page Up/Down, Home/End). The selected type is shared: the text opens on it and the graph opens on the type selected in the text; a relation kind has no box, so the graph keeps the type selected before it. "Show metamodel" from another buffer always shows the graph.
