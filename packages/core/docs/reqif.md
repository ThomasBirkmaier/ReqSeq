# ReqIF block (`src/reqif/`)

ReqIF 1.2 import and export (SR-052..SR-059, SR-095; ADR-0013). So far the model, the parser and the XHTML conversion; the writer and the commands follow (#265, Lanes E and I).

## Model (`model.ts`)

`ReqifFile`: the header, datatypes (STRING, XHTML, INTEGER, REAL, DATE, BOOLEAN, ENUMERATION with its values, `KEY` and `OTHER-CONTENT`), spec types by category (`spec-object`, `spec-relation`, `specification`, `relation-group`) with their attribute definitions, SPEC-OBJECTs, SPEC-RELATIONs, SPECIFICATIONs with the nested SPEC-HIERARCHY, and `unread`: the elements the model leaves out (relation groups, tool extensions, unknown definitions), by name and line, for the loss list (SR-053 AK2). Every identifiable keeps IDENTIFIER, `LONG-NAME`, `LAST-CHANGE`, `DESC` and its line. References stay IDENTIFIERs; values stay the text of the file (numbers, dates, booleans as written), the import converts them. An XHTML value is the namespace-resolved node tree (`XhtmlElement`: local name, namespace, attributes, children in order with the text runs between them), never a re-escaped string. It keeps every element and attribute as given (`script`, `on…`, `javascript:` links too), so the conversion to Markdown and any rendering must allowlist.

## Parser (`parse.ts`)

`parseReqif(bytes, limits?)` gives `{ kind: "parsed", file }` or `{ kind: "refused", message, line }`; the commands turn a refusal into `reqif.invalid`. `limits` defaults to `REQIF_LIMITS`.

- The bytes stream through `streamXml` of `files/xml-scan.ts` (ADR-0012): UTF-8 only, no `<!DOCTYPE`, no entity but the five predefined ones and numeric references, well-formed only, so no file can make ReqSeq open a connection or read another file. No tree of the whole file is built: each item of DATATYPES, SPEC-TYPES, SPEC-OBJECTS, SPEC-RELATIONS and SPECIFICATIONS is read when it ends and its elements are dropped; inside THE-VALUE the XHTML elements become the model's nodes at once. Whatever the model does not read (TOOL-EXTENSIONS, unknown or foreign parts and children of the root, CORE-CONTENT and REQ-IF-CONTENT) is skipped without building anything and recorded once in `unread`. The walk is the scanner's iteration, so nesting depth is not limited, and namespace declarations are a stack per prefix, so deep nesting stays linear.
- Memory: `REQIF_LIMITS.bytes` (256 MiB) is refused before reading. While reading, the parser charges an estimate of what it keeps (open elements, attributes, text, model, unread entries; 64 bytes per object, 2 per character), and refuses the file above `REQIF_LIMITS.retained` (1 GiB) with "Reading the file would keep more than … bytes in memory". Measured on Node 22: a delivery of 50,000 SPEC-OBJECTs with XHTML and 200,000 SPEC-RELATIONs (114 to 161 MB) peaks at 260 to 300 MB of heap and is charged 0.4 to 0.5 GiB. The worst hostile files measured peak at about 1.1 GB, under the default heap (5 million XHTML elements with 4 attributes each, refused).
- Refused while reading: a prefix without declaration (element or attribute), a name that is not a qualified name (`:a`, `a:b:c`), an empty prefixed namespace (`xmlns:p=""`), a root that is not `REQ-IF` in the ReqIF namespace, a ReqIF element inside XHTML, a missing required part (`THE-HEADER`, `REQ-IF-HEADER`, `CORE-CONTENT`, `REQ-IF-CONTENT`, a `TYPE`, `DEFINITION`, `SOURCE`, `TARGET` or `OBJECT` reference, `THE-VALUE`) and an identifiable without IDENTIFIER.
- Element names are resolved by their namespace declarations, never by the prefix: `reqif:SPEC-OBJECT` and an unprefixed one in the default namespace are the same, and XHTML may sit in a default namespace on its `div`. Attributes keep their name as written, as name and value pairs in a flat array. `MULTI-VALUED` is an `xsd:boolean` (`true` or `1`). Text runs that are only whitespace are dropped outside XHTML.
- `unread` holds, by name and line, each skipped element and the unknown children of the items read. Part 1b of #265 refuses a repeated part, records what is still dropped (a second VALUES, THE-ORIGINAL-VALUE, defaults, facets) and gives each entry its owner, as the loss list needs; it also refuses an IDENTIFIER used twice and warns about dangling references. Until then a reference to an IDENTIFIER the file does not define is kept as written.
- `.reqifz` archives are not read (SR-053).

The hand-written samples and the nightly parse at N-036 follow in part 1b.

## XHTML and Markdown (`xhtml-markdown.ts`)

The conversion of an `ATTRIBUTE-VALUE-XHTML` and the text of an element (SR-095, ADR-0013); both directions walk without recursion of their own.

- `xhtmlToMarkdown(value)` gives `{ markdown, images, losses }`. Our node tree becomes hast, then `hast-util-to-mdast` and `mdast-util-to-markdown` with GFM write it in the editor's style: ATX headings, `-` bullets, `1.` lists, `*em*`, `**strong**`, `~~del~~`, fenced code, `---`, GFM tables (AK1). Only XHTML elements with a Markdown form are converted; `b`, `i` and `s` are read as `strong`, `em` and `del`, `span` and `div` as containers. A loss carries its `reqifLoss` code and a reason, once per code and reason, and keeps the text (AK3): `xhtml-style` for each `style`, `xhtml-element` for an element without Markdown form or outside the XHTML namespace and for a non-image `object`, `xhtml-rowspan` and `xhtml-colspan` for spans above 1 (the cells become simple cells), and `xhtml-cell-block` for a list, table, code block, quote, rule or heading in a cell. A cell is flattened at every depth into one line: `br`, paragraphs and `div`s end a line, written `<br>` without loss, and the blocks above keep their text as lines. `style="text-decoration:line-through"` (ReqIF 1.2 §10.8.20) becomes `~~`; every other declaration is `xhtml-style`. A `caption` becomes a paragraph before its table. An `img` without `src` or an `object` without `data` is `xhtml-element`, and emphasis of white space alone is dropped. Elements nested deeper than 256 keep only their text (`xhtml-element`), since the Markdown libraries recurse; wide values are walked without recursion or argument spreads.
- Images: an `object` with an image type (its `type`, else the extension of `data`) and an `img` become `![alt](data)`, the fallback text of the `object` as alt, and are listed in `images` as written. Copying them, `image-missing` and `image-outside` are the import's (AK2, Lane I).
- `markdownToXhtml(markdown, { image? })` gives `{ value, asWritten }`: `value` is one `div` with only the elements of the driver's XHTML modules and the attributes `href`, `title` and `align`: no `class` (§10.8.20), no `start` (not in the List module, so an ordered list counts from 1), no `id` (it would repeat across the values of one file). Images become `<object data type>`, `data` through `image` (the export's link rewrite). HTML in the text stays text, since the editor interprets none; only `<br>` is a line break, as in a table cell. `thead` and `tbody` are dropped (not in Basic Tables), keeping their rows. Task boxes are written as `[ ]` and `[x]`, footnotes as written (`[^1]` and a paragraph `[^1]: …`), with no heading, back link or `id`. A text nested too deeply for the libraries (about 3,000 `>`) is written as one `pre` with the text as typed and `asWritten: true`, so the export can name it.
