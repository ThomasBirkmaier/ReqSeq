# Checking the whole workspace (`workspace.check`, SR-019)

Part of the [`@reqseq/core` README](../README.md).

`src/commands/workspace/check.ts` collects, in this order: the problems of the workspace layout and of the metamodel, those of repositories with a metamodel of their own (`workspace.metamodel-mismatch`, #666, metamodel block), those of the element store (SR-008, unreadable and skipped files), then the whole-workspace states of `FINDING_STATES`: `requiredProblemsState` (SR-015), `unknownProblemsState` (SR-016), `statusProblemsState` (ThomasBirkmaier/ReqSeq-archive#306), `statementProblemsState` (#667: `element.statement-without-text`, a warning on the line of the value for an element of a type with the meaning `requirement` whose text is blank and whose property with the meaning `statement` has a value while it does not count to the version, `src/model/statement-findings.ts`, from `ElementRecord.blankText` without reading a file), `supersededTargetProblemsState` (SR-072), `supersededValidityProblemsState` (SR-040, variants block), `targetNotCoreProblemsState` (SR-041 AK8, variants block), `valueKindProblemsState` (SR-085), `itemLimitProblemsState` (SR-171: `element.too-many-items`, model-findings.md), `criterionKeyProblemsState` (SR-204 AK10: `element.criterion-key-missing`, `-duplicate`, `-invalid`, model-findings.md), `relationTypeProblemsState` (SR-086), `relationLimitProblemsState` (SR-152: `relation.too-many`, `relation.too-few`, model-findings.md), `duplicateIdProblemsState` (SR-088), `missingTargetProblemsState` (SR-089), `crossRepositoryTitleProblemsState` (SR-005 AK4), `unresolvedLinkProblemsState` (#176: a stored `reqseq:` link in the text or a `markdown` property whose target is no UUID, a warning that says which element it names, `src/model/unresolved-links.ts`, from `ElementRecord.unresolvedLinks` without reading a file; the same state reports `relation.not-a-link`, a warning for a `reqseq:` reference in the element text outside a Markdown link and outside code, SR-021 AK3, #633, from `ElementRecord.bareReferences`, and `relation.reference-style`, a warning per link reference definition with a `reqseq:` destination in the text or a `markdown` property, since a reference-style link counts for nothing, #844, from `ElementRecord.referenceDefinitions`), `derivationCycleProblemsState` (SR-090, trace block) and `noParentProblemsState` (SR-022 AK6, trace block: a requirement without a parent, a warning). A new whole-workspace finding joins by adding its state to `FINDING_STATES` (exported for tests that need every finding state). `ok` is false when a finding at or above `failOn` (default `error`, ThomasBirkmaier/ReqSeq-archive#304) exists, whatever `severity` shows (ADR-0009: CLI exit code 1); `severity` only filters the problems shown, and the findings it leaves out are counted in `hidden` (`below`, `warning`, `info`; only when it leaves out at least one). Problems are appended in a loop, never spread into `push`, so hundreds of thousands of findings do not overflow the stack (N-036). `changedFiles` and `changedSince` restrict the check to a merge request (SR-092, `model/changed.ts`, spec question ThomasBirkmaier/ReqSeq-archive#291): the changed elements (their file or an embedded image differs from the revision in the working copy, untracked files included, or the file is named) and their direct targets. A problem with an element is kept when its element is one of them or its target is a changed element; a problem with only a file when the file changed or belongs to one of them; the problems of the layout and the metamodel (with `workspace.metamodel-mismatch`) always. The revision is looked up in every available repository (`resolveCommit`, `changedPaths` of the git reader); a repository without it, or without Git, adds nothing and gets an `info` problem (`git.revision-missing`, `git.unavailable`), as does a folder below the top level of its work tree of which Git sees no file (nothing listed, and no tree at the folder in the commit, ThomasBirkmaier/ReqSeq-archive#377); none has it: `git.commit-not-found` (CLI exit code 4); any git failure in a repository: `git.unavailable`. The UUIDs the changed element files held at the commit count as changed too, so relations to a deleted element or an old UUID are kept. A folder in `changedFiles` is `input.invalid`. The outdated relations are restricted before `datedProblems`, so only the kept ones are dated.

The gaps of verification (SR-230 AK1, AK2, `src/evidence/gaps.ts`, `verificationGapProblems`) come per call after SR-103 and before the outdated relations, only in a full check (no `changedFiles` or `changedSince`) and only while the metamodel is valid, at the workspace file: `evidence.no-location` (warning) while `evidence` of the workspace file is absent or empty and the store holds an element of a type with the meaning `requirement`; otherwise `evidence.open-requirements` (info), one finding with the number of requirements that `countedIn` keeps (not invalid), whose property with the meaning `verification-method` holds `test` or no value (every requirement without such a property), and whose status in the core from `verificationState` is `open`, after `prepare(counted, { own: true })` as `evidence.degree` does; none when that number is 0. The message names the call `element list --where` with `openRequirementsWhere(methodKey)`, which lists exactly them. Cost at N-036: one pass over the store and one memoised evaluation per counted requirement, at most one version batch.

The outdated skill file (SR-229 AK10, `src/commands/tool/guide/skill-check.ts`, `outdatedSkillProblems`) comes per call after the gaps, only in a full check and whatever the state of the metamodel (the skill file names none of it): `readSkillFile` looks at the place of D-079; ReqSeq's own file whose `reqseq-version` is older than `PRODUCT_VERSION` (`compareVersions`, a version that is none is not reported) and whose canonical text differs from `skillFile(entries, itsVersion)` (`sameContent`, so a file that differs only in its version line is not reported) is one `workspace.skill-outdated` info at that path, naming `reqseq tool guide --skill --write`, with `--replace` when its checksum no longer matches. A place `readSkillFile` refuses (a link, a folder, no permission) is no finding. It reads the file the tool places itself, with no input path, so the result is the same in every access. Cost: one `lstat` and at most 64 KiB per call.
