# Checking the whole workspace (`workspace.check`, SR-019)

Part of the [`@reqseq/core` README](../README.md).

`src/commands/workspace/check.ts` collects, in this order: the problems of the workspace layout and of the metamodel, those of repositories with a metamodel of their own (`workspace.metamodel-mismatch`, #666, metamodel block), those of the element store (SR-008, unreadable and skipped files), then the whole-workspace states of `FINDING_STATES`: `requiredProblemsState` (SR-015), `unknownProblemsState` (SR-016), `statusProblemsState` (ThomasBirkmaier/ReqSeq-archive#306), `statementProblemsState` (#667: `element.statement-without-text`, a warning on the line of the value for an element of a type with the meaning `requirement` whose text is blank and whose property with the meaning `statement` has a value while it does not count to the version, `src/model/statement-findings.ts`, from `ElementRecord.blankText` without reading a file), `supersededTargetProblemsState` (SR-072), `supersededValidityProblemsState` (SR-040, variants block), `targetNotCoreProblemsState` (SR-041 AK8, variants block), `valueKindProblemsState` (SR-085), `itemLimitProblemsState` (SR-171: `element.too-many-items`, model-findings.md), `criterionKeyProblemsState` (SR-204: `element.criterion-key-missing`, `-duplicate`, `-invalid`, model-findings.md), `relationTypeProblemsState` (SR-086), `relationLimitProblemsState` (SR-152: `relation.too-many`, `relation.too-few`, model-findings.md), `duplicateIdProblemsState` (SR-088), `missingTargetProblemsState` (SR-089), `crossRepositoryTitleProblemsState` (SR-005 AK4), `unresolvedLinkProblemsState` (#176: a stored `reqseq:` link in the text or a `markdown` property whose target is no UUID, a warning that says which element it names, `src/model/unresolved-links.ts`, from `ElementRecord.unresolvedLinks` without reading a file; the same state reports `relation.not-a-link`, a warning for a `reqseq:` reference in the element text outside a Markdown link and outside code, SR-021 AK3, #633, from `ElementRecord.bareReferences`, and `relation.reference-style`, a warning per link reference definition with a `reqseq:` destination in the text or a `markdown` property, since a reference-style link counts for nothing, #844, from `ElementRecord.referenceDefinitions`), `derivationCycleProblemsState` (SR-090, trace block) and `noParentProblemsState` (SR-022 AK6, trace block: a requirement without a parent, a warning). A new whole-workspace finding joins by adding its state to `FINDING_STATES` (exported for tests that need every finding state). `ok` is false when a finding at or above `failOn` (default `error`, ThomasBirkmaier/ReqSeq-archive#304) exists, whatever `severity` shows (ADR-0009: CLI exit code 1); `severity` only filters the problems shown, and the findings it leaves out are counted in `hidden` (`below`, `warning`, `info`; only when it leaves out at least one). Problems are appended in a loop, never spread into `push`, so hundreds of thousands of findings do not overflow the stack (N-036). `changedFiles` and `changedSince` restrict the check to a merge request (SR-092, `model/changed.ts`, spec question ThomasBirkmaier/ReqSeq-archive#291): the changed elements (their file or an embedded image differs from the revision in the working copy, untracked files included, or the file is named) and their direct targets. A problem with an element is kept when its element is one of them or its target is a changed element; a problem with only a file when the file changed or belongs to one of them; the problems of the layout and the metamodel (with `workspace.metamodel-mismatch`) always. The revision is looked up in every available repository (`resolveCommit`, `changedPaths` of the git reader); a repository without it, or without Git, adds nothing and gets an `info` problem (`git.revision-missing`, `git.unavailable`), as does a folder below the top level of its work tree of which Git sees no file (nothing listed, and no tree at the folder in the commit, ThomasBirkmaier/ReqSeq-archive#377); none has it: `git.commit-not-found` (CLI exit code 4); any git failure in a repository: `git.unavailable`. The UUIDs the changed element files held at the commit count as changed too, so relations to a deleted element or an old UUID are kept. A folder in `changedFiles` is `input.invalid`. The outdated relations are restricted before `datedProblems`, so only the kept ones are dated.

The gaps of verification (SR-230 AK1, AK2, AK5, `src/evidence/gaps.ts`, `verificationGaps`) come per call after SR-103 and before the outdated relations, only in a full check (no `changedFiles` or `changedSince`) and only while the metamodel is valid, at the workspace file: `evidence.no-location` (warning) while `evidence` of the workspace file is absent or empty and the store holds an element of a type with the meaning `requirement`; otherwise `evidence.open-requirements` (info), one finding with the number of requirements that `countedIn` keeps (not invalid), whose property with the meaning `verification-method` holds `test` or no value (every requirement without such a property), and whose status in the core from `verificationState` is `open`, after `prepare(counted, { own: true })` as `evidence.degree` does; none when that number is 0. The message gives only the number; `verificationGaps` returns with it the step `openRequirementsStep`: `element.list` with `selection.where` from `openRequirementsWhere(methodKey)`, which lists exactly them, and `limit` with the number above the default page of 200, at most 5,000, with no `workspace` (it runs in the one checked). `workspace.check` puts it into `next` only while `problems` shows the info, so a severity that hides the info drops it, and a restricted check has neither (SR-230 AK2). The app's "List all elements" opens the list with the step's `selection` (SR-226). Cost at N-036: one pass over the store and one memoised evaluation per counted requirement, at most one version batch. Beside them, also without an evidence location, `evidence.no-criteria-property` (warning, SR-230 AK5) per type of `typesWithMeaning(metamodel, "requirement")` whose effective `properties` lack the key of `propertyWithMeaning(metamodel, "acceptance-criteria")` (every such type when no property has the meaning; a kind other than text with many does not matter), while the store holds an element of exactly that type whose status `invalidStatuses` does not hold; at the file and line of the type's definition from `Metamodel.typePlaces`, with the metamodel repository, in the order of the types. One more pass over the store, only when such a type exists.

The skill file findings (SR-229 AK10, `src/commands/tool/guide/skill-check.ts`, `skillProblems`) come per call after the gaps, only in a full check and whatever the state of the metamodel (the skill file names none of it): `readSkillFiles` looks at each place of D-079 in its order. ReqSeq's own file whose `reqseq-version` is older than `PRODUCT_VERSION` (`compareVersions`, a version that is none is not reported) and whose canonical text differs from `skillFile(entries, itsVersion)` (`sameContent`, so a file that differs only in its version line is not reported) is one `workspace.skill-older-version` info at that path, naming `reqseq tool guide --skill --write`, with `--replace` when its checksum no longer matches. A place where nothing lies, while another place holds ReqSeq's own file of any version, is one `workspace.skill-missing` info at that path with the call without `--replace`. Each finding adds what its call does at every other place where it does more than create, replace or leave ReqSeq's own intact file: with `--replace` it replaces a file ReqSeq did not write or one changed since; without, it writes nothing there and fails; at a `blocked` place (a link, a folder, a file in the way, a Git place, no permission) it writes nothing and fails either way. A `blocked` place is no finding itself. It reads the files the tool places itself, with no input path, so the result is the same in every access. Cost per call: the `realpath` and `gitRootOf` walk of `skillLocations`, and per place the `linksStayInside` look, one `lstat` (and the folder walk when nothing is there), the Git check, a read of at most 64 KiB, and the skill text rendered twice for ReqSeq's own file.
