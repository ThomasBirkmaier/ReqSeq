# ReqIF mapping files (`src/reqif/mapping.ts`)

The mapping of the types and attributes of one ReqIF source to the own metamodel, one YAML file of `reqif-mapping.schema.json` per source (SR-054, D-022, D-056, ADR-0013 "Paths"). It imports the files, metamodel, model and workspace blocks; `reqif.saveMapping` uses it now, `reqif.import` and `reqif.export` will read with it.

- `mappingTarget(layout, root, source, given, command)`: where a mapping is written, for every access: directly in the mapping folder (`mappings` of the workspace file, default `reqif` in the main repository, SR-054 AK1). Without `given` the file is `mappingFileName(source)`: `portableName` of the source name in lower case plus `.yaml` (`Kunde A` gives `kunde-a.yaml`). `given` is a local path resolved against `root` (the CLI makes it absolute first); its folder, with links resolved, must be the mapping folder and its name end in `.yaml`, else `input.invalid` with `reason: "outside-mapping-folder"`. ReqSeq follows no link to its files: a mapping folder that is or lies below a link, inside the repository or out of it, is `input.invalid` (`reason: "link"`); paths compare by the platform's rules (`samePath`: on Windows without case). A mapping folder in the metamodel folder is `input.invalid` (`reason: "metamodel-folder"`), one in a repository not on this machine `file.folder-missing`. The path then passes `refuseUnlisted` (no `.git`, no link, portable names).
- `checkMapping(layout, metamodel, mapping, at, command)`: the mapping against the own metamodel, which it only reads: types, properties (of the mapped type when `source-type` names a mapped one; `title` and `text` always), `values` only for a choice property and only its choice keys, relation kinds (or a relation-valued property, whose targets are then SPEC-RELATIONs), the statement property, `omit-properties` (also of each export profile) and the target repository. One `input.invalid` lists every violation, `details.fields` below `at` (`mapping.attributes[2].values.High`).
- `readMappingFile(layout, metamodel, root, given, command)`: reads a mapping from any local path the access allows (SR-054 AK2: the command names the file). A file that cannot be read or does not match the schema is `file.faulty` at `mapping`; then `checkMapping`.
- Command `reqif.saveMapping` (`src/commands/reqif/saveMapping.ts`): `checkMapping`, then `mappingTarget`. A new file is written in the schema's key order, the folder created when missing. An existing file is changed key by key (`editYamlDocument`, ADR-0007): keys whose value changed are rewritten, keys the input leaves out and keys the schema does not know removed, comments and other bytes kept; an equal mapping writes nothing (`files: []`). Schema defaults come with the input and are written (`statement.datatype: string`), so a hand-written `statement` without `datatype` is rewritten once. When the default file holds the mapping of another `source.name` (names equal once portable, such as `Kunde A` and `KUNDE A`), it is replaced only when `file` names it, else `input.invalid` (`reason: "other-source"`). A file that does not parse is `file.faulty`. Mapping files are not elements: nothing is deleted or renamed.
