# ReqIF mapping files (`src/reqif/mapping.ts`)

The mapping of the types and attributes of one ReqIF source to the own metamodel, one YAML file of `reqif-mapping.schema.json` per source (SR-054, D-022, D-056, ADR-0013 "Paths"). It imports the files, metamodel, model and workspace blocks; `reqif.saveMapping` uses it now, `reqif.import` and `reqif.export` will read with it.

- `mappingTarget(layout, root, source, given, command)`: where a mapping is written, for every access: directly in the mapping folder (`mappings` of the workspace file, default `reqif` in the main repository, SR-054 AK1). Without `given` the file is `mappingFileName(source)`: `portableName` of the source name in lower case plus `.yaml` (`Kunde A` gives `kunde-a.yaml`). `given` is a local path resolved against `root` (the CLI makes it absolute first); its folder, links resolved, must be the mapping folder and its name end in `.yaml`, else `input.invalid` with `reason: "outside-mapping-folder"`. A mapping folder in the metamodel folder is `input.invalid` (`reason: "metamodel-folder"`), one in a repository not on this machine `file.folder-missing`. The path then passes `refuseUnlisted` (no `.git`, no link, portable names).
- `checkMapping(layout, metamodel, mapping, at, command)`: the mapping against the own metamodel, which it only reads: types, properties (of the mapped type when `source-type` names a mapped one; `title` and `text` always), `values` only for a choice property and only its choice keys, relation kinds, the statement property, `omit-properties` (also of each export profile) and the target repository. One `input.invalid` lists every violation, `details.fields` below `at` (`mapping.attributes[2].values.High`).
- `readMappingFile(layout, metamodel, root, given, command)`: reads a mapping from any local path the access allows (SR-054 AK2: the command names the file). A file that cannot be read or does not match the schema is `file.faulty` at `mapping`; then `checkMapping`.
- Command `reqif.saveMapping` (`src/commands/reqif/saveMapping.ts`): `checkMapping`, then `mappingTarget`. A new file is written in the schema's key order, the folder created when missing. An existing file is changed key by key (`editYamlDocument`, ADR-0007): keys whose value changed are rewritten, keys the input leaves out removed, comments and other bytes kept; an equal mapping writes nothing (`files: []`). A file that does not parse is `file.faulty`. Mapping files are not elements: nothing is deleted or renamed.
