# Baselines block (`src/baselines/`)

Part of the [`@reqseq/core` README](../README.md). Baseline files (D-039, `baseline.schema.json`): stage 4 has the read-only reader (`read.ts`) so that `evidence.list` can name the baselines that contain the version of a record (SR-032 AK2, assumption of spec question #530 Q1). `data.export` selects by baseline (SR-061 AK2, `selects` and `findBaseline` below); `create.ts` writes new baseline files (SR-050), `show.ts` and `compare.ts` show a baseline and compare an element with it (SR-051, below); `counting.ts` says which evidence records count for a baseline (SR-094, below). The other commands still refuse `selection.baseline` (#530 Q4). The block never changes or removes a file and never writes to Git.

## Reading

The file format, the fast reader and the bounds are [ADR-0018](../../../docs/adr/0018-baseline-file.md). A file in the layout ReqSeq writes is read by the line scanner (`scan.ts`: `scanBaseline`, and `baselineHeader` for the lines before `repositories:`, with the `selection.ids` lines scanned too), through `readYamlFileFast` of the files block; any other layout (a comment, a blank line, CRLF, a BOM, entries out of order) falls back to YAML and the schema, with the same baseline or the same problems. On both paths an element copy or a repository listed twice is `baseline.invalid` at the line of the second one.

`readBaselines(layout, kept?)` → `{ location, baselines, problems, faulty, incomplete }`:

- Where: the `baselines` location of the workspace file, default the folder `baselines` in the main repository (`settingLocation`). Every `*.yaml` file directly in the folder, in file order (code units), as saved filters are read; the workspace file is never one. A `.yml` file is `baseline.invalid` (warning) and not read; other files (a README) are passed over; a folder that does not exist holds no baseline; a path that is no folder is `file.unreadable`.
- A file is checked against `baseline.schema.json`: YAML errors are the problems of `readYamlFile` (`file.invalid-yaml`, ...); a schema violation is `baseline.invalid` (error) with the line of the value, at most `MAX_VIOLATIONS` per file and then one problem that counts the rest. A faulty file gives no baseline.
- `Baseline`: `name`, `repository`, `file`, `data` (the file as read) and `contains(id, version)`: the file lists the element's UUID with that version (in any repository; `elements[].repository` names a copy, SR-088). `selects({ id, repository })` (`data.export`): the file lists the UUID in any version, an entry with `repository` for that copy only, one without for every copy; one index per file read, kept with it. Taking an entry without `repository` as every copy is the interim rule: ADR-0018 takes it as the copy in the file's repository, else the only copy, and `baselineOf` follows with SR-051.
- `faulty`: the files that gave no baseline, relative to their repository, in file order.
- `namedBaseline(workspace, text, command)` (`baseline.get`, `baseline.compare`): the baseline `findBaseline` finds, else `input.invalid` at `baseline` with `reason` `unknown-baseline` or `ambiguous-baseline`, or `file.faulty`.
- `findBaseline(baselines, text)` → `found`, `ambiguous` (the files), `faulty` (the file) or `none`: by `name` first (ignoring case and Unicode normal form, as saved filters), then by file name in the folder with or without `.yaml` (the folder is configurable, so no folder part); a text that names only a faulty file by its file name is `faulty`.
- `incomplete`: the repository of the folder is not on this machine (SR-006 AK2). A location in a repository the workspace file does not list gives nothing (the layout reports it).
- `baselinesContaining(baselines, id, version)`: the names of the baselines that contain the version, in file order, each name once.

## Kept between calls

`baselineFilesState` (reset with the workspace layout) keeps what each file gave with its size and modification time, including the parsed file (`data`) for `baseline.get` and `baseline.compare`: in a running server about the size of the files themselves, noticeable at 20 baselines of 50,000 entries. `workspaceBaselines(workspace)` lists the folder on every call and parses again only a file that is new or whose size or time changed, and drops files that are gone. So a baseline committed by another person counts as soon as the working copy has it, also in a running server or the app, and a baseline of 50,000 elements is parsed once (N-036).

## Text of a new file

`baselineText(data)` (`text.ts`) writes the layout of ADR-0018 that `scanBaseline` reads: the header in block style with `package`, `view` and `ids` items as flow mappings and lists of plain values in `where` on one line, then one flow mapping per line for `repositories` and `elements` (`elements: []` when empty); a repository name YAML would read as no string is quoted. `baselineStem(name)` is the file name without extension: `portableName` with `baseline` when nothing is left, `-baseline` after a Windows device name. `writeNewBaseline(repository, folder, name, text)` (`write.ts`) creates the file under the first free name (`-2`, `-3`, … for a name the folder has in any case or normal form), through the create path of `writeFileAtomic`, so nothing is ever replaced; the folder is created when missing. `involvedCommits(layout, elements)` (`state.ts`) gives the HEAD commit of the repositories of the elements, the main and the metamodel's, in workspace order, and refuses one without commit (`git.unavailable`, the reason in words); `refuseUncommitted(workspace, commits, checked)` refuses with `baseline.uncommitted-changes` while the files of the selected elements, the files they embed, the metamodel's YAML files or the workspace file differ from the commit (`uncommittedFiles`), naming the elements and the other files.

## Creating

`createBaseline(workspace, request)` (`create.ts`, for `baseline.create`; the command resolves the selection and its stored form: UUIDs, `{ id, title }` of package and view, a saved filter as its `where` and `view`, ADR-0018 `selection`). The command refuses `input.invalid` at `selection.view` when it names another view than the saved filter (assumption of spec question #440). In this order, nothing written on a refusal: `file.faulty` when the baselines folder cannot be listed, since its taken names are unknown (AK6); `baseline.exists` when a valid baseline has the name (`foldName`, AK6); `file.folder-missing` when the folder's repository is not here; `file.faulty` for a selected element without version; `git.unavailable` for a repository involved (the selected elements', the main and the metamodel's, AK4) without commit (AK7) or whose changes Git cannot tell; `baseline.uncommitted-changes` (AK2) when `uncommittedFiles` (`model/uncommitted.ts`, the check of `data.export` on a given set of files) finds a change in the files of the selected elements, the files they embed, the metamodel's YAML files or the workspace file, naming the elements (also those whose embedded file changed) and the other files; evidence records do not count. The file is `baselineText` written by `writeNewBaseline` (above), never replaced or committed.

## Showing and comparing

`showBaseline(workspace, request)` (`show.ts`, for `baseline.get`, SR-051 AK1–AK3). The command resolves the stored selection as it selects now (`query` lies above this block): `ids` items as ADR-0018 reads them, `package` and `view` by UUID or text, `filter` by name; one that cannot be resolved now is a `baseline.invalid` warning and is treated as no stored selection.

- Evidence (`withEvidence`, SR-094): `verification: { view, status }` for each entry of the page whose type has the meaning requirement (not for `added` or `missing` rows). The command (`commands/baseline/get.ts`; the evidence block lies above this one) passes `ShowRequest.verification`: `recordStatusOf` of the evidence block at the entry's version in the baseline, over the element's own records only (AK5, never `indirect`) that count for the baseline (`countsFor`: dated at or before its date and time; by day when either date has no time, the day as written, AK2) and hold in the view of the stored selection (AK4: its variant, else the core). None of that version but others: `outdated`; none: `open` (AK3). A stored selection that cannot be resolved has its `view` resolved alone; a view that is gone leaves the evidence out with a `baseline.invalid` warning. While the metamodel is not valid there are no records. Valid baseline and record files always carry a time, so the day rule only holds for records given otherwise. Cost: the records index of the workspace (`evidenceIndexState`, built once per state of the records) and one pass over each page entry's own records.

- The copy of an entry (and of a stored `ids` item): the one its `repository` names, else the copy in the file's repository, else the only copy (`copyOf`). None is `missing`; several elsewhere is `missing` with a `baseline.invalid` warning; a second entry of the same copy gives no row and a warning. `Baseline.selects` (`data.export`) still takes an entry without `repository` as every copy.
- State, the first that holds: `missing`; `superseded` (status invalid now, D-044, also when changed); `removed` (a stored selection that no longer selects it, also when changed); `changed` (also when the current version cannot be computed, with a `file.faulty` warning); `unchanged`. `current` whenever it differs. `added`: selected now and not in the file, after the entries. Without stored selection no `removed`, no `added`, `selectionKnown: false`.
- Cost (N-036): one `currentVersionsOf` for all entries and added elements, one lookup by UUID per entry; `versionDates` for the page only (`limit`, `offset`); `counts` and `total` over all. No old content is read (D-033).

`compareBaseline(workspace, baseline, ref)` (`compare.ts`, `baseline.compare`, AK4): the copy `ref` resolves to when the baseline lists it, else the one listed copy of its UUID (also for copies in several repositories or a gone file; several listed is `ref.ambiguous` naming them); the baseline's commit of the element's repository as `from`, HEAD as `to` (`null` when the file differs from HEAD or is gone), the path now and, when it moved, the path at `from` (`fileSince`, `model/file-since.ts`: the file read at `from` when it changed since; only when it did not hold the UUID, the other files `changedPaths` names, read at `from`), and `["git", "-C", <repository folder relative to the workspace root>, "diff", from, (to), "--", (oldFile), file]`. A file moved to a path Git does not track shows only as deleted in the command until that path is added to Git (`git add -N`); ReqSeq never stages. Runs nothing; `git.commit-not-found` when the baseline names no commit for the repository or Git does not have it, `git.unavailable` when Git cannot tell.

`baseline.list` (`commands/baseline/list.ts`): the reader's valid baselines with date, number of entries and `view` when the stored selection is only a view naming a variant (SR-103 AK4).
