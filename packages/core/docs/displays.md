# Displays block (`src/displays/`)

The display models that the app's renderer and the HTML export share (ADR-0019): one pure builder per display, which takes command outputs as they are and gives the rows, groups, order, bounds and words both sides render. Public as the subpath `@reqseq/core/displays` (`index.ts`). Its modules import only types, each other and the import-free modules of core (`graph/words.ts`, `model/criterion-items.ts`, `problem-titles.ts`, `hint-order.ts`), so the sandboxed renderer bundle loads no `node:*` with it; the `no-restricted-imports` block on `packages/core/src/displays/**` in `eslint.config.js` enforces it.

- Words (`labels.ts`): `relationGroupLabel` (an outgoing kind by its name, an incoming one by its `inverse-name`, else its name, as `trace.matrix` names an incoming column, a relation property by its name, the key where the metamodel names none, "inline reference", incoming with "← "); `emptyValueLabel` ("–", SR-232 AK1); `boundNote` ("Only the nearest 100 are shown.", SR-232 AK5); `shownId` (SR-084 AK4, from `graph/words.ts`).
- `ElementRef` (`element-ref.ts`): an element as a row shows it and where it leads, by UUID and repository (no URL, ADR-0019 point 5), with `invalid` for a status the metamodel marks invalid (D-044).
- `neighbourhoodDisplay` (`neighbourhood.ts`): of the answers of `trace.neighbourhood` (parents: the up walk over the derivations; children: the down walk; incoming: one step down over every key), the parents level by level, topmost first, with the notes of the outdated links of shown elements to them; the children as a tree, depth first in walk order, repeated places as leaves, the element itself where a cycle leads back to it among them (SR-107 AK3), opened rows below (`open`: the keys the reader opened, or `all` for the export), drawn from the shown elements only; the incoming links per key in the order they first appear, derivations left out, a link of the element to itself kept (SR-107 AK5); a link's source is looked up among the shown elements and the element itself. Option `bound` per part: the export's 100 parents and 100 children (SR-232 AK5), the app's `limit` of its calls (200 parents, 5000 children and incoming); `more` when the walk reached more or the answer is one page of more. Built with a stack, not recursion: a chain can be thousands of levels deep.
- Cost (N-036, SR-082): a builder works on one page's inputs; the export builds each model just before writing its page and keeps none. The neighbourhood is linear in its answers.
- Tests: the builders' own tests (`*.test.ts` here); `html-export/neighbourhood-input.test.ts` checks on one fixture that the export's walks and `trace.neighbourhood` give the same model (ADR-0019 point 2), with an element that points at itself and a cycle back to it; `fixtures/displays/neighbourhood.json` feeds `html-export/neighbourhood-render.test.ts` and the app's `neighbourhood-render.test.ts`, so each renderer shows every row and group of the same model.
