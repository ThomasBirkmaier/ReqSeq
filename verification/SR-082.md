## Per criterion

- **AK3 holds.** An open looks the element up in the loaded store, reads its one file and builds its view and parents line in memory. The code is the same JavaScript on the same Node on every system; the one file read is not where the time goes. The slowest tagged time is less than a quarter of the limit, a margin that the difference of the same JavaScript between systems on a machine of the size AK3 names does not use up.
- **AK1 does not carry over.** A new process (Node's start differs by system, slowest on Windows) reads the 94 MB model cache; the margin is less than two times. No measurement on macOS or Windows exists.
- **AK2 does not carry over.** Reading 50,000 element files without the cache depends on the file system (APFS, NTFS) and its filters (Windows Defender scans files as they are opened). No measurement on macOS or Windows exists.
- **AK4 does not carry over.** Most of it is in memory with a wide margin, but the sort by version date reads Git again after `HEAD` moved: a `git` process, whose start is much slower on Windows, at up to 369 ms of 500 ms on Linux. A criterion is shown whole or not at all.
- **AK5 does not carry over.** The first open reads a batch of element files for the versions, at 659 ms of 1 s on Linux: file reading with a margin of one and a half times.

A run of the suite's tagged tests on a macOS and a Windows machine of the size the criteria name would show AK1, AK2, AK4 and AK5.
