# SR-074: Oberfläche auf Englisch anzeigen

Verification method: Inspection. Record written by an agent (Claude Code) on 2026-11-05 for issue #81, branch `sr-074-english-ui`. Not confirmed yet: a human confirms it at stage acceptance (D-050).

> Gegeben App, Kommandozeile, API, MCP-Server und Dokumentation, wenn sie geprüft werden, dann sind alle Texte, Meldungen und Hilfen auf Englisch.

> Gegeben Elemente mit deutschem Inhalt, wenn sie angezeigt werden, dann zeigt das Tool den Inhalt unverändert.

## AK1: every text, message and help is in English

### How

1. Searched for German letters (ä, ö, ü, ß) and for the German glossary terms of the spec (Beleg, Prüfling, Durchführung, Begründung, Nachweis…, Fassung, Datensatz, Validierung, Gültigkeit, Anforderung, Abdeckung) in:
   - the command schemas and the shared schemas (`schemas/`), whose descriptions become the CLI help, the MCP tool descriptions and the API reference (`schemas/generated/`, `packages/core/src/generated/contracts.json`);
   - the causes and remedies of the problem codes (`schemas/problem-codes.yaml`);
   - the sources of all packages (`packages/*/src`), leaving out tests and comments;
   - the user guide (`docs/guide`).
2. Ran the built CLI's `--help` and read its first lines.

### Result

- **Found and fixed in this branch:** 24 descriptions in 9 schema files named a German term beside the English word or used it alone, for example "The item under test (Prüfling)", "Where the Beleg is", "the Nachweisgrad of a selection", "Fassung: normal-form version". They now read in English only. They were visible in the CLI help, the MCP tool descriptions and the API reference.
- **Kept automated:** `scripts/contracts/user-text.test.mjs` ("texts for users in English") fails when a description, summary or title of the generated contracts, or a cause or remedy of a problem code, holds a German letter or one of those terms.
- **Nothing else found:** in the sources outside comments, the German text is limited to comments that quote the German spec (`„…“`), which no user sees. The user guide has no German. The app's labels, menus and messages are English string literals in `packages/app/src/renderer` and `packages/app/src/main`. The window title is "ReqSeq".
- **Not covered by the search:** a German word without an umlaut outside the glossary list. A human reading the app, the CLI help and the guide judges that.

## AK2: German content is shown unchanged

### How

`reqseq element get N-041 --workspace spec` (the spec is a German ReqSeq workspace, D-064), as text and with `--json`. I compared the JSON `text` with the element's file in `spec/need/`.

### Result

The CLI shows the title "Fehlender Zugriff ist sichtbar" and the text as written, umlauts included. The JSON `text` is a substring of the file. Unit tests that write and read German content (`packages/core/src/files/write.test.ts`, `yaml-text.test.ts`, `commands/element/create.test.ts`, `workspace/init.test.ts`) keep it byte for byte; only paths and search compare in Unicode NFC, which changes no content shown. The app shows the same `element.get` output (ADR-0002).
