# SR-252: Web-Oberfläche in der Desktop-Hülle zeigen

Verification method: Test. The tests of AK2, AK6, AK7 and AK8 run on Linux only (#2449), so the macOS view (VAR-003) and the Windows view (VAR-001) got an analysis per criterion: does the Linux test also hold there? Record written by an agent (Claude Code) on 2026-11-23 for issue #2449, against `main` at `7a2f813`. Not confirmed yet: a person confirms it at the v0.14 acceptance (D-050).

**Result: for none of the four criteria does the Linux test carry over.** The shell's code and the web engine differ per system exactly where these criteria look, so this file prepares no record. AK1, AK3 to AK5, AK9 and AK10 have tests on all three systems.

## What differs per system

- **The web engine:** WebKitGTK on Linux, WKWebView on macOS, WebView2 on Windows (ADR-0021). Each starts its own processes, writes its own data and may connect by itself.
- **The shell's own code** (`packages/shell/shell/src/`): `unix.rs` (process group, output filter, opener call) serves Linux and macOS; `windows.rs` (Job Object, handle list, output filter, `ShellExecuteW`) serves Windows only. `engine.rs` switches off the engine's own connections with one block per system. `host.rs` calls `gtk::init` on Linux only.
- **The recording:** the Linux tests record with `strace -f` and a network namespace. ADR-0021 (Test seam) plans `eslogger` or `fs_usage` and pf on macOS, ETW through `logman` and firewall logging on Windows, with assumption A8 that they run on the hosted runners; the shell README says "no recorder yet" for macOS and Windows.

## AK2: the token in no argument, output or file of the shell

- Linux: `[SR-252/AK-nhyc] the token is in no argument, no output of the shell and no file it writes` in `packages/shell/e2e/shell.test.ts` (`describe.runIf(linux)`, `strace`), passed on `main@a6730d6` (`spec/evidence/ci/shell-ubuntu-24.04.xml`).
- macOS: the shell's arguments to the server and the output filter are the Unix code that Linux runs, and the server's arguments are fixed before the server prints the token (`start.rs`, unit test `the_server_is_node_with_the_cli_and_ui_no_open_in_the_root` on all three systems). Not shown: the processes WKWebView starts and the files the system writes for the app (WKWebView's processes are not started by the shell as on Linux), which the Linux test covers for WebKitGTK.
- Windows: the output filter and the start of the server are `windows.rs`, code that no test runs on Windows (the shell README: not in the coverage), and WebView2 starts `msedgewebview2.exe` processes with arguments of its own.
- **Does not carry over** to macOS or Windows.

## AK6: only the server, the engine, the dialogs and the opener; no workspace file

- Linux: `[SR-252/AK-cg77] reading and changing elements starts only the server and the engine and opens no workspace file`, same file and run. It accepts as engine only `webkit2gtk-4.1/WebKit(Web|Network|GPU)Process`.
- macOS and Windows: other engine processes, the opener is `/usr/bin/open` (macOS) or `ShellExecuteW` (Windows, `windows.rs`), and the dialogs are the system's own. What the shell starts and opens there is not recorded.
- **Does not carry over.**

## AK7: no connection to another machine, also none the engine makes by itself

- Linux: `[SR-252/AK-wfx8] showing pages and an element with a remote image and raw HTML connects to no other machine`, same file and run, which records the connections of WebKitGTK (DNS prefetching switched off in `engine.rs`).
- macOS: WKWebView's own connections (the fraudulent-website warning, switched off in `engine.rs`) are not recorded. Windows: WebView2's own connections (SmartScreen, background networking, component update, switched off by browser arguments in `engine.rs`) are not recorded. Whether these switches suffice is what AK7 asks; the Linux test says nothing about another engine.
- **Does not carry over.**

## AK8: the window cannot open: exit code, English reason, no server

- Linux: `[SR-252/AK-ts68] on Ubuntu 24.04 without libwebkit2gtk-4.1-0 the shell ends with 1, names the package and the reason, and starts no server` (`packages/shell/test/delivery/no-engine.test.ts`) and `[SR-252/AK-ts68] on a machine where the window cannot open, the shell ends with a code other than 0, an English reason, and no server` (`packages/shell/test/delivery/shell.test.ts`, skipped on macOS and Windows: "a start without a display is tested on Linux"), passed on `main@6542f58` (`spec/evidence/ci/delivery-ubuntu-24.04.xml`). The first runs the Linux launcher, the second the `gtk::init` branch of `host.rs`; both exist on Linux only.
- macOS and Windows: a window that cannot open reaches the shell's rules through Tauri (an error of the builder, or `WindowFailed` from `setup`). The rule itself, an English reason and exit code 1 without a server, is shown by the unit test `a_window_that_cannot_open_starts_no_server` in `packages/shell/shell/src/run.rs`, which runs on all three systems but is no tagged evidence. That Tauri reports the failure on these systems is not shown, and ADR-0021 assumption A3 records the opposite for one Windows case: started with `WEBVIEW2_BROWSER_EXECUTABLE_FOLDER` set to an empty folder, the release `ReqSeq.exe` neither ended nor wrote to standard error within 60 s (#2407).
- **Does not carry over.** On Windows AK8 may not be met.

## What would close the gap

The recordings ADR-0021 plans for macOS and Windows (AK2, AK6, AK7), and a start on macOS and Windows where the window cannot open (AK8). These are new test work, not records, and outside the answer to #2449 (no extra CI runs). Until then the four criteria stay open in the macOS and Windows views.
