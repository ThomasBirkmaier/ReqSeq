Verification method: Test. When #2449 was answered, the tests of AK2, AK6, AK7 and AK8 ran on Linux only, so the macOS view (VAR-003) and the Windows view (VAR-001) got an analysis per criterion: does the Linux test also hold there? That analysis was written by an agent (Claude Code) on 2026-11-23 for issue #2449, against `main` at `7a2f813`. The Windows parts below, and the section on the gaps of the Windows recording, were written by an agent (Claude Code) on 2026-11-23 for issue #2465 (PR #2481), against `main` at `3a29cc3`. Not confirmed yet: a person confirms it at the v0.14 acceptance (D-050).

**Result of #2449: for none of the four criteria does the Linux test carry over.** The shell's code and the web engine differ per system exactly where these criteria look, so this file prepares no record; the gap is #2465. AK1, AK3 to AK5, AK9 and AK10 have tests on all three systems.

**Windows since #2465:** AK2, AK6 and AK8 (the empty runtime folder) have tagged e2e tests on Windows; AK7 has its recorder and controls on Windows in an untagged test until question #2480 is answered. The sections below say what each covers and what stays open. macOS is still open in #2465.

## What differs per system

- **The web engine:** WebKitGTK on Linux, WKWebView on macOS, WebView2 on Windows (ADR-0021). Each starts its own processes, writes its own data and may connect by itself.
- **The shell's own code** (`packages/shell/shell/src/`): `unix.rs` (process group, output filter, opener call) serves Linux and macOS; `windows.rs` (Job Object, handle list, output filter, `ShellExecuteW`) serves Windows only. `engine.rs` switches off the engine's own connections with one block per system. `host.rs` calls `gtk::init` on Linux only.
- **The recording:** the Linux tests record with `strace -f` and a network namespace. On Windows the e2e suite records with the audit of process creation (4688), the ETW provider Microsoft-Windows-Kernel-File through `logman`, firewall program rules with the audit of refused connections (5157) and the DNS client log (3006) (`packages/shell/e2e/record-windows.ts`, ADR-0021 Test seam). ADR-0021 plans `eslogger` or `fs_usage` and pf on macOS; there is no recorder there yet.

## AK2: the token in no argument, output or file of the shell

- Linux: `[SR-252/AK-nhyc] the token is in no argument, no output of the shell and no file it writes` in `packages/shell/e2e/shell.test.ts` (`describe.runIf(linux)`, `strace`), passed on `main@a6730d6` (`spec/evidence/ci/shell-ubuntu-24.04.xml`).
- macOS: the shell's arguments to the server and the output filter are the Unix code that Linux runs, and the server's arguments are fixed before the server prints the token (`start.rs`, unit test `the_server_is_node_with_the_cli_and_ui_no_open_in_the_root` on all three systems). Not shown: the processes WKWebView starts and the files the system writes for the app (WKWebView's processes are not started by the shell as on Linux), which the Linux test covers for WebKitGTK.
- Windows: `[SR-252/AK-nhyc] the token is in no argument, no output of the shell and no file it writes (Windows)` in `packages/shell/e2e/shell.test.ts`. It runs `windows.rs` (output filter, start of the server) and records the command lines of the shell's whole process tree, WebView2's included, and the files the tree outside the server creates or writes, read back for the token as UTF-8 and UTF-16. Each write is named from the Create or NameCreate before it in the trace, and a write the trace names no file for fails the test. Controls: the trace lost no buffer or event, the engine's renderer is in the process tree, the server's opens of the workspace file and the engine's Write events in its data folder are in the record. Gaps: see below.
- **Does not carry over** to macOS.

## AK6: only the server, the engine, the dialogs and the opener; no workspace file

- Linux: `[SR-252/AK-cg77] reading and changing elements starts only the server and the engine and opens no workspace file`, same file and run. It accepts as engine only `webkit2gtk-4.1/WebKit(Web|Network|GPU)Process`.
- Windows: `[SR-252/AK-cg77] reading and changing elements starts only the server and the engine and opens no workspace file (Windows)`, same file. Every process the shell's tree starts outside the server must be `msedgewebview2.exe` of an installed WebView2 runtime, and no process outside the server may create or open a path in the workspace; same controls as AK2. The opener and the dialogs are not used in this run (AK3 and SR-253 have their own tests).
- macOS: other engine processes, the opener is `/usr/bin/open`, and the dialogs are the system's own. What the shell starts and opens there is not recorded.
- **Does not carry over** to macOS.

## AK7: no connection to another machine, also none the engine makes by itself

- Linux: `[SR-252/AK-wfx8] showing pages and an element with a remote image and raw HTML connects to no other machine`, same file and run, which records the connections of WebKitGTK (DNS prefetching switched off in `engine.rs`).
- macOS: WKWebView's own connections (the fraudulent-website warning, switched off in `engine.rs`) are not recorded. Whether these switches suffice is what AK7 asks; the Linux test says nothing about another engine.
- Windows: the untagged test `SR-252 AK7 recorder (Windows): ...` in the same file refuses every connection of the shell, the server (a copy of `node.exe`) and `msedgewebview2.exe` to an address other than loopback, and records refusals (5157) and name lookups (3006). Controls: the control process's connection to `192.0.2.1` is refused and recorded with its program, its lookup is recorded, the firewall profiles are on, and every engine program in the record is one the rules refuse. The engine's network service looks up `wpad` by itself (proxy auto-detection) through the DNS client service, which no program rule refuses; whether that counts as a connection is question #2480, so the test is no evidence yet. Not covered on Windows: what services make on the engine's behalf besides lookups (the WinHTTP auto-proxy service), and IPv6, since the runner has only link-local IPv6.
- **Does not carry over.**

## AK8: the window cannot open: exit code, English reason, no server

- Linux: `[SR-252/AK-ts68] on Ubuntu 24.04 without libwebkit2gtk-4.1-0 the shell ends with 1, names the package and the reason, and starts no server` (`packages/shell/test/delivery/no-engine.test.ts`) and `[SR-252/AK-ts68] on a machine where the window cannot open, the shell ends with a code other than 0, an English reason, and no server` (`packages/shell/test/delivery/shell.test.ts`, skipped on macOS and Windows: "a start without a display is tested on Linux"), passed on `main@6542f58` (`spec/evidence/ci/delivery-ubuntu-24.04.xml`). The first runs the Linux launcher, the second the `gtk::init` branch of `host.rs`; both exist on Linux only.
- macOS and Windows: a window that cannot open reaches the shell's rules through Tauri (an error of the builder, or `WindowFailed` from `setup`). The rule itself, an English reason and exit code 1 without a server, is shown by the unit test `a_window_that_cannot_open_starts_no_server` in `packages/shell/shell/src/run.rs`, which runs on all three systems but is no tagged evidence. That Tauri reports the failure on these systems is not shown, and ADR-0021 assumption A3 records the opposite for one Windows case: started with `WEBVIEW2_BROWSER_EXECUTABLE_FOLDER` set to an empty folder, the release `ReqSeq.exe` neither ended nor wrote to standard error within 60 s (#2407).
- Windows: `[SR-252/AK-ts68] with an empty WebView2 runtime folder the shell ends with 1, names the reason in English, and no server runs` in `packages/shell/e2e/shell.test.ts` starts the e2e build with `WEBVIEW2_BROWSER_EXECUTABLE_FOLDER` set to an empty folder: exit code 1, the reason of the builder error on standard error (not the fixed line of the panic hook, which a release build reaches by abort), no page, and no process left whose parent was the shell. Open in #2477: the release `ReqSeq.exe` under the same condition, and the shell that neither ends nor prints a reason with an unwritable user data folder or an engine process that cannot start.
- **Does not carry over** to macOS. On Windows AK8 is not met for every way the window can fail (#2477).

## Gaps of the Windows recording

These hold for the Windows tests of AK2 and AK6 and are not shown by them:

- A file written and deleted before the test reads it back counts as gone, not as holding the token (the Linux test reads files back the same way).
- Paths are compared without their alternate data stream, so the token is looked for in the main stream of `file:stream`, not in the stream itself.
- Writes the Kernel-File provider does not log as Write events, such as writes through a mapped view, are not checked.
- A program started through a broker (COM, WMI, a ShellExecute that explorer carries out) is not a descendant of the shell in the process creation events, so its arguments (AK2) and its start (AK6) are not checked.
- Paths on a network share (`\Device\Mup`) are not mapped to a drive and are not read back.

## What would close the gap

On macOS the recordings ADR-0021 plans (AK2, AK6, AK7) and a start where the window cannot open (AK8), tracked in #2465. On Windows the answer to #2480 for AK7 and the fix of #2477 for AK8.
