## AK3: Mermaid draws the graph without an error, with every node, edge and title

### Linux evidence

- `[SR-151/AK-n1xs] draws the graph of 50 nodes and 100 edges with special characters in its titles, with every node, edge and title` and `[SR-151/AK-n1xs] draws the metamodel graph of the standard model, with every type, edge and label` in `packages/web/test/mermaid-render.spec.ts`, in Chromium, passed on `main@a6730d6` (`spec/evidence/ci/web-ubuntu-24.04.xml`).
- The `web` job of CI runs only on `ubuntu-24.04` (`.github/workflows/ci.yml`). The macOS and Windows views show AK3 as outdated: their last evidence of it is for an older version of SR-151.

### Why it holds on macOS and Windows

- **The input is the same bytes on every system.** The Mermaid text comes from core (`trace.mermaid`, `metamodel.mermaid`), which writes the same bytes on every platform: LF, no trailing spaces, a final newline (`packages/core/src/graph/mermaid.ts`, SR-151 AK4). AK4, which compares the output across the accesses, passes on all three systems.
- **The drawing is JavaScript in a browser.** The test loads the Mermaid build that ReqSeq ships (`packages/core/vendor/html-export/mermaid.js`) into an empty page and calls `mermaid.render`. Mermaid parses the text and builds the SVG in JavaScript; whether it reports an error and which nodes, edges and title texts the SVG holds does not depend on the operating system.
- **What can differ, and does not count.** Fonts and text measuring differ per system, so the size and position of the boxes can differ. AK3 asks for no error and for every node, edge and title character for character, which the test reads from the SVG's text and structure, not from pixels.

AK3 holds on macOS and Windows by this analysis.
