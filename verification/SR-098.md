- Nightly run [45160916771](https://github.com/ThomasBirkmaier/ReqSeq/actions/runs/45160916771) on `fb84753`, on a runner with 4 cores and 16 GB, the machine AK1 names: the slowest tagged median is 163 ms of 300 ms (`verification/performance.md` on the branch `perf-record`). The evidence in `spec/evidence/ci/perf-ubuntu-24.04.xml` is older (`c3750b6`) until the nightly results are published again (#2451).

### Why it holds on macOS and Windows

- **What is timed is mostly in memory.** `element.search` runs on the search index of the loaded workspace, built before the timing starts (`warmWorkspace`); a save carries the index in memory. Besides the index, a search reads the files of the hits of its page for their snippets (SR-174), at most 50 files, which the same search read before (median of 7 runs). It starts no program and opens no connection. The rest is the same JavaScript on the same Node on every system.
- **Margin.** The slowest tagged median is a little over half the limit, which leaves about 140 ms. The differences between systems for the same JavaScript on a machine of the size AK1 names are small against that; the part that depends on the file system is reading at most 50 files that the system has just read, where a slower file open (NTFS, a virus scanner) costs at most about a millisecond each, some tens of milliseconds for the page. This is an estimate, not a measurement on macOS or Windows.
- **Not covered:** single runs include pauses of the garbage collector and the scheduler (slowest single run on Linux 561 ms); AK1 is asserted, as on Linux, on the median.

AK1 holds on macOS and Windows by this analysis.
