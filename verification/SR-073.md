# SR-073: Mit der Tastatur bedienen

Verification method: Demonstration. Record written by an agent (Claude Code) on 2026-10-28 for issue #85, branch `sr-073-demonstration-record`. **Not confirmed.** A human confirms it at stage acceptance (D-050, the UI gate of N-032, #8).

> Die App muss vollständig mit der Tastatur bedienbar sein.

The requirement derives from N-032. ADR-0010 ("Minibuffer") and `packages/app/README.md` ("Keys") give the keys; the record checks them against the code and the Electron tests of the app.

## On which build and workspace

- **Build:** `main` at commit `b27449d` (2026-10-28), built with `pnpm build` and `pnpm --filter @logreq/app build:electron`, run on Linux (Electron 44, Xvfb, the window of the tests).
- **Workspaces:** the fixture "Weather station" (`fixtures/SR-069/filter`) of the Electron tests named below, and a copy of the specification of LogReq (`spec/`) for the screenshots of SR-100 and SR-110 this record reuses.
- **Run by the agent for this record:** `packages/app/test/command-line.spec.ts` (3 tests, keys only, no mouse), which wrote `SR-073/catalog-prompt.png`. The other Electron tests named below ran in CI on the same code; they were not run again here.
- **Searched:** `packages/app/src/renderer/actions.ts` (every action of the app, its title and its key), `catalog-commands.ts` (which catalog commands the prompt offers), `schemas/commands/catalog.json` and `packages/core/src/commands/` (which commands are implemented), and `spec/metamodel/spec-model.yaml` (properties of kind `relation` and relation kinds).

## AK1: create, search, filter, edit, set relations and confirm hints with the keyboard

> Gegeben die App, wenn sie ohne Maus bedient wird, dann lassen sich Anlegen, Suchen, Filtern, Bearbeiten, Beziehungen setzen und Hinweise bestätigen vollständig mit der Tastatur ausführen.

Every step is a Playwright test of the built app that presses keys only (`window.keyboard`, no `click` and no `mouse` in these tests unless named).

Every action of the app is in the command prompt by its name (AK2 below), so each has a keyboard path; the actions that a click also starts (a row of a list, a box of the graph, a link in the text or a relation box, the copy symbol of a field) have their keys too: Enter, the arrow keys of the graph (SR-111 AK5), Ctrl/Cmd+Enter ("Follow reference"), Ctrl/Cmd+Shift+C ("Copy field"). ### Result

Anlegen, Suchen, Filtern and Bearbeiten (title, text, properties) work with the keyboard alone. Beziehungen setzen works only for properties of kind `relation`, not for the relation kinds of the metamodel, and Hinweise bestätigen is not possible in the app. **Not met**; #718 is open for both (the rest of #85, PR 5b). Not confirmed.

## AK2: the command prompt finds every function of the app by its name

> Gegeben eine Befehlspalette, wenn sie per Tastenkürzel geöffnet wird, dann findet sie jede Funktion der App über ihren Namen.

"Befehlspalette" is the command prompt of the minibuffer, Ctrl/Cmd+Shift+P (`COMMAND_SHORTCUT`, `actions.ts` line 258); everywhere else the spec calls it „Befehlszeile“ (spec question #642, F3).

### What was demonstrated, step by step

1. **The functions the app has.** The prompt lists the actions of the app that apply to the shown buffer (`actions.ts`, from "Go to element or buffer" to "Stop following agent", each with its key as hint) and the catalog commands of `catalogItems` (`catalog-commands.ts` lines 665 to 690): every implemented read command and "Create element", each by its catalog `title`, except a command an action covers (by title or `covers`), which is listed once, by the action. A command that needs the selection of a list is offered only on a list (`offered`, line 132); the actions of other buffers (for example "Sort list" on an element) are offered where they apply (SR-133: „die Befehle der App zeigt sie nur dort, wo sie ausführbar sind“). The ranking is fuzzy (uFuzzy), and the initials of a name find it first (SR-108 AK1, SR-121 AK1).
2. **Run on the built app** (`test/command-line.spec.ts`, run for this record, all 3 tests passed): on an element, Ctrl/Cmd+Shift+P, "sro" finds "Show relation options" first; Ctrl/Cmd+Enter asks its argument `ref` with the shown element first, then the optional `kind` with exactly the kinds `logreq relation options` gives; "der" narrows them to "Derives from" (`SR-073/catalog-prompt.png`); Enter runs it and the output opens a result buffer. "flt" finds "Filter list by type" first. With nothing typed on an element, the commands with an element argument come first and "Show workspace status" below them (`[SR-133/AK1]`).
3. **Tests that support it:** `[SR-108/AK1] finds each action among the first three by its initials and by a typo, on the real names` (`src/renderer/actions.test.ts` line 281), `[SR-133/AK1] keeps every command reachable by search, fitting or not` (`src/renderer/usage.test.ts` line 335), "offers editing the title on an element whose buffer gives it, by its name (#621, SR-073 AK2)" (`actions.test.ts` line 146), the catalog commands of the prompt in `src/renderer/catalog-commands.test.ts` and `src/renderer/App.test.ts` ("App, catalog commands in the command prompt (#85)"), and the cross-access test that the bridge lists the catalog as the API does (`packages/cli/test/cross-access.test.ts` line 2302). Screenshots of the prompt: `SR-100/commands.png` ("sort" finds "Sort list") and `SR-100/jump.png` (Ctrl/Cmd+P).
4. **What the prompt does not find.** The catalog has 39 commands implemented in core (`packages/core/src/commands/`); 12 of them are write commands that the app does not offer at all, so the prompt cannot find them: "Create relation" (`relation.add`), "Remove relation" (`relation.remove`), "Confirm hints" (`hint.confirm`), "Set status" (`element.setStatus`), "Supersede element" (`element.supersede`), "Bulk update elements" (`element.bulkUpdate`), "Add attachment" (`element.addAttachment`), "Save filter" (`filter.save`), "Record evidence" (`evidence.record`, #597), "Enrich JUnit file" (`evidence.enrichJunit`), "Store data" (`data.store`) and "Initialise workspace" (`workspace.init`). "Update element" (`element.update`) is what "Save element", the boxes and the title do, under their own names. The example of SR-108 AK1, „crel“ for „Create relation“, has no command to find in the app today. The commands of baselines, variants and ReqIF are not implemented in core yet (stages 5 and 6) and are not counted.

**Assumption (finding F2):** a function of the catalog that the app does not offer still counts as a „Funktion der App“, because D-029 and SR-080 make every function available in the app, the CLI, the API and MCP with the same result. Read the other way ("only what the app already has"), AK2 would be met.

### Result

Every function the app has today is found by its name in the command prompt, with its key. The implemented write commands of the catalog other than "Create element" are not in the app and so not found. **Partly met** under the assumption above; #718 is open for them. Not confirmed.

## Findings

- **F1 (AK1):** relations of a relation kind cannot be set and hints cannot be confirmed in the app. Issue #718.
- **F2 (AK2):** the command prompt does not offer the implemented write commands of the catalog except "Create element". Issue #718 (with F1, both are the rest of #85, PR 5b).

## Known limits of this record

- Checked on Linux only; the macOS and Windows runs of the Electron tests are the CI's. The macOS keys (Cmd, the physical Ctrl+P and Ctrl+T in the text editor) are the ones ADR-0010 names; they were not tried by hand.
- One Electron spec was run for this record; the others named are the CI's runs of the same code.
- No screen reader or focus-order audit; AK1 asks for the activities with the keyboard, not for accessibility in general.
- **A human repeats it** at stage acceptance, without a mouse: open a workspace (Ctrl/Cmd+O or "Open workspace"), create an element, search it, filter the list, edit its title, text and a property, set a package, and try to set a "Derives from" relation and confirm an outdated hint (both are expected to fail until #718 is done).
