## Where the description is delivered

The format pages are generated by `packages/docs/src/formats.ts` (list `FORMATS`, 15 formats) from `schemas/<format>.schema.json` with the example files of `schemas/examples/<format>/`; `checkFormats` fails the build when a schema is not in the list. Every delivery ships the offline build of the documentation site (SR-141): `.github/workflows/release.yml` (job `docs-site`) builds it, and `scripts/package/stage.mjs` puts it into `lib/docs/` of the archives and `docs/` of the CLI tarball.

Checked: the CLI tarball of the latest release, v0.12.0 (`reqseq-cli-0.12.0.tgz`), contains `package/docs/reference/formats/<format>/index.html` for all 15 formats of `FORMATS`.

## AK1: a description of every field with an example for each format

> Gegeben die Auslieferung des Tools, wenn sie geprüft wird, dann enthält sie für Element, Metamodell, Zuordnung, Filter, Perspektive, Baseline, Arbeitsbereich, lokale Datei des Arbeitsbereichs, Datensatz, die Datei der Daten je Stand (SR-062) und die Dateien im Ordner des Zwischenspeichers für Adresse und Token der API, Aktivität, verbundene Agents und zuletzt geöffnete Arbeitsbereiche je eine Beschreibung aller Felder mit Beispiel.

### How

I matched `FORMATS` with the formats of the AK and generated the pages (`node packages/docs/dist/bin.js`, into `packages/docs/site/src/content/docs/reference/formats/`). A script collected every property name of each schema, in `properties` at any depth (`$defs`, `items`, `allOf`, `anyOf`, `oneOf`, `additionalProperties`), and looked for a row of that field in the field tables of its page (rows name nested fields by path, such as `attributes[].omit-values`), and for every example file of the format under its own heading on the page. I read the rows the script did not find. `pnpm vitest run packages/docs/src/formats.test.ts packages/docs/src/reference.test.ts packages/docs/src/schema-fields.test.ts`: 21 passed.

### Result

| Format in the AK | Schema | Examples on the page | Fields described |
|---|---|---|---|
| Element | `element.schema.json` | 3 of 3 (`.md`) | yes |
| Metamodell | `metamodel.schema.json` | 1 of 1 | yes |
| Zuordnung | `reqif-mapping.schema.json` | 1 of 1 | yes |
| Filter | `filter.schema.json` | 1 of 1 | yes, with one table per form of `condition` |
| Perspektive | `perspective.schema.json` | 2 of 2 | yes |

| Arbeitsbereich | `workspace.schema.json` | 1 of 1 | yes |

| Datensatz | `evidence-record.schema.json` | 3 of 3 (`.md`) | yes |

`html-export-marker` is the fifteenth format of `FORMATS`; the AK does not name it, and its page has every field and its example.

**Gap.** In `workspace-local.schema.json`, each value of `repositories` (an `additionalProperties` object per repository name) has the required field `path` ("Absolute path, or relative to the main repository … No `~` expansion."). The page `reference/formats/workspace-local` has rows for `reqseq-local` and `repositories` only; `path` appears in the example, not in a field table, and its description is on no page. `fieldRows` in `packages/docs/src/schema-fields.ts` follows `properties` and `items`, not `additionalProperties`, and this is the only schema where an `additionalProperties` value has fields of its own. The delivered page of v0.12.0 has the same two rows. All other properties of the 15 schemas have a row.

AK1 is not met until `path` is described on the page (#2456).

## AK2: a file made only from the description is read without error

> Gegeben eine Datei, die nur nach dieser Beschreibung von Hand erstellt wurde, wenn das Tool sie liest, dann meldet es keinen Fehler.

### How

In a temporary folder I made two Git repositories from the format pages and their examples only: `system` with `reqseq-workspace.yaml` (metamodel in the repository `metamodel`), `.reqseq/local.yaml` pointing to that repository, the three element files, the three evidence records, the two baselines, the filter, the two perspectives and the ReqIF mapping; `metamodel` with the metamodel of the page. I wrote a third perspective by hand (`where: { type: [need] }`, a sort with `order: desc`, a comment). With `XDG_CACHE_HOME` set to a temporary folder, I wrote by hand `activity.json` and `agent-4242-0a1b2c3d.json` into `<cache>/reqseq/<sha256 of the workspace root>/`, `recent-workspaces.json` into `<cache>/reqseq/`, a data file per state `<commit>.jsonl` with one line as `$defs/line` describes it, and `api.json` with the port, token and process ID of a running `serve api`. Then I ran the built CLI:

- `workspace status`, `workspace check`, `element list`, `filter list`, `perspective list`, `baseline list`, `metamodel get`;
- `reqif import fixtures/SR-056/delivery/lieferung-1.reqif d1 --mapping reqif/customer-acme.yaml`;
- `data store data` with the commit of the hand-made data file (the tool reads an existing file of that name and replaces it only if it is a data file per state);
- `workspace activity`, `workspace agents`, `workspace recent`;
- a second `serve api` start, and `GET /v1/commands` with the token of the hand-made `api.json`.

### Result

- No file gave `file.faulty` or another reading error. `workspace status` reports the metamodel valid and both repositories found through the local file; `element list` shows the three elements, `filter list` the filter, `perspective list` all three perspectives, `baseline list` both baselines; `reqif import` created 4 elements through the mapping.
- `workspace check` reports content findings only, about the data, not about reading the files: two `relation.missing-target` errors (the examples name a variant and a package that the example set does not hold), an unknown property `customer-id` (the element example shows that ReqSeq keeps unknown properties), missing criterion keys, outdated versions and records after the copy, and a missing parent.
- `data store` replaced the hand-made data file. Control: a file of that name with other content was refused ("is not a ReqSeq data file").
- `workspace activity` returned the access of the hand-made file; `workspace agents` showed the client `hand-written` as connected; `workspace recent` returned both entries, with `exists: false` for a root that does not exist.
- The second `serve api` start read the hand-made `api.json` and refused with "A ReqSeq API for this working copy runs already at http://127.0.0.1:<port>"; the request with its token answered 200.

AK2 is met for every format of AK1.

## AK3: an example is read by a general parser without extensions

> Gegeben eine Beispieldatei, wenn sie mit einem allgemeinen Parser ihres Formats gelesen wird, YAML, Markdown, bei den Daten je Stand JSON Lines und bei den Dateien im Ordner des Zwischenspeichers JSON, dann gelingt das ohne Erweiterungen.

### How and result

- `pnpm schemas:check` (`scripts/contracts/validate-schemas.mjs`, run in CI) reads every example (`.json` with `JSON.parse`, `.yaml` and the front matter of `.md` with the library `yaml`, `.jsonl` line by line) and validates it against its schema: "schemas ok: 16 schemas, 81 commands, 111 examples".
- Independently, a script read the 23 example files of the 15 formats: `.json` with `JSON.parse`, `.jsonl` per line with `JSON.parse`, `.yaml` with `yaml` (YAML 1.2 core schema, strict, unique keys, no custom tags), `.md` front matter with `yaml` and the body with `micromark` (CommonMark, no extensions). A second script read them with Python's `json` and PyYAML `safe_load`, and found no GFM-only construct (tables, strikethrough, task lists) in a Markdown body. Result: 23 files read, no problem.
- The cache-folder examples are JSON (`api.json`, `activity.json`, `agent-41213-9f3c20ab.json`, `recent-workspaces.json`), the data file per state is JSON Lines.

AK3 is met.
