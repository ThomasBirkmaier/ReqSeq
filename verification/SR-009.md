## AK2: a file made only from the description is read without error

> Gegeben eine Datei, die nur nach dieser Beschreibung von Hand erstellt wurde, wenn das Tool sie liest, dann meldet es keinen Fehler.

### How

I made a workspace by hand in a temporary Git repository, from the descriptions and their examples only:
- `reqseq-workspace.yaml` written from the workspace page, with one repository and the metamodel in `model/`;
- `model/standard-model.yaml`, the three element files, the two evidence records, the filter and the two baselines, copied from the examples.

Then I ran the built CLI: `reqseq workspace check`, `element list`, `filter list` and `baseline list`.

### Result

- The first workspace file left out `url` of the repository. The tool refused it with `file.faulty … repositories[0].url is required`. The description marks `url` as required, so the description and the tool agree.
- With `url` added, every file was read: no `file.faulty` or other reading error. `element list` shows the three elements, `filter list` the filter and `baseline list` the baselines.
- `workspace check` reports content findings, which are about the data, not about reading the files. Two errors (`relation.missing-target`) come from the examples naming the Pro variant and a package that the example set does not contain. The warnings are outdated versions after the copy, a missing parent, and `customer-id`, a property the standard model does not have (the element example shows that ReqSeq keeps unknown properties).

## AK3: an example is read by a general parser without extensions

> Gegeben eine Beispieldatei, wenn sie mit einem allgemeinen YAML- oder Markdown-Parser gelesen wird, dann gelingt das ohne Erweiterungen.

### How and result

`scripts/contracts/validate-schemas.mjs` (`pnpm schemas:check`, run in CI) parses every example of `schemas/examples/` with the general YAML library `yaml`, with no custom tags or schema extensions, and validates each against its schema. For a Markdown file it parses the front matter between the `---` lines. Result on this branch: "schemas ok: 13 schemas, 49 commands, 22 examples". By reading, the bodies of the element and record examples are plain CommonMark (headings, paragraphs, lists, links), and the YAML examples use only standard YAML 1.2 (maps, lists, strings, flow style).
