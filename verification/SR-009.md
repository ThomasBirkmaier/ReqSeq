## AK2: a file made only from the description is read without error

> Gegeben eine Datei, die nur nach dieser Beschreibung von Hand erstellt wurde, wenn das Tool sie liest, dann meldet es keinen Fehler.

### How

In a temporary folder I made two Git repositories by hand from the format pages and their examples only: `reqseq-workspace.yaml` (main repository `system`, metamodel in its own repository `metamodel`), `.reqseq/local.yaml` pointing to that repository, the metamodel, the three element files, the three evidence records, the two baselines, the filter and the ReqIF mapping. Then I wrote the other files by hand from their pages and ran the built CLI on each:

- `workspace check`, `workspace status`, `element list`, `filter list`, `baseline list`, `metamodel get`;
- `reqif import <file> d1 --mapping reqif/customer-acme.yaml` with `fixtures/SR-056/delivery/lieferung-1.reqif`;
- a data file per state `<commit>.jsonl` with one line as `$defs/line` describes it, then `data store data` with the same commit (the tool reads an existing file of that name and replaces it only if it is a data file per state);
- with `XDG_CACHE_HOME` set to a temporary folder, `activity.json` in `<cache>/reqseq/<sha256 of the workspace root>/` and `recent-workspaces.json` in `<cache>/reqseq/`, then `workspace activity` and `workspace recent`;
- `api.json` written by hand with the port, token and process ID of a running `serve api`, then a second `serve api` start, and a request to `/v1/commands` with the token of the file.

### Result

- No file gave `file.faulty` or another reading error. `workspace status` reports the metamodel valid and both repositories found through the local file; `element list` shows the three elements, `filter list` the filter, `baseline list` both baselines; `reqif import` creates elements through the mapping.
- `workspace check` reports content findings only, which are about the data, not about reading the files: two `relation.missing-target` errors (the examples name a variant and a package that the example set does not contain), an unknown property `customer-id` (the element example shows that ReqSeq keeps unknown properties), missing criterion keys, outdated versions after the copy and a missing parent.
- `data store` replaced the hand-made data file. As a control, a file of the same name with other content was refused: "is not a ReqSeq data file".
- `workspace activity` returned the access of the hand-made `activity.json`; `workspace recent` returned both entries, with `exists: false` for a root that does not exist.
- The second `serve api` start read the hand-made `api.json` and refused with "A ReqSeq API for this working copy runs already at http://127.0.0.1:<port>"; the request with its token answered 200.
- Controls: a mapping file without `source` gave `file.faulty … source is required`, so the reading is checked against the description.

AK2 is met for every format of AK1. The AK2 run was made at `dbe9ab3c`. Up to `444b81e5`, the schemas changed only by added descriptions (filter conditions, baseline `title`, #1553); no example and no code that reads the files changed.

## AK3: an example is read by a general parser without extensions

> Gegeben eine Beispieldatei, wenn sie mit einem allgemeinen Parser ihres Formats gelesen wird, YAML, Markdown, bei den Daten je Stand JSON Lines und bei den Dateien im Ordner des Zwischenspeichers JSON, dann gelingt das ohne Erweiterungen.

### How and result

- `pnpm schemas:check` (`scripts/contracts/validate-schemas.mjs`, run in CI) reads every example: `.json` with `JSON.parse` (and a YAML 1.2 parser with unique keys, so no key appears twice), `.yaml` and the front matter of `.md` with the library `yaml` (YAML 1.2 core schema, no custom tags), `.jsonl` line by line with `JSON.parse`, and validates each against its schema (`.jsonl` lines against `$defs/line`). Result: "schemas ok: 13 schemas, 52 commands, 78 examples".
- Independently, a script read the 19 example files of the 12 formats: `.json` with `JSON.parse`, `.jsonl` per line with `JSON.parse`, `.yaml` with `yaml` (YAML 1.2 core, strict, unique keys), `.md` front matter with `yaml` and the body with `micromark` (CommonMark, no extensions), and checked that no body uses a GFM-only construct (tables, strikethrough, task lists). Result: 19 files read, no problem. Python's `json` and PyYAML `safe_load` also read all 19.
- The cache-folder examples are JSON (`api.json`, `activity.json`, `recent-workspaces.json`), the data file per state is JSON Lines (one JSON object per line).

AK3 is met.
