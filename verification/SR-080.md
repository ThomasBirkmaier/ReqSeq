## AK4: every value the web UI shows is available over CLI, API and MCP

### Linux evidence

- `[SR-080/AK-hn1m] every value the web UI shows is the output of a command the CLI and the MCP server give alike` in `packages/web/test/contract-queries.spec.ts`, in Chromium, Firefox and WebKit, passed on `main@a6730d6` (`spec/evidence/ci/web-ubuntu-24.04.xml`).
- The `web` job of CI runs only on `ubuntu-24.04` (`.github/workflows/ci.yml`).

### Why it holds on macOS and Windows

- **The test compares outputs, not systems.** It records the command calls of the pages and compares each value the page shows with the output of the same command through the CLI and the MCP server. Nothing in it is Linux tooling; the `unshare -rn` around the job only takes the network away.
- **The values come from one implementation.** Every value the pages show is the output of a catalog command with its one implementation in `packages/core/src/commands/` (ADR-0002); the server of the web UI, the CLI and the MCP server are adapters without logic of their own, the same JavaScript on every system. That the four accesses give the same result on macOS and Windows is shown there by SR-080 AK1 to AK3 (`packages/cli/test/cross-access.test.ts` and the e2e suite, on all three systems).
- **The pages are one bundle.** The sources of `packages/web/src` have one branch on the operating system, the label of the finder key (`packages/web/src/areas/lists.ts`), which is no value of the workspace or a setting.

AK4 holds on macOS and Windows by this analysis.
