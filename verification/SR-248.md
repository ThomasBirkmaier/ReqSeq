## What is the same on every system

- **The server** is `reqseq ui` of the built CLI: `packages/api` (`ui-server.ts`) and `packages/core`, the same JavaScript on every system (ADR-0002, ADR-0020).
- **The pages** are one bundle (`packages/web`, vite build). The sources of `packages/web/src` and `packages/api/src` have one branch on the operating system, the label of the finder key (`packages/web/src/areas/lists.ts`).

## Per criterion

- **AK1:** the test gives the server a command runner whose outputs differ from the files and compares the page with those outputs. The page shows what the commands give; nothing in that depends on the system. Holds.
- **AK2:** the recorder (`packages/testkit/preload/record-access.mjs`, `packages/testkit/src/access-record.ts`) wraps `node:child_process` and `node:fs` in the server's process and names the step from the stack frames, with patterns for both `/` and `\` (`STEP_FRAMES`); it is not Linux tooling. One part of the server differs by system: the watcher of changed files (SR-007) puts a plain watch on every folder on Linux and one recursive watch per repository on macOS and Windows (`packages/core/src/model/watch.ts`). Both are the step "watcher" that AK2 allows (`model/watch*.js`), and the files a detected change makes the server read are read by the same code on every system; SR-007 is verified on all three systems. Git is started only by catalog commands and the open of the workspace, the same code on every system. Holds.
- **AK3:** the test records the pages' command calls (`recordCommandCalls`); which calls the pages make is the bundle's logic. Holds.
- **AK4:** the refusal comes from one check in core (`packages/core/src/workspace/local-paths.ts`), which the server applies as the API does; the test asserts the same code and details as over the API. Paths on Windows (drive letters, case, `\`) are handled in that check, and SR-142 AK1, the same boundary over the API and the MCP server, is verified on macOS and Windows by its tests there. Holds.
- **AK5:** what the pages render from element content (raw HTML as text, links, images, SVG, Mermaid) is the bundle's logic in the browser; loads to another machine are recorded by Playwright's `context.route` and by the network block of the tests in the server (`scripts/test-support/block-network.mjs`). Holds.

All five criteria hold on macOS and Windows by this analysis.
