> Das Tool muss als Desktop-App mit Kommandozeile für Windows, macOS und Linux ausgeliefert werden.

## The reading

D-003: "Das Tool ist eine installierte App. Kein Browser, keine Mobil-Version."

The delivery is one portable artifact per system, with no installer; unpacking the artifact is installing it. Linux gets a tar.gz. So "wenn die Auslieferung installiert wird" (AK1) and "in einem Netz ohne Internet installiert wird" (SR-078 AK2) mean: the artifact is unpacked into a folder. ADR-0014 has the layout, the names and the reasons; `docs/guide/how-to/install-reqseq.md` (Install ReqSeq) is the user's guide.

| System | Artifact | Built on | Contents |
|---|---|---|---|
| macOS (arm64) | `ReqSeq-<v>-mac-arm64.zip` | GitHub `macos-26` | `ReqSeq.app`, launcher `Contents/Resources/bin/reqseq` |
| Linux (x64) | `ReqSeq-<v>-linux-x64.tar.gz` | GitHub `ubuntu-24.04` | folder with `ReqSeq`, `chrome-sandbox`, `bin/reqseq`, `resources/` |
| Windows (x64) | `ReqSeq-<v>-win-x64.zip` | GitHub `windows-2025` | `ReqSeq.exe`, launcher `bin\reqseq.cmd`, `resources\` |
| Node 22 pipelines | `reqseq-cli-<v>.tgz` | GitHub `ubuntu-24.04` | command line and MCP server |

All names come from `toolchain/packaging/names.json`.

## AK1: the app starts after installation on Windows 11, macOS 26 and Ubuntu 24.04

> Gegeben je ein Rechner mit Windows 11, macOS 26 und Ubuntu 24.04, wenn die Auslieferung installiert wird, dann startet die App auf allen drei.

### How

`[SR-076/AK-sngx] the app of the <system> delivery starts after unpacking` (`packages/app/test/delivery/start.test.ts`) unpacks the artifact into a temporary folder (`ditto` on macOS, `tar` on Linux and Windows), on Linux, where the user may not create user namespaces (Ubuntu 24.04 as shipped), takes the documented admin step for `chrome-sandbox` with `sudo -n` (root-owned, mode 4755), and starts the packaged binary as a normal user with Chromium's sandbox on (never `--no-sandbox`), on a copy of `fixtures/SR-004/one-repository`, with its own home, cache, config and user data folders. The packaged app has Node's inspect arguments switched off (fuse), so the test connects through Chromium's DevTools port (`--remote-debugging-port=0`, `DevToolsActivePort`) and waits for the overview of the workspace. If no port opens, it falls back to: the app still runs after 10 s and the workspace is in the recent list the app writes into the test's own cache folder. The JUnit file names the way taken and the sandbox used (test annotation).

### Where it runs

Every run of `Release` (tag or by hand) builds and tests each system on GitHub's runner, in the job `build (<image>)`:

| Job | System | Counts for |
|---|---|---|
| `build (macos-26)` | macOS 26 on Apple silicon | macOS 26 |
| `build (ubuntu-24.04)` | Ubuntu 24.04 x64 as GitHub ships it (whether the `chrome-sandbox` admin step was needed there is in the test annotation) | Ubuntu 24.04 |
| `build (windows-2025)` | Windows Server 2025 x64 | Windows, but not Windows 11 itself: the human judges whether Windows Server 2025 counts for Windows 11 |

## AK2: the delivery contains app, command line and MCP server for all three systems

> Gegeben die Auslieferung, wenn sie geprüft wird, dann enthält sie App, Kommandozeile und MCP-Server für alle drei Systeme.

### How

- `[SR-076/AK-z5f8] the <system> delivery contains the app, the launcher, the command line and the MCP server` (`packages/cli/test/delivery/delivery.test.ts`) inspects the unpacked artifact with the testkit inspector (`packages/testkit/src/delivery.ts`): the app binary and `app.asar` (main process, core's code fingerprint), the launcher with its exec bit, the command line (`resources/cli/dist/bin.js`) with `@reqseq/mcp`, `@reqseq/api` and core (fingerprint, read worker), `THIRD_PARTY_NOTICES.txt` naming `@dagrejs/dagre` and `@dagrejs/graphlib` (ADR-0015), the JUnit guide, no update configuration or updater, no source maps, type declarations or TypeScript build info, the Electron fuses of ADR-0014 (RunAsNode on, Node options and inspect arguments off, app only from the asar), on Linux the exec bits of `ReqSeq` and `chrome-sandbox`, on macOS `codesign --verify --deep --strict` (an ad-hoc signature that does not verify makes macOS call the app damaged).
- `[SR-076/AK-z5f8] the launcher of the <system> delivery runs the command line and the MCP server` runs the unpacked launcher: `workspace status --json` on a fixture workspace gives its status, and `reqseq mcp` answers an MCP client with the catalog's tools and the status.

### Where it runs

Both tests run in each build job on its own artifact (`macos-26`, `ubuntu-24.04`, `windows-2025`). A test whose artifact is missing or whose system differs is skipped with its reason.

### Result

Both tests passed in each of the three build jobs of the `v0.7.2` release run (table under AK1).

## SR-078 AK2: installation without network

> Gegeben die Auslieferung, wenn sie in einem Netz ohne Internet installiert wird, dann gelingt die Installation ohne Nachladen.

- `[SR-078/AK-n50j] the <system> delivery installs without network and its app starts` and `... its command line and MCP server run`: on Linux the whole suite runs in a network namespace with loopback only (`scripts/package/delivery-tests.sh`: made by root, the tests run as the normal user, so Chromium keeps its sandbox). The script marks the namespace with `REQSEQ_DELIVERY_OFFLINE=1`; on Linux these tests fail without it, and first check that only loopback is there and a connect to a public address fails (ENETUNREACH); the test unpacks the artifact there and starts the app, the command line and the MCP server. They run in `build (ubuntu-24.04)`. macOS and Windows have no network namespace: no SR-078 AK2 run there.
- `[SR-078/AK-n50j] the CLI tarball installs without network and runs on Node`: `npm install --global --offline` of `reqseq-cli-<v>.tgz` in the same namespace (its dependencies are bundled), then the command line and the MCP server on plain Node. Runs in `build (ubuntu-24.04)`.

## Limits

- The Ubuntu 24.04 app start needs one admin step (`chrome-sandbox` owned by root with mode 4755, or an AppArmor profile; `docs/guide/how-to/install-reqseq.md`). The test takes that step as an administrator would.
- Windows evidence comes from Windows Server 2025, not from Windows 11.
- No test runs the packaged app for an hour or records its traffic (SR-078 AK1 is tested elsewhere).
