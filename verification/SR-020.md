# SR-020: Bestand schnell prüfen

Verification method: Test. An agent (Claude Code) wrote this record on 2026-10-24 for issue ThomasBirkmaier/ReqSeq-archive#32, branch `sr-020-fast-check`. It says what the test measures and where its result is recorded. **Confirmed** by the product owner at the quality gate before stage 5.

> Gegeben ein Arbeitsbereich mit 50.000 Elementen und 200.000 Beziehungen auf einem Rechner mit 4 Kernen und 16 GB Speicher, wenn die Prüfung über die Kommandozeile läuft, dann ist sie nach höchstens 60 Sekunden fertig.

## Test

- AK1: `[SR-020/AK-srb3] checks the workspace from the command line in at most 60 s` in `packages/cli/test/perf/workspace-check.test.ts`. It is part of the performance suite (`pnpm test:perf` after `pnpm build`, ADR-0011), which runs nightly and on pull requests labelled `perf`. The workflow runs it on `ubuntu-24.04` inside `unshare -rn`, so there is no network.
- Workspace: the generated workspace of `packages/testkit` (D-055, seed 36). It has 50,000 elements and 200,000 relations with valid versions, in four repositories, written to a new temporary folder.
- What is timed: one new process of the built CLI, `reqseq workspace check --json`, from spawn to exit. That includes Node start, reading every file, every finding state of stage 1 and the JSON output. The process gets an empty cache folder of its own and loads the network block (SR-077).
- Asserted: exit code 0, nothing on stderr, `{ ok: true, problems: [], checkedElements: 50000 }`, and a time of at most 60 s. The test is tagged, so it asserts its threshold (ADR-0011). The time is also recorded in `verification/performance.md` on the branch `perf-record` (#340).

## macOS and Windows (#2449)

Analysis written by an agent (Claude Code) on 2026-11-23 for issue #2449, against `main` at `7a2f813`. Not confirmed yet: a person confirms it at the v0.14 acceptance (D-050). The question: does the Linux measurement of AK1 also hold in the macOS view (VAR-003) and the Windows view (VAR-001)? The performance suite runs on `ubuntu-24.04` only.

- **Linux evidence:** the three AK1 tests of `packages/cli/test/perf/workspace-check.test.ts` (`[SR-020/AK-srb3] checks the workspace from the command line in at most 60 s`, `... in which every relation is outdated ...`, `... with its evidence records ... (SR-230 AK2)`), nightly run [45160916771](https://github.com/ThomasBirkmaier/ReqSeq/actions/runs/45160916771) on `fb84753`, on a runner with 4 cores and 16 GB: 10.3 s, 19.5 s and 14.4 s against 60 s (`verification/performance.md` on the branch `perf-record`). The evidence in `spec/evidence/ci/perf-ubuntu-24.04.xml` is older (`c3750b6`) until the nightly results are published again (#2451).
- **What is the same:** the command is the same JavaScript on every system, on the same version of Node.
- **What is not:** AK1 is a new process that reads 50,000 element files without the cache, so its time is mostly process start and reading many small files. Both depend on the system: the file system (APFS, NTFS), the file-system filters (Windows Defender scans files as they are opened), and the start of a process. No measurement on macOS or Windows exists. A margin of three times on Linux does not show that reading 50,000 files on NTFS with a virus scanner stays within 60 s.
- **Result: does not carry over.** This file prepares no record for macOS or Windows. A run of the suite's AK1 tests on a macOS and a Windows machine of the size AK1 names would show it.
