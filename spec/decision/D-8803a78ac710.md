title: "Varianten über eine Gültigkeitsliste"
spec-id: "D-020"
---

Jedes Requirement hat eine Gültigkeit: die Liste der Varianten, für die es gilt. Ohne Angabe gilt es für alle.

Ersetzt eine Variante ein Requirement des Kerns, zeigt das neue Requirement mit der Beziehung „ersetzt“ auf das alte. Gültigkeit und „ersetzt“ gehören zu den fest eingebauten Bedeutungen des Metamodells (D-012).

Ein Merkmalsmodell gibt es im Tool nicht. Wer eines braucht, pflegt es in einem anderen Werkzeug und überträgt das Ergebnis als Liste.

Liegt eine Variante in einem eigenen Repository, setzt sie Beziehungen auf den Kern wie über jede Repository-Grenze ([N-040](reqseq:6adc4fbb-04b5-4bda-a110-17ed577eb713?version=n1:ec82dab993b4b934)). Welcher Stand des Kerns gilt, regelt die Versionsverwaltung. Ändert sich der Kern, erkennt das Tool das über den Prüfwert ([D-013](reqseq:6adc4946-b44c-4ae1-8dbf-fb9e88b8c607?version=n1:0c3f2da31ca1ae9a)).

Eine Variante baut nur auf dem Kern auf, nicht auf einer anderen Variante. Jede Variante ist ein eigenes Element mit fester ID, und die Gültigkeit verweist auf diese IDs, nicht auf frei geschriebene Namen. So lässt sich das später erweitern, ohne vorhandene Gültigkeitslisten zu ändern.

Grund: Eine Liste ist leicht zu lesen und in Markdown einfach abzubilden. Sie deckt [N-017](reqseq:6ad3a38f-4289-49af-8017-ed7811529bd5?version=n1:22ae739d45e2453d) bis [N-022](reqseq:6ad3a4c6-cb89-4fc6-acdf-ff0c8aad33ed?version=n1:0d48a780647af98d) ab. Ein Merkmalsmodell bräuchte einen eigenen Editor und würde den Basisumfang groß machen.
