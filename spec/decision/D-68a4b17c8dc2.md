Agents dürfen in allen Repositories des Projekts selbst committen und mergen. Jede Änderung, auch eine kleine, läuft über einen Pull Request, den der Agent selbst mergt, wenn die Pflichtprüfungen grün sind und das Review durch einen zweiten Agenten nichts Blockierendes findet. Im Repository von ReqSeq sperrt main Force-Push und Löschen und verlangt die Prüfungen static sowie checks und electron jeweils auf ubuntu-24.04, macos-26 und windows-2025.

Das gilt auch für Schemas, Architekturentscheidungen, Regeln für Agents, Skills und die Pipeline. Solche Pull Requests meldet der Agent dem Produktverantwortlichen, wartet aber nicht auf ihn.

Der Produktverantwortliche beantwortet Rückfragen zur Spec und nimmt jede Stufe ([D-035](reqseq:6adc6f46-bc08-4598-9b30-474383c78014?version=n2:6facaf59f99e82fc)) ab. Die Architektur ([D-052](reqseq:6adc723f-2ec5-40bf-a21e-82712e92cfc7?version=n2:65283a967ea08d99)) sieht er bei der Abnahme von Stufe 0.

Grund: Nur so läuft der Bau ohne Warten. Pflichtprüfungen, kleine Pull Requests und die Abnahme je Stufe halten das Risiko klein. Seit 2026-10-29 ist main geschützt, und der direkte Weg auf main entfällt. Seit 2026-10-30 ersetzt macos-26 das Image macos-14, damit seltener umgezogen werden muss; GitHub schaltet macos-14 am 2026-11-02 ab.
