title: "Fest eingebaute Bedeutungen des Metamodells"
spec-id: "D-012"
---

Einige Bedeutungen sind fest eingebaut und lassen sich nicht ändern: Jedes Element hat ID und Typ; welche Statuswerte es haben kann, legt sein Typ fest ([D-030](reqseq:6adc615b-272a-4377-82e5-9ae991d75bb2?version=n2:5086a4bc7d6ff7de), [D-045](reqseq:6adc6923-8957-4ae9-8e6c-dc5cd1d097c8?version=n2:04e934b66316908b)). Jede Beziehungsart ist entweder eine Parent-Child-Beziehung oder hat keine Bedeutung für die Traceability. Ein Nachweis verweist immer auf ein Requirement, eine Validierung auf einen Need oder ein Requirement.

Ebenfalls fest eingebaut sind: die Gültigkeit eines Requirements und die Beziehung „ersetzt“ ([D-020](reqseq:6adc5316-641d-4817-964e-8803a78ac710?version=n2:0cd25f27b89543f2)), das Kennzeichen, ob eine Property zum Inhalt gehört ([D-013](reqseq:6adc4946-b44c-4ae1-8dbf-fb9e88b8c607?version=n2:fa0fbf62535d1e3c)), das Kennzeichen für Emergentes Verhalten ([N-009](reqseq:6ad3a133-a4fa-4a32-b108-299779d40b05?version=n1:b4fb2144d129d4bd), [N-010](reqseq:6ad3a134-2f57-4d7f-9a41-13eaa6681093?version=n1:11470c24333dbe06)), die Zugehörigkeit zu einem Paket ([N-014](reqseq:6ad3a38b-de82-4761-a388-5eb0e98bd5ac?version=n2:b0db2781054ca671), [N-015](reqseq:6ad3a38e-f464-4b39-b1d3-224e5ed3f65c?version=n2:c32cdef663dc7eba), [D-040](reqseq:6adc6920-0efc-478d-b91c-4ca42caaa8a8?version=n2:e84656cd8b820df6)), die Akzeptanzkriterien eines Requirements ([D-072](reqseq:3d5793a1-a4d5-493c-892b-c1b1dded5eca?version=n2:7ef5d1ede9d258ed)), das Kennzeichen „ungültig“ eines Statuswerts ([D-044](reqseq:6adc6922-e6d1-4d0a-9617-83d65c71cf7f?version=n2:ce205554ccf5d3d5)) und die festen Schlüssel aller Typen, Properties, Beziehungsarten und Statuswerte ([D-043](reqseq:6adc6922-7314-49bd-bfed-ff5f8a7211b4?version=n2:d496a4c7295aafde)). Die vollständige Liste der Bedeutungen steht in [D-059](reqseq:6adc78d3-0812-43dc-94fe-7af63b9acd96?version=n2:bb11050375857ccd).

Alles andere legt das Metamodell fest: Typen, Properties und die Namen der Beziehungsarten. Das Tool wird mit einem Standardmodell ausgeliefert.

Grund: Kette, Abdeckung und Indirekter Nachweis lassen sich nur berechnen, wenn das Tool weiß, was Parent und Child sind, egal wie eine Organisation ihre Beziehungen nennt.

Ein Element darf Properties tragen, die sein Typ nicht kennt. Das Tool zeigt sie als Hinweis an und erhält sie. So bleiben Übergänge bei Änderungen am Metamodell möglich, und falsche Daten fallen trotzdem auf. Ein Schreibbefehl lehnt ab: das Setzen einer Property, die der Typ nicht hat; einen Statuswert, den der Typ nicht hat; eine Beziehung einer Beziehungsart zwischen Typen, die diese Beziehungsart nicht erlaubt; für eine Property mit Wertart Zahl einen Wert, der keine Zahl ist; für eine Property mit festen Werten einen anderen Wert; für eine Property mit Wertart Beziehung einen Eintrag, der nicht genau ein vorhandenes Element nennt; für ein Akzeptanzkriterium einen Kriterienschlüssel in falscher Form oder einen, den nach der Änderung zwei Akzeptanzkriterien trügen ([D-072](reqseq:3d5793a1-a4d5-493c-892b-c1b1dded5eca?version=n2:7ef5d1ede9d258ed)). Jeden anderen Wert speichert er, und die Prüfung meldet ihn als Hinweis, zum Beispiel ein Datum in falscher Form oder ein Ziel einer Property mit Wertart Beziehung, dessen Typ sie nicht erlaubt; ebenso leere Pflicht-Properties, eine unter- oder überschrittene Anzahl und einen Zyklus. ID, Typ und Status sind keine Properties, die ein Schreibbefehl setzt, und die Properties der Herkunft schreibt nur der Import ([SR-057](reqseq:6adc6d24-cc88-431d-8094-09bfe52f8f07?version=n2:b6218f080615aa61)).
