title: Skill-Datei für Agents
spec-id: D-079

ReqSeq legt für einen [Agent](reqseq:f872adef-c0d6-4968-836b-cc23fa3b7173?version=n2:17c9a424ad1f1dc9) eine Skill-Datei im offenen Format der Agent Skills an zwei Orten in der Wurzel des Git-Repositorys an, ohne Git im Ordner des Arbeitsbereichs, und schreibt an beide denselben Inhalt; die Orte sind, in dieser Reihenfolge, `.claude/skills/managing-requirements/SKILL.md`, wo Claude Code die Skills eines Repositorys sucht, und `.agents/skills/managing-requirements/SKILL.md`, wo andere [Clients](reqseq:7ecb6c50-e26f-4fde-a60b-540a5e33ddc4?version=n2:2a8258e3bd617d85) sie suchen (#2171). Ein Client, der keine Skills aus einem Ordner des Repositorys liest, etwa Claude Desktop, findet die Skill-Datei nicht; ReqSeq legt für ihn keinen weiteren Ort an, und ihn erreichen nur die Anweisungen des MCP-Servers (SR-229 AK17). Weitere Orte für andere Clients kommen erst dazu, wenn feststeht, dass der Client sie liest und keinen dieser beiden; sie ändern diese Entscheidung. Eine vorhandene Datei an einem dieser Orte ändert ReqSeq nur auf ausdrückliche Angabe, im Einklang mit [D-068](reqseq:12bb3e5a-c303-4774-9f3b-b61677923a73?version=n2:4df637923b92d47a).

Grund: Claude Code lädt Skills aus einem Unterordner erst, wenn der Agent dort eine Datei liest; ein Agent, der nur über den MCP-Server arbeitet, sähe einen Skill im Ordner `spec/` nie. Die Dokumentation von Claude Code nennt `.agents/skills/` nicht; der Leitfaden der Agent Skills für Clients empfiehlt diesen Ort für Skills, die mehrere Clients teilen, und Codex, Gemini CLI, GitHub Copilot, Cursor, Windsurf, Zed und Mistral Vibe lesen ihn (#2171). Ein Client, der beide Orte liest, findet den Skill zweimal.
