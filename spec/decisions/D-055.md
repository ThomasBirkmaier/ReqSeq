title: "Eigenes Repository für Testdaten"

Ein zweites privates Repository (logreq-testdata) enthält einen Testbestand für ein erfundenes Produkt mit Varianten: Metamodell im eigenen Repository, mehrere Repositories mit Beziehungen nur über ID (D-028), Pakete, Baselines, Nachweise mit Belegen, ReqIF-Lieferungen und bewusst eingebaute Fehler. Ein Skript erzeugt daraus mehrere lokale Repositories mit Historie.

Kleine Testdateien je System Requirement und ein Generator für 50.000 Requirements (N-036) liegen im Code-Repository.

Agents dürfen den Testbestand ändern, die Spec nie.

Grund: Die eigene Spec deckt nicht alle Fälle ab, und Merge Requests auf einem echten Requirements-Repository lassen sich nur so prüfen.
