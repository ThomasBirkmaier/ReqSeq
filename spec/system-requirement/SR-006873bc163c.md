acceptance-criteria:
  - key: hk4d
    text: Gegeben ein Paket mit Elementen und Beziehungen untereinander, wenn es exportiert wird (zum Beispiel `reqseq reqif export --output editor.reqif` mit dem Paket Editor als Auswahl), dann entsteht eine Datei, die gegen das Schema von ReqIF 1.2 gültig ist. Sie enthält jedes Element der Auswahl, auch Needs und Decisions, in einer flachen SPECIFICATION in der Reihenfolge, in der `reqseq element list` dieselbe Auswahl liefert; eingebettete Bilder liegen als Dateien in einem Ordner neben der ReqIF-Datei.
  - key: fbfz
    text: Gegeben der Export, wenn er geprüft wird, dann ist der IDENTIFIER jedes Elements „_“ gefolgt von seiner UUID und jede Beziehung ist als SPEC-RELATION enthalten.
  - key: n04g
    text: "Gegeben eine exportierte Datei, wenn sie in einen leeren Arbeitsbereich mit demselben Metamodell importiert wird, in dem jeder exportierte Typ die Herkunfts-Properties hat (SR-057), dann stimmen Titel, Text, Properties außer dem Status und Beziehungen mit dem Original überein (jedes neu angelegte Element bekommt eine neue UUID und den Anfangsstatus seines Typs, SR-053 AK1); die Herkunfts-Properties, die der Import ergänzt (SR-057), zählen beim Vergleich nicht. Weil sie nicht zur Fassung zählen (D-057), stimmen die Fassungen der importierten Elemente mit dem Original überein, außer wo der Import eine Angabe auf eine neue UUID umschreibt (die Gültigkeit auf eine exportierte Variante, der Pfad eines eingebetteten Bildes); eine so umgeschriebene Angabe und ein Bild mit gleichem Inhalt gelten beim Vergleich als gleich. Der Import trägt in ihre Beziehungen die importierten Ziele mit ihren neuen Fassungen ein, sodass keine Beziehung als veraltet gilt. Dafür enthält der Export den Text als XHTML und zusätzlich die STRING-Attribute `reqseq-markdown` und `reqseq-values`. Eine Datei des Tools (REQ-IF-TOOL-ID `reqseq`) braucht keine Zuordnung von Hand: der Import legt die Zuordnung eins zu eins an und speichert sie wie jede andere (SR-054)."
