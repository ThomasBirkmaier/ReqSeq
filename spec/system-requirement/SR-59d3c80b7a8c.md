acceptance-criteria:
  - "Gegeben ein Paket oder eine Auswahl, wenn eine Baseline angelegt wird (App, CLI, API, MCP: `baseline.create`), dann entsteht im Ordner für Baselines (D-039) eine Datei mit Name, Datum, dem aktuellen Commit je beteiligtem Repository und ID und Fassung jedes enthaltenen Elements."
  - Gegeben Elemente der Auswahl haben nicht committete Änderungen, wenn eine Baseline angelegt werden soll, dann lehnt das Tool das ab und nennt diese Elemente. Als Änderung zählen die Dateien der ausgewählten Elemente, die darin eingebetteten Dateien, die Dateien des Metamodells und die Datei des Arbeitsbereichs, nicht die Nachweis-Datensätze. Auch die Datei eines ausgewählten Elements, die noch nie committet wurde, zählt als nicht committete Änderung.
  - Gegeben eine Auswahl über eine Variante, wenn eine Baseline angelegt wird, dann nennt die Baseline-Datei diese Variante.
  - "Gegeben eine Auswahl mit R1 im Haupt-Repository `system` und R2 im Repository `sensor`, das Metamodell liegt in `system`, wenn eine Baseline angelegt wird, dann nennt die Datei den Commit von `system` und von `sensor` je einmal: Beteiligt sind die Repositories der ausgewählten Elemente, das Haupt-Repository und das Repository des Metamodells."
  - Gegeben eine Auswahl ohne Elemente, wenn eine Baseline angelegt wird, dann entsteht die Datei mit leerer Liste der Elemente.
  - Gegeben eine Baseline „Release 1“ besteht schon, wenn eine weitere Baseline mit dem Namen „Release 1“ angelegt werden soll, dann lehnt das Tool das ab, nennt die vorhandene Datei und überschreibt nichts.
  - Gegeben ein beteiligtes Repository hat keinen Commit, weil es nicht unter Git steht oder Git keinen aktuellen Commit liefert, wenn eine Baseline angelegt werden soll, dann lehnt das Tool das ab und nennt das Repository.
  - Gegeben eine Auswahl nennt einen gespeicherten Filter mit der Sicht der Variante A und zusätzlich eine andere Sicht, zum Beispiel die Variante B oder den Kern, wenn eine Baseline angelegt werden soll, dann lehnt das Tool das ab und nennt die Sicht des Filters; nennen beide dieselbe Sicht, nennt die Baseline-Datei sie einmal.

rationale: "Eine Baseline hält einen Stand fest, den die Versionsverwaltung kennt; deshalb lehnt das Tool nicht committete Änderungen ab (AK2), statt „jederzeit“ jeden Arbeitsstand anzunehmen. Anlass und Zustimmung liegen außerhalb des Tools (D-006). Den Commit der Datei führt das Tool nicht aus (SR-083). Entscheidung des Produktverantwortlichen, 2026-10-29: „jederzeit“ wird begründet oder entfällt, hier entfällt es; das Format der Datei regelt eine ADR, ihr Ordner steht in D-039. Gespeicherter Filter mit anderer Sicht (AK8): Entscheidung des Produktverantwortlichen, 2026-10-30: Einfache offene Fragen entscheidet die Stufenleitung in der Nacht selbst; #440 wird mit der schon gebauten Ablehnung beantwortet, weil eine Baseline nie ersetzt wird und eine nur halb gespeicherte Auswahl sonst Elemente als hinzugekommen meldet, die nie ausgewählt waren."
---

Das Tool muss eine Baseline einer Auswahl als Datei mit ID und Fassung jedes Elements und dem Commit jedes beteiligten Repositories anlegen, ohne nach Anlass oder Zustimmung zu fragen.
