title: "Geänderte Kern-Requirements seit der Baseline einer Variante zeigen"
spec-id: "SR-103"
requirement-type: functional
acceptance-criteria:
  - "Gegeben ein Kern-Requirement ohne Gültigkeit, das A übernommen hat, hat sich seit der neuesten Baseline von A geändert, wenn die Hinweise abgefragt werden (App: Seite von A; CLI, API, MCP: `hint.list` oder `workspace.check`), dann nennt das Tool es an A mit der Fassung aus der Baseline und der aktuellen Fassung."
  - Gegeben eine neue Baseline von A, wenn die Hinweise erneut abgefragt werden, dann erscheint es nicht mehr.
  - Gegeben eine Variante ohne Baseline, wenn die Hinweise abgefragt werden, dann zeigt das Tool dazu keinen Hinweis.
  - "Gegeben die Baselines „R1“ vom 2026-11-02 und „R2“ vom 2026-11-09, deren Auswahl beide die Sicht von A nennt, wenn die Hinweise abgefragt werden, dann vergleicht das Tool mit „R2“: Die neueste Baseline von A ist die mit dem jüngsten Datum, bei gleichem Datum die letzte in der Reihenfolge der Dateien."
  - "Gegeben ein solcher Hinweis, wenn er mit `hint.confirm` bestätigt werden soll, dann lehnt das Tool das ab und nennt den Grund: Erledigt ist er erst mit einer neuen Baseline von A (D-042)."
  - Gegeben ein Kern-Requirement, das für A ausgeschlossen oder in A ersetzt ist, hat sich seit der neuesten Baseline von A geändert, wenn die Hinweise abgefragt werden, dann nennt das Tool es hier nicht; für ein ersetztes Kern-Requirement gilt SR-045.

Das Tool muss an jeder Variante die übernommenen Kern-Requirements zeigen, die sich seit ihrer neuesten Baseline geändert haben.
