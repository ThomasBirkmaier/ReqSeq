title: "Geänderte Kern-Requirements seit der Baseline einer Variante zeigen"
spec-id: "SR-103"
requirement-type: functional
acceptance-criteria:
  - "Gegeben ein Kern-Requirement, das A übernommen hat, hat sich seit der neuesten Baseline von A geändert, wenn die Hinweise abgefragt werden (App: Seite von A; CLI, API, MCP: `hint.list` oder `workspace.check`), dann nennt das Tool es an A mit der Fassung aus der Baseline und der aktuellen Fassung."
  - Gegeben eine neue Baseline von A, wenn die Hinweise erneut abgefragt werden, dann erscheint es nicht mehr.
  - Gegeben eine Variante ohne Baseline, wenn die Hinweise abgefragt werden, dann zeigt das Tool dazu keinen Hinweis.
  - "Gegeben die Baselines „R1“ vom 2026-11-02 und „R2“ vom 2026-11-09, deren Auswahl beide nur die Sicht von A ist, wenn die Hinweise abgefragt werden, dann vergleicht das Tool mit „R2“: Die neueste Baseline von A ist die mit dem jüngsten Zeitpunkt aus Datum und Uhrzeit, bei gleichem Zeitpunkt die mit dem letzten Dateinamen. Eine Baseline, deren Auswahl außer der Sicht von A noch ein Paket oder einen Filter nennt, ist keine Baseline von A."
  - "Gegeben ein solcher Hinweis, wenn er mit `hint.confirm` bestätigt werden soll, dann lehnt das Tool das ab und nennt den Grund: Erledigt ist er erst mit einer neuen Baseline von A (D-042)."
  - Gegeben ein Kern-Requirement, das für A ausgeschlossen oder in A ersetzt ist, hat sich seit der neuesten Baseline von A geändert, wenn die Hinweise abgefragt werden, dann nennt das Tool es hier nicht; für ein ersetztes Kern-Requirement gilt SR-045.
  - Gegeben ein Kern-Requirement ist seit der neuesten Baseline von A in die Sicht von A gekommen, weil es neu angelegt, sein Ausschluss zurückgenommen oder sein Ersatz entfernt wurde, wenn die Hinweise abgefragt werden, dann nennt das Tool es an A als neu seit der Baseline, mit der aktuellen Fassung und ohne Fassung aus der Baseline.

Das Tool muss an jeder Variante die übernommenen Kern-Requirements zeigen, die sich seit ihrer neuesten Baseline geändert haben.
