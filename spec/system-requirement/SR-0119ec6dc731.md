title: Agent-Anleitung aus einer Quelle erzeugen
spec-id: SR-229
rationale: Agents ohne Vorwissen legten Requirements und Tests an, spielten aber keine Nachweise ein und hielten einen Nachweisgrad von 0 % für fertig; ein Agent änderte ein Requirement im Status Approved, ohne zu fragen. Eine Anleitung, die aus den Quellen entsteht, bleibt bei jeder Version und jedem Metamodell richtig (D-067).
requirement-type: functional
acceptance-criteria:
  - key: p4y6
    text: Gegeben ein Arbeitsbereich, wenn `tool.guide` aufgerufen wird (App, Kommandozeile, API, MCP-Server), dann liefert das Tool die Agent-Anleitung als Markdown, bei gleicher Eingabe über jeden Zugang zeichengleich; die Eingabe `names` wählt, ob Befehle als Aufruf der Kommandozeile oder als Name des MCP-Werkzeugs erscheinen, ohne sie als Aufruf der Kommandozeile. Der MCP-Server sendet in seinem `initialize`-Ergebnis als Anweisungen genau die Ausgabe mit den Namen der MCP-Werkzeuge. Mit dem Standardmodell ist sie höchstens 6.000 Zeichen lang.
  - key: hyqj
    text: Gegeben ein Ordner ohne Arbeitsbereich oder ein Arbeitsbereich, dessen Metamodell sich nicht lesen lässt, wenn `tool.guide` aufgerufen wird oder der MCP-Server dafür startet, dann liefert das Tool die Agent-Anleitung ohne die Angaben aus dem Metamodell, nennt den Grund und, ohne Arbeitsbereich, den Aufruf, der einen anlegt.
  - key: qk2t
    text: Gegeben die Agent-Anleitung, wenn sie gelesen wird, dann enthält sie in dieser Reihenfolge Abschnitte zu Need, Requirement mit Akzeptanzkriterien und Nachweismethode, Test je Akzeptanzkriterium, Nachweisort, Ergänzen der Testergebnisse, Nachweisgrad und Prüfung des Arbeitsbereichs, nennt zu jedem Schritt, den ein Befehl ausführt, diesen Befehl, sagt, dass jeder Testlauf eine eigene Datei im Nachweisort bekommt und was der Prüfling ist, und nennt für andere Nachweismethoden als Test den Befehl, der einen Datensatz erfasst.
  - key: zp64
    text: Gegeben das Metamodell des Arbeitsbereichs, wenn die Agent-Anleitung erzeugt wird, dann nennt sie die anlegbaren Typen, die die Bedeutung Need oder Requirement tragen oder erben, mit Name und Präfix, je genanntem Typ seine Statuswerte mit dem Anfangsstatus (SR-064 AK4) und den ungültigen, die Beziehungsarten mit der Bedeutung Ableitung, die Form des Testnamens nach SR-205 AK1 mit einem Beispiel und die Nachweisorte, ohne Nachweisort, wie einer eingetragen wird; fehlt einer Bedeutung ein Typ oder eine Property, entfällt der zugehörige Teil.
  - key: tmc3
    text: "Gegeben die Agent-Anleitung, wenn sie erzeugt wird, dann enthält sie wörtlich diese Regeln aus einer Liste im Tool: Über jeden Status entscheidet ein Mensch; der Agent schlägt eine Statusänderung vor und setzt sie nur, um eine ausdrückliche Entscheidung auszuführen. Vor einer inhaltlichen Änderung an einem Element, dessen Status nicht der Anfangsstatus seines Typs ist, fragt der Agent, außer eine Regel des Projekts erlaubt sie. Das Tool löscht kein Element; ein Element wird abgelöst. Elemente liest und ändert der Agent über die Befehle, nicht über ihre Dateien. Regeln des Projekts gehen der Agent-Anleitung vor. Vor dem Abschluss einer Arbeit prüft der Agent den Arbeitsbereich und den Nachweisgrad und nennt Befunde und Lücken."
  - key: j7mz
    text: Gegeben die Agent-Anleitung und die Skill-Datei, wenn sie geprüft werden, dann ist jeder darin genannte Befehl ein Befehl des Befehlskatalogs.
  - key: nrf2
    text: Gegeben `tool.guide` wird mit der Angabe Skill aufgerufen, wenn die Ausgabe gezeigt wird, dann ist sie eine Skill-Datei im Format der Agent Skills mit dem Namen `managing-requirements`, einer Beschreibung in dritter Person, was sie tut und wann sie gilt, mit höchstens 1.024 Zeichen, und den Abläufen „Requirement anlegen“, „Requirement bis zum Nachweis umsetzen“, „Stand vor dem Abschluss prüfen“ und „Element ändern, dessen Status nicht der Anfangsstatus ist“, je als nummerierte Schritte; sie enthält keine Namen aus dem Metamodell, nennt jeden Befehl mit dem Namen des MCP-Werkzeugs und dem Aufruf der Kommandozeile, ihr erster Schritt nennt beide Wege zur Agent-Anleitung und was zu tun ist, wenn keiner erreichbar ist, und sie trägt die Version des Tools und einen Prüfwert über ihren Inhalt.
  - key: v09f
    text: Gegeben ein Arbeitsbereich, wenn die Skill-Datei mit `tool.guide` geschrieben wird, dann legt das Tool sie am Ort aus D-079 an oder ersetzt eine Datei dort, die es selbst erzeugt hat und deren Prüfwert noch stimmt; eine andere oder geänderte Datei ersetzt es nur mit ausdrücklicher Angabe und meldet sonst, dass es nichts geschrieben hat. Über API und MCP-Server schreibt es nicht, wenn der Ort außerhalb der Repositories des Arbeitsbereichs liegt, und nennt den Aufruf der Kommandozeile, der sie schreibt.
  - key: x7d8
    text: Gegeben ein Arbeitsbereich wird angelegt (`workspace.init`, SR-014 AK1), wenn das Anlegen gelingt, dann schreibt das Tool auch die Skill-Datei wie in AK8 ohne die ausdrückliche Angabe zum Ersetzen, außer die Eingabe sagt, dass kein Skill angelegt wird, und nennt sie in der Liste der angelegten Dateien; die App fragt dabei nicht danach.
  - key: gmk1
    text: Gegeben eine vom Tool erzeugte Skill-Datei am Ort aus D-079 trägt eine ältere Version als das Tool, und ihr Inhalt weicht von dem ab, den das Tool jetzt erzeugen würde, wenn der Arbeitsbereich geprüft wird, dann meldet das Tool einen Befund mit dem Schweregrad Info und dem Aufruf, der sie erneuert; eine neuere Version meldet es nicht.

Das Tool muss einem Agent eine [Agent-Anleitung](reqseq:3bf89678-e8fb-4dc5-ab9c-a3dafc0291e3?version=n2:b10f2185357a408f) für die Arbeit mit ReqSeq geben, deren Text an einer Stelle im Tool steht und deren Namen und Werte es aus dem Befehlskatalog und dem Metamodell des Arbeitsbereichs einsetzt, als Befehl in allen Zugängen, als Anweisungen des MCP-Servers und als Skill-Datei; keine dieser Ausgaben wird einzeln von Hand gepflegt.
