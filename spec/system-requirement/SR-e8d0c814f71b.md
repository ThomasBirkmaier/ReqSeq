title: Anzahl der Beziehungen im Metamodell begrenzen
spec-id: SR-152
rationale: "Entscheidung des Produktverantwortlichen, 2026-10-31: Das Metamodell begrenzt heute nur, welche Typen eine Beziehungsart verbinden darf, aber weder, wie viele Beziehungen ein Element haben darf, noch wie viele es haben muss. Regeln wie „ein System Requirement leitet sich aus höchstens einem Use Case ab“ sollen im Metamodell stehen und geprüft werden. Abweichungen sind Hinweise und blockieren das Speichern nicht. Eingetragen in Später."
requirement-type: functional
acceptance-criteria:
  - Gegeben das Metamodell legt für eine Beziehungsart und einen Ziel-Typ eine Höchstzahl je Quell-Element fest, zum Beispiel höchstens eine Beziehung „derives-from“ von einem System Requirement auf einen Use Case, wenn ein Element mehr solche Beziehungen hat und der Bestand über Kommandozeile, API, MCP oder App geprüft wird, dann erscheint ein Hinweis mit Element, Beziehungsart, Ziel-Typ, Anzahl und Höchstzahl.
  - Gegeben das Metamodell legt für eine Beziehungsart eine Mindestzahl je Quell-Element fest, zum Beispiel mindestens eine Beziehung „derives-from“ je System Requirement, wenn ein Element weniger solche Beziehungen hat und der Bestand geprüft wird, dann erscheint ein Hinweis mit Element, Beziehungsart, Anzahl und Mindestzahl.
  - Gegeben eine Beziehung würde die Höchstzahl überschreiten, wenn sie in App, Kommandozeile, API oder MCP gesetzt wird, dann speichert das Tool sie und zeigt den Hinweis aus AK1.
  - Gegeben eine Beziehungsart ohne Mindest- und Höchstzahl im Metamodell, wenn der Bestand geprüft wird, dann darf jedes Element beliebig viele Beziehungen dieser Art haben, auch keine, und es erscheint kein Hinweis zur Anzahl.

Das Tool muss im Metamodell je Beziehungsart und Ziel-Typ eine Mindest- und eine Höchstzahl von Beziehungen je Quell-Element festlegen lassen und Abweichungen bei der Prüfung des Bestands als Hinweis melden.
