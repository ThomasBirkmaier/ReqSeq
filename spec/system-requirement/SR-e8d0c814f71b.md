title: Anzahl der Beziehungen im Metamodell begrenzen
spec-id: SR-152
rationale: "Entscheidung des Produktverantwortlichen, 2026-10-31: Das Metamodell begrenzt heute nur, welche Typen eine Beziehungsart verbinden darf, aber weder, wie viele Beziehungen ein Element haben darf, noch wie viele es haben muss. Regeln wie „ein System Requirement leitet sich aus höchstens einem Use Case ab“ sollen im Metamodell stehen und geprüft werden. Abweichungen sind Hinweise und blockieren das Speichern nicht."
requirement-type: functional
acceptance-criteria:
  - Gegeben das Metamodell legt für eine Beziehungsart, einen Ziel-Typ und, wenn angegeben, einen Quell-Typ eine Höchstzahl je Quell-Element fest, zum Beispiel höchstens eine Beziehung „derives-from“ von einem System Requirement auf einen Use Case, wenn ein Element mehr solche Beziehungen hat und der Bestand über Kommandozeile, API, MCP oder App geprüft wird, dann erscheint ein Hinweis mit Element, Beziehungsart, Ziel-Typ, Anzahl und Höchstzahl.
  - Gegeben das Metamodell legt für eine Beziehungsart, einen Ziel-Typ und, wenn angegeben, einen Quell-Typ eine Mindestzahl je Quell-Element fest, zum Beispiel mindestens eine Beziehung „derives-from“ von einem System Requirement auf einen Need, wenn ein Element weniger solche Beziehungen hat und der Bestand geprüft wird, dann erscheint ein Hinweis mit Element, Beziehungsart, Ziel-Typ, Anzahl und Mindestzahl.
  - Gegeben eine Beziehung würde die Höchstzahl überschreiten, wenn sie in App, Kommandozeile, API oder MCP gesetzt wird, dann speichert das Tool sie und zeigt den Hinweis aus AK1.
  - Gegeben eine Beziehungsart ohne Mindest- und Höchstzahl im Metamodell, wenn der Bestand geprüft wird, dann darf jedes Element beliebig viele Beziehungen dieser Art haben, auch keine, und es erscheint kein Hinweis zur Anzahl.
  - Gegeben eine Mindest- oder Höchstzahl, wenn sie für ein Element geprüft wird, dann zählt jede Beziehung, deren Ziel sich zu genau einem Element des Ziel-Typs oder eines davon erbenden Typs auflösen lässt, gleich welchen Status das Ziel hat, und eine doppelte Beziehung zählt doppelt; ein fehlendes oder mehrdeutiges Ziel zählt nicht. Liegt ein Ziel in einem Repository, das lokal fehlt oder das die Arbeitsbereichs-Datei nicht nennt, gibt es zu diesem Element keinen Hinweis zur Mindestzahl. Ein Quell-Element mit ungültigem Status bekommt keinen Hinweis zur Anzahl.

Das Tool muss im Metamodell je Beziehungsart, Ziel-Typ und, wenn angegeben, Quell-Typ eine Mindest- und eine Höchstzahl von Beziehungen je Quell-Element festlegen lassen und Abweichungen bei der Prüfung des Bestands als Hinweis melden.
