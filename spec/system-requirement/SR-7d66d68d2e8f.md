acceptance-criteria:
  - "Gegeben eine neue Lieferung derselben Quelle, wenn sie mit `reqseq reqif analyze` gelesen oder importiert wird, dann zeigt das Tool vorher neue, geänderte und weggefallene Elemente getrennt an. Der Vergleich geht über Quelle und IDENTIFIER der Quelle; geändert heißt, die Lieferung ergibt für das Element ohne die Herkunfts-Properties andere Werte als seine Importfassung. Eine Property, die zur Fassung zählt und die die Zuordnung nicht kennt, zählt dabei mit: Ein Element, an dem sie lokal ergänzt oder geändert wurde, zeigt das Tool als geändert, auch wenn die Lieferung gleich geblieben ist, und zusammen mit einer lokalen Änderung am Text als Konflikt."
  - Gegeben ein Element mit gleicher Quelle und gleichem IDENTIFIER, wenn importiert wird, dann legt das Tool kein zweites Element an. Ergibt die Lieferung für das Element eine andere Importfassung als die, die es trägt, schreibt das Tool die Werte der Lieferung in das vorhandene Element, bei einem Konflikt erst nach der Wahl (AK4). Ergibt sie dieselbe und entspricht die Fassung des Elements seiner Importfassung, schreibt es die Datei nur, wenn Titel, zugeordnete Properties oder Beziehungen von der Lieferung abweichen, und sonst nicht, auch nicht für Lieferung und Datum des Imports; ein lokal geändertes Element bleibt nach AK5, wie es ist.
  - Gegeben ein weggefallenes Element, wenn importiert wird, dann kennzeichnet das Tool es nur in der Ausgabe von Analyse und Import und ändert weder seinen Status noch sonst etwas an seiner Datei; das Element bekommt keine Property dafür.
  - Gegeben ein importiertes Element, dessen Fassung nicht mehr seiner Importfassung entspricht, und die neue Lieferung ändert es ebenfalls, wenn importiert wird, dann zeigt das Tool es vorher als Konflikt und übernimmt die Lieferung dafür erst nach einer Wahl je Element („übernehmen“ oder „behalten“). Fehlt die Wahl für einen Konflikt, lehnt der Import ganz ab und nennt die Konflikte. Ergibt die Lieferung dieselbe Fassung, die das Element lokal schon hat, ist das kein Konflikt. Nach „behalten“ trägt das Element die Importfassung der Lieferung, sodass dieselbe Lieferung keinen Konflikt mehr ergibt.
  - Gegeben ein importiertes Element, dessen Fassung nicht mehr seiner Importfassung entspricht, und die neue Lieferung ergibt dieselbe Importfassung, die es trägt, wenn analysiert oder importiert wird, dann schreibt das Tool seine Datei nicht und zeigt das Element weder als geändert noch als Konflikt, auch wenn die Lieferung einen anderen Titel nennt.
  - Gegeben ein Element, in das der Import die Lieferung schreibt und dessen Titel, zugeordnete Properties, die nicht zur Fassung zählen, oder Ziele einer Beziehungsart von der Lieferung abweichen, wenn analysiert oder importiert wird, dann warnt das Tool vorher mit `reqif.replaces-local` und nennt je Element, was die Lieferung ersetzt.

Wenn eine Lieferung derselben Quelle erneut importiert wird, muss das Tool neue, geänderte und weggefallene Elemente vorher zeigen, vorhandene Elemente mit der Lieferung aktualisieren und lokale Änderungen nicht ohne Wahl überschreiben.
