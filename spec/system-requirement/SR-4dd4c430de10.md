acceptance-criteria:
  - key: n6cm
    text: "Gegeben die Baseline „Release 1“ vom 2026-11-02 enthält SR-X in der Fassung vom 2026-10-30, wenn sie geöffnet wird (CLI, API, MCP: `baseline.get`), dann zeigt das Tool jedes enthaltene Element mit der Fassung aus der Baseline und deren Datum, hier SR-X mit 2026-10-30. Den Inhalt der alten Fassung zeigt `baseline.get` nicht; den Unterschied zeigt `baseline.compare` (AK5, D-033)."
  - key: c0xb
    text: "Gegeben seit der Baseline wurde SR-X geändert, SR-Y abgelöst, und SR-Z erfüllt heute die gespeicherte Auswahl der Baseline, steht aber nicht in der Datei, wenn die Baseline geöffnet wird (CLI, API, MCP: `baseline.get`), dann kennzeichnet das Tool SR-X als geändert, SR-Y als abgelöst und SR-Z als hinzugefügt. Ein geändertes und abgelöstes Element ist als abgelöst gekennzeichnet. Ohne gespeicherte Auswahl gibt es kein „hinzugefügt“, und das Ergebnis sagt das."
  - key: ntjw
    text: "Gegeben SR-W steht in der Baseline, ist nicht abgelöst und erfüllt die gespeicherte Auswahl heute nicht mehr, wenn die Baseline geöffnet wird (CLI, API, MCP: `baseline.get`), dann kennzeichnet das Tool SR-W als entfernt. Ist SR-W seit der Baseline außerdem geändert, ist es nur als entfernt gekennzeichnet, mit der aktuellen Fassung neben der Fassung aus der Baseline. Ohne gespeicherte Auswahl gibt es kein „entfernt“."
  - key: dcx7
    text: "Gegeben ein geändertes Element, wenn der Unterschied angefordert wird (CLI, API, MCP: `baseline.compare`), dann nennt das Tool die beiden Commits und den Git-Befehl für den Vergleich."
  - key: v9hv
    text: "Gegeben ein Element, das in der Baseline steht, und der Commit, den die Baseline für sein Repository nennt, liegt in der lokalen Git-Historie, wenn der Unterschied angefordert wird (CLI, API, MCP: `baseline.compare`), dann nennt die Ausgabe neben den beiden Commits und dem Git-Befehl (AK4) je geändertem Text, geändertem Akzeptanzkriterium (zugeordnet über den Kriterienschlüssel) und geänderter Property, die nach dem Metamodell der lokalen Kopie zur Fassung zählt, den alten und den neuen Wortlaut, ungekürzt (ein hinzugekommenes Akzeptanzkriterium hat keinen alten, ein entferntes keinen neuen Wortlaut), sowie die hinzugekommenen und die entfernten Beziehungen; gespeicherte Fassungen von Zielen zählen nicht als Unterschied, wie in SR-232 AK7. Verglichen wird die Datei des Elements im Commit der Baseline mit seiner Datei in der lokalen Kopie. Unterscheidet sich nichts davon, nennt die Ausgabe keinen Unterschied, und der Antwortsatz sagt das."
  - key: w2b9
    text: "Abweichend von AK4: Gegeben der Commit, den die Baseline für das Repository des Elements nennt, liegt nicht in der lokalen Git-Historie (nicht geholt, flacher Klon), wenn der Unterschied angefordert wird (CLI, API, MCP: `baseline.compare`), dann lehnt das Tool das ab und nennt den Commit und dass er geholt werden muss."
  - key: x9z6
    text: "Gegeben das Element steht nicht in der Baseline, die Baseline nennt für sein Repository keinen Commit, Git kann das Repository nicht lesen, im Commit der Baseline hält keine Datei das Element, oder seine Datei fehlt in der lokalen Kopie oder lässt sich nicht als Element lesen, wenn der Unterschied angefordert wird (CLI, API, MCP: `baseline.compare`), dann lehnt das Tool das ab und nennt den Grund."
