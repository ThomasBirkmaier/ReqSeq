title: Akzeptanzkriterien mit Formatierung und Verweisen
spec-id: SR-127
rationale: Akzeptanzkriterien stehen als Property im YAML-Frontmatter und sollen trotzdem formatiert sein können, etwa mit Links ins Glossar oder mit fett gesetztem Gegeben, Wenn und Dann für bessere Lesbarkeit (ThomasBirkmaier/ReqSeq-archive#379).
requirement-type: functional
acceptance-criteria:
  - key: bd1x
    text: Gegeben ein Verweis in einem Akzeptanzkriterium, wenn das Ziel geändert wird, dann gilt er wie ein Verweis im Text als veraltet, und das Element erscheint unter den betroffenen Elementen der Änderung.
  - key: f93q
    text: Gegeben eine Datei mit formatierten Akzeptanzkriterien und Verweisen, wenn sie in einem Texteditor geöffnet wird, dann ist der Kopf gültiges YAML, und jedes Akzeptanzkriterium steht darin als lesbarer Markdown-Text.
  - key: mdr7
    text: Gegeben eine Text-Property, wenn das Metamodell sie als Markdown kennzeichnet, dann gelten Formatierung und Verweise für sie; im Standardmodell sind das die Akzeptanzkriterien und die Begründung, Titel und Kennungen bleiben reiner Text.

Das Tool muss in Akzeptanzkriterien und anderen Text-Properties Hervorhebungen, Code und Verweise auf Elemente in Markdown zulassen, wobei die Datei als YAML gültig und im Klartext lesbar bleibt.
