acceptance-criteria:
  - Gegeben eine gültige ReqIF-Datei, wenn sie importiert wird (zum Beispiel `reqseq reqif import --file lieferung.reqif --mapping reqif/kunde-a.yaml --delivery "Lastenheft 2026-11"`), dann entsteht für jedes SPEC-OBJECT, dessen Typ die Zuordnung nicht weglässt, eine Element-Datei und für jede SPEC-RELATION eine Beziehung, außer wo AK2 einen Verlust meldet. Die Dateien liegen im Ordner, den die Zuordnung als Ziel nennt, sonst in einem Ordner mit dem Namen der Quelle, den die Zuordnung nennt, im Haupt-Repository; jedes neue Element hat den Anfangsstatus seines Typs, nie einen Status aus der Lieferung (SR-064 AK4, SR-087).
  - "Gegeben Inhalte, die sich nicht verlustfrei übernehmen lassen, wenn analysiert oder importiert wird, dann listet das Tool jedes betroffene Element mit dem Grund in der Ausgabe von Analyse und Import. Beispiele: die SPEC-HIERARCHY (eine Meldung je SPECIFICATION) und eine SPEC-RELATION, deren anderes Ende nicht importiert wird (in der Datei eines anderen Werkzeugs)."
  - "Gegeben ein Repository des Arbeitsbereichs fehlt auf diesem Rechner oder eine Element-Datei lässt sich nicht lesen, wenn eine Lieferung importiert wird, dann lehnt der Import ab, bevor er eine Datei schreibt, und nennt das Repository (`file.folder-missing`) oder die Datei (`file.faulty`); die Analyse (`reqseq reqif analyze`) meldet dieselben Fälle als Warnung und lehnt nur ab, wenn der Zielordner der Zuordnung in dem fehlenden Repository liegt."

Das Tool muss ReqIF-Dateien der Version 1.2 importieren und Verluste beim Import melden.

Gepackte Lieferungen (`.reqifz`) gehören nicht zum Basisumfang.
