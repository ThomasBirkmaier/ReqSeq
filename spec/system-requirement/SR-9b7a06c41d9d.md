title: "Nachweis je Variante führen"
spec-id: "SR-047"
requirement-type: functional
acceptance-criteria:
  - "Gegeben ein Kern-Requirement mit einem bestandenen Datensatz für Variante A, wenn der Status für Variante B berechnet wird, dann ist er dort offen."
  - Gegeben ein Datensatz ohne Angabe einer Variante, wenn der Status berechnet wird, dann zählt er nur für den Kern, außer das Element gehört zu einem Repository, das in der Workspace-Datei als variantenunabhängig gekennzeichnet ist.
  - "Gegeben ein Kern-Requirement, das für Variante C ausgeschlossen ist, mit einem bestandenen Datensatz ohne Variante, einem fehlgeschlagenen für B und keinem für A, wenn sein Nachweisstatus angezeigt wird (App: Seite des Requirements; CLI, API, MCP: `evidence.status`), dann zeigt das Tool je einen Eintrag für den Kern und jede Variante, für die es gilt, zum Beispiel „Kern: verified · A: open · B: failed“, und keinen Eintrag für C; wie die App die Einträge darstellt, regelt SR-157. Ebenso gibt es keinen Eintrag für eine Variante, die es durch ein eigenes Requirement ersetzt; das ersetzende Requirement hat seinen eigenen Status."
  - Gegeben ein Kern-Requirement ist für Variante C ausgeschlossen oder in C durch ein eigenes Requirement ersetzt, wenn mit `evidence.record` ein Datensatz für C geschrieben werden soll (App, CLI, API, MCP), dann lehnt das Tool das ab und nennt den Ausschluss oder den Ersatz, wie bei einer Variante, die nicht in der Gültigkeit steht.
