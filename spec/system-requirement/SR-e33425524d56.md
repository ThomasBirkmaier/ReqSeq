title: Höchstzahl von Listeneinträgen im Metamodell
spec-id: SR-171
rationale: Das Metamodell soll festlegen können, wie viele Einträge eine Listen-Property höchstens hat, zum Beispiel höchstens drei Akzeptanzkriterien je System Requirement, und die Prüfung des Bestands soll Abweichungen melden (#632).
requirement-type: functional
acceptance-criteria:
  - Gegeben das Metamodell legt für eine Property mit mehreren Einträgen, die keine Beziehung ist, eine Höchstzahl fest, wenn ein Element mehr Einträge hat und der Bestand über Kommandozeile, API, MCP oder App geprüft wird, dann erscheint ein Hinweis mit Element, Property, Anzahl und Höchstzahl.
  - Gegeben eine Property mit mehreren Einträgen, die keine Beziehung ist, ohne Höchstzahl im Metamodell, wenn der Bestand geprüft wird, dann darf ein Element beliebig viele Einträge haben, und es erscheint kein Hinweis zur Anzahl.
  - Gegeben das Metamodell legt für eine Property mit Wertart Beziehung eine Höchstzahl fest, wenn es gelesen wird, dann meldet das Tool einen Fehler im Metamodell mit Datei und Zeile (SR-011 AK3); für solche Properties gibt es keine Mindest- oder Höchstzahl.
  - "Gegeben ein Schreibbefehl setzt mehr Einträge, als die Höchstzahl erlaubt (App, CLI, API, MCP: `element.create`, `element.update`, `element.bulkUpdate`), wenn er ausgeführt wird, dann speichert das Tool sie, und die Prüfung des Bestands meldet den Hinweis aus AK1."

Das Tool muss im Metamodell eine Höchstzahl von Einträgen je Property mit mehreren Werten zulassen und Elemente melden, die sie überschreiten.
