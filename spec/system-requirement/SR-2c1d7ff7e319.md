title: Nachweise in der Traceability-Matrix zeigen
spec-id: SR-126
rationale: "Eine Traceability-Matrix ist Pflicht und fehlt noch; sie soll neu gedacht werden: mit kaskadierten Filtern zum Beispiel alle SRs eines Pakets wählen, die Matrix aufrufen und so die relative Übersicht bekommen. Auch Testergebnisse müssen mit ihrem Ausführungsstatus bis zum Requirement verfolgbar sein. Ein Testfall ohne Durchführung in AK2 ist einer, der in einer Ergebnisdatei nur übersprungen vorkommt, so wie das Tool es umsetzt. Bei mehreren gleich neuen Durchführungen eines Testfalls zeigt die Zelle die schlechteste, damit sie zum Nachweisstatus passt (AK1)."
requirement-type: functional
acceptance-criteria:
  - Gegeben Requirements der Auswahl mit Nachweis-Datensätzen, wenn die Matrix angezeigt wird, dann hat sie eine Spalte mit den Testfällen je Requirement, jeweils mit Ergebnis und Datum der letzten Durchführung, bei mehreren gleich neuen die schlechteste, und eine Spalte mit dem Nachweisstatus.
  - Gegeben ein Requirement ohne Testfall, mit einem Testfall, der in einer Ergebnisdatei nur übersprungen vorkommt (SR-093 AK3), mit einem Testfall ohne Durchführung zur aktuellen Fassung oder mit einem, dessen neueste Durchführung zur aktuellen Fassung nicht bestanden ist, wenn die Matrix angezeigt wird, dann ist seine Zelle entsprechend gekennzeichnet.
  - Gegeben ein indirekt nachgewiesenes Requirement, wenn die Matrix angezeigt wird, dann ist sein Nachweisstatus als indirekt gekennzeichnet.
  - Gegeben die Matrix einer Auswahl, wenn sie angezeigt wird, dann steht über der Spalte des Nachweisstatus der Nachweisgrad der Auswahl mit der Anzahl je Status.
  - Gegeben eine Auswahl ohne gewählte Variante, wenn die Matrix angezeigt wird, dann zeigen Testfälle, Nachweisstatus und Nachweisgrad nur den Kern.

Das Tool muss in der Traceability-Matrix einer Auswahl zu jedem Requirement seine Testfälle mit dem Ergebnis der letzten Durchführung und seinen Nachweisstatus zeigen.
